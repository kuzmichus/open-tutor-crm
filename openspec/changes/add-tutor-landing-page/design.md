# Design

## Context

Публичная часть лендинга уже есть: `GET /` отдаёт `index.html` в
сингл-режиме, ассеты — с `/landing-assets/`. Не хватает управляющей
поверхности: шаблона, из которого рождается первый черновик, и страницы, где
репетитор видит статус и выполняет действия.

Ограничения проекта, которые определяют решения:

- шаблоны модулей неймспейсятся подкаталогом и подключаются через
  `TEMPLATE_DIRS` (`app/templating.py`);
- CDN запрещены, статика — только локальная;
- разрушительные действия подтверждаются двухшагово на Alpine, без
  `window.confirm()`;
- сингл-режим — `settings.single_mode`, читается в момент вызова;
- опубликованная страница отдаётся как файл, без серверного рендера.

## Goals / Non-Goals

**Goals:**

- Готовый черновик из профиля со всеми точками входа.
- Страница управления со статусом и действиями.
- Предпросмотр черновика без публикации.
- Пункт меню, видимый только там, где фича работает.
- Безопасность: экранирование полей профиля и 404 в мульти-режиме.

**Non-Goals:**

- Редактор GrapesJS и его роут.
- Клиентская подстановка «Вход…» (файл `landing-auth.js`).
- Загрузка картинок из интерфейса.

## Decisions

### D1. Самодостаточный шаблон вместо общего `base.html`

Опубликованная страница отдаётся с `/` как файл и не имеет доступа к
`app.css` и общему каркасу. Поэтому `default_page.html.j2` содержит весь CSS
inline и не наследует `base.html`. Это дублирует часть оформления, но
гарантирует, что страница выглядит одинаково у любого репетитора и не
зависит от версии дизайн-системы приложения.

### D2. Все поля профиля экранируются явно

Расширение `.j2` не входит в `select_autoescape` Jinja (там `.html`, `.htm`,
`.xml`), поэтому автоЭкранирования нет. Каждое значение выводится через
`| e`, включая `<title>` и значения атрибутов. Иначе `<script>` из «О себе»
стал бы исполняемым на публичной странице. Тест на экранирование обязателен.

### D3. Первый черновик создаётся явным действием

`GET /tutor/landing` не пишет на диск: иначе состояние «пусто» было бы
недостижимо, а правки редактора затирались бы при каждом открытии страницы.
Первый черновик создаёт `POST /tutor/landing/reset` (кнопка «Создать
черновик»), он же перезаписывает существующий по явному «Вернуть шаблон».

### D4. Статус публикации приоритетнее черновика

`page_state` возвращает `published`, если есть `index.html`, даже когда
черновик тоже есть: при опубликованной странице репетитору важно видеть, что
сайт уже показывает лендинг. Иначе — `draft` при наличии `draft.html`, иначе
`empty`.

### D5. Действия — обычные POST-формы с 303

Формы работают без JS, состояние живёт в URL (`?status=…`). Ответ — 303 на
страницу управления, что защищает от повторной отправки при обновлении.
Неизвестный `status` просто не показывает плашку. `no-draft` показывается
как ошибка-подсказка, остальные — как успех.

### D6. Подтверждение «Вернуть шаблон» на Alpine

Перезапись черновика — разрушительное действие, но системный диалог в
проекте не используется. Повторяем приём карточки группы: `x-data` с
флагом `confirming`, первый клик меняет подпись на «Точно вернуть шаблон?»,
второй отправляет POST. В пустом состоянии подтверждение не нужно — кнопка
«Создать черновик» отправляет форму сразу.

### D7. Гейт режима — на каждом роуте

`_ensure_landing_enabled()` вызывается первым действием и в GET, и в
предпросмотре, и во всех трёх POST. Проверка только на странице управления
позволила бы опубликовать лендинг прямым POST в мульти-режиме. В
мульти-режиме все роуты отвечают 404, как и остальная выключенная
функциональность.

### D8. Пункт меню зависит от флага, а не от CSS

`landing_enabled()` регистрируется как Jinja-global в
`register_template_helpers()` модуля лендинга, поэтому сайдбар видит флаг
без правки контекста каждой страницы. В мульти-режиме пункт не рендерится
вовсе: тест обхода внутренних ссылок сайдбара дёргает каждый `href`, и
скрытая CSS-ссылка на 404 уронила бы его.

### D9. Предпросмотр — `FileResponse` без кэша

Черновик меняется при каждой правке, поэтому отдаётся с `Cache-Control:
no-cache`, как и опубликованная страница с `/`. Ссылки на ассеты в
редакторском HTML абсолютные (`/landing-assets/…`), поэтому предпросмотр не
зависит от текущего URL.

## Risks / Trade-offs

- **Дублирование CSS.** Шаблон не использует дизайн-систему — это цена
  независимости публичной страницы. Правки оформления лендинга не должны
  ломать интерфейс CRM.
- **Забытый `| e`.** Новое поле профиля в шаблоне без фильтра — XSS. Тест
  на экранирование ловит регрессию.
- **Скрытая кнопка редактора.** `editor_available=False` — временное
  решение до задачи 4; шаблон уже содержит ветку для кнопки.
