# Design

## Context

Редактор лендинга — автономная страница GrapesJS 0.23.9 с локальной
статикой и русской локалью. Черновик лежит на диске (`draft.html`), в
редактор попадают тело без скриптов и первый `<style>`. Шаблон по
умолчанию (`default_page.html.j2`) задаёт классы секций и CSS-переменные
темы (`--accent`, `--border`, `--radius`, …). Asset Manager уже умеет
загружать и удалять картинки.

## Goals / Non-Goals

**Goals:**

- Добавить основные блоки лендинга в панель «Блоки» одним кликом.
- Вставленный блок сразу выглядит как страница: те же классы и токены.
- Вставка изображения открывает выбор/загрузку картинки.
- Набор блоков расширяется правкой одного Python-модуля.

**Non-Goals:**

- Генерация блоков из HTML текущего черновика.
- Хранение блоков в БД или отдельном JSON-файле.
- Поддержка пользовательских блоков и шаблонов.

## Decisions

### D1. Блоки — данные Python-сервиса, а не JS-массив в шаблоне

Набор описан в `app/landing/services/blocks.py` как список словарей
(`id`, `category`, `content`, опции). Вьюха сериализует его в JSON и
кладёт в `<script type="application/json" id="landing-blocks">` — тем же
приёмом, что черновик и список ассетов. Причины: разметку удобно
тестировать как данные (без браузера), подписи остаются в локали, а
шаблон редактора не разрастается.

### D2. Классы шаблона, а не собственные стили

Секции используют классы `.header`, `.hero`, `.section`, `.price`,
`.contact-link`, `.footer` из шаблона по умолчанию. Их правила уже лежат
в первом `<style>` черновика, поэтому вставка не требует новых стилей, а
сохранение не плодит дубли правил. Блоки без собственного класса
(разделитель, колонки) несут оформление в `style`-атрибуте: они должны
выглядеть одинаково и в старом черновике, где новых правил ещё нет.

### D3. CTA — адрес репетитора подставляет сервер

`/s/<tutor_id>` знает только сервер, поэтому `landing_blocks(cta_url)`
получает адрес из `public_page_url(tutor.id)`. Статический JSON блока не
может содержать чужой или устаревший id.

### D4. Вставка по клику

В GrapesJS 0.23.9 блок по умолчанию только перетаскивается
(`appendOnClick: false`). Для лендинга включено `appendOnClick: true`:
клик по блоку добавляет его в выбранный контейнер или в конец страницы.

### D5. Изображение выбирается сразу после вставки

Блок «Изображение» содержит `<img alt="…" data-landing-image>` без `src`:
пустой `src=""` браузер считает битой картинкой, а служебную
data-URI-заглушку GrapesJS не нужно сохранять в HTML. Редактор слушает
`component:add`, находит маркер `data-landing-image`, снимает его и
открывает Asset Manager с `types: ['image']`; выбранный ассет
записывается в `src` компонента. Маркер на сохранённой странице не
остаётся. Двойной клик по любой картинке в канвасе открывает Asset
Manager штатным поведением GrapesJS.

## Risks

- Новые блоки добавляют правила только за счёт существующего CSS
  шаблона; в черновике, где эти правила удалили, блоки будут выглядеть
  «голыми». Это осознанно: редактор не навязывает стили поверх правок
  репетитора.
- `appendOnClick` вставляет блок в конец выбранного контейнера — при
  вставке секции внутрь другой секции нужен откат (Ctrl+Z).
