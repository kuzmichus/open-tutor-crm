# Design

## Context

Плательщик ученика уже смоделирован: `students.payer_contact_id` — либо NULL
(платит сам ученик), либо привязанный к ученику контакт (`contacts`). Валидация
живёт в `app/student/services/student_form.py::validate_payer`, запись — в
`app/student/services/student_writer.py`, отображение — в
`app/student/templates/student/card.html`.

Признак «физлицо/юрлицо» относится не к конкретному человеку, а к тому, как
оформлены платежи по ученику: у одного и того же ребёнка может платить мама как
физлицо, а позже — компания родителя как юрлицо. Поэтому тип плательщика — это
свойство ученика, а не контакта.

## Goals / Non-Goals

**Goals:**

- Хранить тип плательщика у ученика: физлицо (по умолчанию) или юрлицо.
- Переключатель в форме рядом с выбором плательщика, без правок JS.
- Существующие данные и вызовы сервисов продолжают работать.

**Non-Goals:**

- Реквизиты юрлица (название, ИНН, банковские данные) и счета.
- Отчёты, фильтры и рассылки по типу плательщика.
- Тип плательщика у контакта или у платежа.

## Decisions

**D1. Отдельное поле `students.payer_type`, а не свойство контакта.**
Плательщиком может быть сам ученик (тогда `payer_contact_id IS NULL`), и тип
контакта в этом случае ничего не даёт. Кроме того, один контакт бывает
привязан к нескольким ученикам, а тип оплаты у них может различаться. Отдельная
колонка оставляет признак там, где он принимается решение — в карточке ученика.

**D2. Кодовые значения `individual` / `legal_entity`, дефолт `individual`.**
Значения — английские коды в стиле `kind`/`status`, подписи — в
`presentation.py` (`_PAYER_TYPE_LABELS`). Набор значений объявлен константой
`STUDENT_PAYER_TYPES` рядом с моделью, чтобы CHECK, парсер формы и подписи
ссылались на один источник. Пустое значение формы означает «не передано» и
трактуется как `individual`: так старые формы и вызовы сервиса из других
модулей не ломаются.

**D3. NOT NULL + `server_default='individual'` в миграции.**
Колонка обязательна: «тип не задан» — не третье состояние, а именно физлицо.
`server_default` заполняет существующие строки (NOT NULL без него упал бы на
таблице с данными) и сохраняет текущее поведение; ORM-дефолт остаётся для
INSERT. CHECK-ограничение `ck_students_payer_type` объявлено в самой колонке
миграции, поэтому откат `drop_column` уносит и его.

**D4. Валидация — в `parse_student_form`, запись — в `_apply_student_fields`.**
Правило «значение из закрытого списка» живёт рядом с остальными проверками
формы, а не в шаблоне. В writer поле записывается через
`data.get("payer_type") or "individual"`, а не через `_STUDENT_FIELDS`: прямые
вызовы `create_student`/`update_student` из тестов и других модулей приходят
без ключа, и `data[field]` дал бы `KeyError`.

**D5. Переключатель — существующая радиогруппа `.tabs` + `.sr-only`.**
Разметка повторяет «Кто ученик»: `role="radiogroup"`, подпись через
`aria-labelledby`, скрытые radio с `name="payer_type"`. Класс `tab--active` не
навешивается через Alpine — форма и так перерисовывается сервером после
сохранения, а `checked` выставляет шаблон по `form.payer_type`. Новых CSS и
правок `students.js` не требуется, поэтому визуально переключатель совпадает с
остальными сегментами карточки.

**D6. Отображение на карточке — подпись хелпером `payer_type_label`.**
Шаблон не содержит словаря кодов: подпись ставится рядом с ФИО плательщика
через хелпер, зарегистрированный в `register_template_helpers()` вместе с
`kind_label`. Неизвестное значение выводится как есть — так же ведёт себя
`status_label`.

## Risks / Trade-offs

- Риск: у существующих учеников тип станет «физлицо» независимо от реальности.
  Это безопасный дефолт: признак новый, раньше его не спрашивали, а
  переключение доступно в карточке.
- Риск: юрлицо-плательщик без реквизитов. Осознанно: задача про переключатель,
  реквизиты — отдельная функциональность.
- Риск: значение из старой формы без поля сохранит `individual` и затрёт
  выбранное ранее «юрлицо». Такой формы в интерфейсе нет: поле всегда
  отправляется вместе с остальными полями вкладки «Общее».
- Откат: `alembic downgrade` удаляет колонку и CHECK; revert коммитов убирает
  переключатель. Данные учеников не затрагиваются.
