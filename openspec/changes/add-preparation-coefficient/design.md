# Design

## Context

Вкладка «Календарь» (`/tutor/profile?tab=calendar`) — одна форма на несколько
карточек: часовой пояс, учебный год, рабочее время, желаемая нагрузка и основные
настройки. POST `/tutor/profile/calendar` разбирается `parse_calendar_form`
(`app/tutor/services/calendar_form.py`) и сохраняется `save_settings`
(`app/tutor/services/settings.py`) в `tutor_settings`. Значения полей для GET и
ре-рендера собирает `_form_defaults` (`app/tutor/services/profile_page.py`).

Настройки хранятся лениво: строки в БД нет до первого сохранения —
`get_settings` отдаёт transient-объект с дефолтами из `DEFAULTS`. Колонки с
`nullable=False` обязаны иметь ORM-дефолт, иначе upsert упадёт на NOT NULL.

## Goals / Non-Goals

**Goals:**

- Коэффициент подготовки хранится в настройках репетитора со значением по
  умолчанию 0.7.
- В карточке «Желаемая нагрузка» появляется второе поле с понятным пояснением.
- Валидация: число 0..5, запятая как разделитель допустима, пусто = 0.7.

**Non-Goals:**

- Использование коэффициента в расчётах загрузки, статистики и отчётов.
- Отдельная карточка под параметр: он относится к той же теме, что и нагрузка.
- Хранение коэффициента как процента: доля 0..1 читается проще и умножается на
  длительность урока без преобразований.

## Decisions

**D1. Отдельная колонка `tutor_settings.preparation_coefficient`,
`Numeric(4, 2)`, NOT NULL с ORM-дефолтом 0.70.**
Параметр скалярный, как `weekly_load_hours` и `workday_*`, поэтому живёт
отдельной колонкой. NOT NULL оправдан: у коэффициента всегда есть осмысленное
значение по умолчанию, «не задано» не имеет смысла. `Numeric(4, 2)` хранит
значения вида 0.70 и 1.25 без двоичных погрешностей float.

**D2. Диапазон 0..5, шаг 0.1 в UI.**
Ноль допустим — репетитор может не готовиться отдельно. Верхняя граница 5
отсекает опечатки (пять часов подготовки на час урока); шаг 0.1 задаёт
привычную точность, но сервер принимает любое конечное значение в диапазоне.

**D3. UI — второе поле в существующей карточке «Желаемая нагрузка».**
Нагрузка и коэффициент описывают одно и то же — сколько времени занимает
работа, поэтому карточка переводится на `.form-grid` из двух `.field`. Новых
CSS-классов не вводим.

**D4. Пустое поле возвращает значение по умолчанию, а не ошибку.**
Параметр всегда имеет значение, поэтому очистка поля означает «вернуть 0.7».
Мусор и значения вне диапазона отклоняются сообщением «Коэффициент подготовки —
число от 0 до 5 (например, 0.7).».

**D5. Общий парсер `decimal_or_none` в `app/common/services/forms.py`.**
Разбор десятичных полей нужен не только этой форме; общий парсер принимает
запятую и отбрасывает `NaN`/`Infinity`, которые `Decimal` разбирает, но в
`Numeric`-колонку не записать.

## Risks / Trade-offs

- `nullable=False` + `server_default='0.7'` безопасен для существующих строк:
  миграция заполнит их значением по умолчанию.
- `downgrade` удаляет введённые значения — откат только с бэкапом.
- Коэффициент пока нигде не используется — это осознанно, см. Non-Goals.
- Откат: revert коммитов плюс `alembic downgrade 5b38b6d8c1a1`.
