# Spec Delta

## MODIFIED Requirements

### Requirement: KV-таблица параметров репетитора
Параметры репетитора (токены мессенджеров, маркеры заданий и будущие настройки) SHALL храниться в таблице `tutor_params` — одна строка на пару «репетитор + ключ»: `tutor_id` (FK на `tutors`, CASCADE) + `key` + `value`. Сервис SHALL предоставлять `get_param`, `save_param` (upsert без коммита), `set_param` (upsert с коммитом), `delete_param`, `all_params` и `all_params_by_tutors` (параметры пачки репетиторов одним запросом).

#### Scenario: Запись и чтение параметра
- **WHEN** `set_param(db, tutor_id, "telegram_token", token)` вызывается дважды с разными значениями
- **THEN** `get_param` возвращает последнее, в таблице одна строка для этой пары

#### Scenario: Изоляция параметров
- **WHEN** параметр записан репетитору A
- **THEN** чтение по id репетитора B возвращает `None`

#### Scenario: Запись без коммита для задания cron
- **WHEN** задание cron сохраняет маркер через `save_param` и затем падает до коммита runner'а
- **THEN** значение в базе не меняется — транзакция откатывается целиком

#### Scenario: Параметры пачки репетиторов
- **WHEN** `all_params_by_tutors` вызывается для списка id
- **THEN** возвращается словарь «id репетитора → ключ → значение», прочитанный одним запросом; репетитор без параметров в результате отсутствует

## ADDED Requirements

### Requirement: Рассылка дней рождения
Система SHALL отправлять репетитору список именинников заданием cron: при включённом переключателе «День рождения» (`notify_birthday`) и достижении местным временем педагога времени отправки (`digest_time`) список учеников с днём рождения сегодня SHALL уходить во все привязанные каналы (Telegram, MAX). Сообщение SHALL содержать заголовок с датой и по строке на именинника: имя, фамилия и исполняющийся возраст. Схема БД MUST NOT меняться.

#### Scenario: Рассылка после времени из профиля
- **WHEN** местное время педагога достигает `digest_time`, переключатель «День рождения» включён, у репетитора есть именинник и привязан хотя бы один канал
- **THEN** во все привязанные каналы уходит сообщение со списком именинников и их возрастом

#### Scenario: Своё время отправки
- **WHEN** в профиле указано время отправки 18:00, а прогон задания выполняется в 09:00
- **THEN** сообщение не отправляется; в 18:00 и позже в тот же день список отправляется

#### Scenario: Несколько привязанных каналов
- **WHEN** у репетитора привязаны Telegram и MAX
- **THEN** одинаковый текст уходит в оба канала, а журнал `sent_messages` получает по строке на канал

#### Scenario: Изоляция по репетитору
- **WHEN** у другого репетитора именинник в тот же день
- **THEN** в список попадают только ученики этого педагога

#### Scenario: Часовой пояс педагога
- **WHEN** часовой пояс педагога отличается от UTC
- **THEN** время отправки и дата дня рождения считаются по настенному времени зоны педагога

### Requirement: Состав списка именинников
В список SHALL попадать каждый неархивный ученик репетитора с заполненной датой рождения, у которого месяц и день даты рождения совпадают с текущей локальной датой педагога. Фильтр по подтипу ученика (ребёнок/взрослый) MUST NOT применяться. Ученики без даты рождения и архивные в список не попадают. Порядок строк — по фамилии, при её отсутствии — по имени. Возраст SHALL выводиться как разница годов, а при годе рождения в будущем — не выводиться вовсе.

#### Scenario: Взрослый ученик
- **WHEN** у ученика с подтипом «взрослый» сегодня день рождения
- **THEN** он попадает в список наравне с детьми

#### Scenario: Архивный ученик
- **WHEN** у архивного ученика сегодня день рождения
- **THEN** в список он не попадает

#### Scenario: День рождения 29 февраля
- **WHEN** у ученика дата рождения 29 февраля, а текущий год невисокосный
- **THEN** в рассылку 28 февраля и 1 марта он не попадает

#### Scenario: Порядок строк
- **WHEN** именинников несколько
- **THEN** строки идут по фамилии; ученик без фамилии упорядочивается по имени

### Requirement: Условия отказа от рассылки дней рождения
Рассылка MUST NOT выполняться, если переключатель «День рождения» выключен, если у репетитора нет привязанного канала, если местное время ещё не достигло `digest_time` или если на текущий день именинников нет. Рассылка MUST отправляться не более одного раза за локальный календарный день; факт обработки дня SHALL фиксироваться маркером `birthday_digest_date` в `tutor_params` в той же транзакции, что и отправка.

#### Scenario: Переключатель выключен
- **WHEN** переключатель «День рождения» выключен
- **THEN** задание не отправляет сообщений и не ставит маркер дня

#### Scenario: Нет именинников
- **WHEN** на текущий день у педагога нет именинников
- **THEN** сообщение не отправляется, а день помечается обработанным — повторных проверок и пустых сообщений нет

#### Scenario: Повторный прогон в тот же день
- **WHEN** задание выполняется повторно в тот же локальный день после отправки списка
- **THEN** второе сообщение не отправляется

#### Scenario: Следующий день
- **WHEN** наступает следующий локальный день и его время отправки
- **THEN** список за новый день отправляется снова

#### Scenario: Нет привязанных каналов
- **WHEN** у репетитора не привязан ни один канал уведомлений
- **THEN** сообщение не отправляется, сетевые запросы к API мессенджеров не выполняются

### Requirement: Сбой канала не отменяет рассылку дней рождения
Отправка SHALL выполняться независимо по каждому привязанному каналу: ошибка доставки в один мессенджер MUST NOT препятствовать отправке в остальные и MUST NOT поднимать исключение из задания. Сбой SHALL фиксироваться в журнале `sent_messages`, а день SHALL считаться обработанным, чтобы сбойный канал не повторял попытку каждую минуту до конца дня. Сбой обработки одного репетитора MUST NOT мешать рассылке остальным.

#### Scenario: Один канал недоступен
- **WHEN** привязаны Telegram и MAX, а API Telegram отвечает ошибкой
- **THEN** сообщение доставляется в MAX, ошибка Telegram попадает в журнал, повторной отправки в этот день не происходит

#### Scenario: Некорректное время в настройках
- **WHEN** в `digest_time` сохранено значение вне формата «ЧЧ:ММ»
- **THEN** задание не падает, а использует время по умолчанию и пишет предупреждение в лог
