# Proposal

## Why

В профиле на вкладке «Календарь» есть поле «Длительность урока по умолчанию
(мин)» (`tutor_settings.default_lesson_duration`, по умолчанию 60). Значение
сохраняется и показывается обратно, но ни на что не влияет: новый урок
открывается с невыделенным селектом (браузер показывает первый вариант —
30 минут), а диалог окна для брони подставляет жёстко зашитые 40 минут из
примера спеки. Репетитор каждый раз выбирает длительность заново, хотя уже
сообщил её в настройках.

## What Changes

- Форма создания урока (`GET /tutor/lessons/new`) предвыбирает в селекте
  «Длительность» значение `default_lesson_duration` из профиля.
- Диалог окна для брони (`GET /tutor/slots/new`) предвыбирает то же значение
  в обоих режимах — «Одно окно» и «Несколько дней». Прежний дефолт 40 минут
  уходит: окно и урок из него должны совпадать по времени.
- Приоритет источников значения сохраняется: явно присланный
  `?duration_min=` (переход из окна «Записать ученика»), присланные данные
  после ошибки валидации и длительность существующего окна/урока остаются
  выше настройки профиля.
- Редактирование урока не меняется: форма показывает длительность самого
  урока, а не значение из профиля.
- Настройка, лежащая вне закрытого списка длительностей (ручная правка БД,
  старые данные), не ломает селект: подставляется 60 минут
  (`DEFAULT_LESSON_DURATION`).
- Значение читается через один хелпер
  `app.tutor.services.settings.default_lesson_duration(db, tutor_id)` —
  потребители (`lesson_form_context`, `dialog_context`) не дублируют
  валидацию по списку.
- Миграций и изменений схемы БД нет.

## Capabilities

### New Capabilities

— (нет)

### Modified Capabilities

- `lesson-management`: требование «Создание урока» — в создании без явной
  длительности селект предвыбирает настройку профиля; «Поле длительности» —
  уточнение про предвыбор.
- `slot-management`: требование «Окно создаётся из диалога в двух режимах» —
  длительность по умолчанию берётся из настроек профиля в обоих режимах.
- `tutor-profile-settings`: требование «Вкладка «Календарь» хранит часовой
  пояс, учебный год и настройки уроков» — `default_lesson_duration`
  применяется как предвыбранная длительность новых уроков и окон.

## Impact

- **Сервисы**: `app/tutor/services/settings.py` (новый
  `default_lesson_duration`), `app/lesson/services/lesson_form.py`
  (`lesson_form_context`), `app/slot/services/dialog_context.py`
  (`_single_values`, `_batch_values`, `dialog_context`).
- **Шаблоны**: правок не требуется — `lesson/_form.html` и
  `slot/_dialog.html` уже выделяют option по значению из контекста.
- **JS**: `app/static/lessons.js` читает фактическое значение селекта в
  `init()`, поэтому подсказка «Урок закончится в ЧЧ:ММ» согласуется с новым
  дефолтом автоматически.
- **Тесты**: `tests/test_lesson_create.py`, `tests/test_lesson_update.py`,
  `tests/test_slot_views.py` — новые сценарии; регресс
  `tests/test_calendar.py` (префилл из окна) и `tests/test_profile.py`.
- **Спецификации**: `openspec/specs/{lesson-management,slot-management,
  tutor-profile-settings}/spec.md` — после синхронизации delta-spec.
- **Вне объёма**: поле профиля остаётся `input[type=number] min=15` с
  серверной валидацией по списку (не select); дефолты режима «Несколько
  дней» (10:00–18:00, перерыв 15, будни) не меняются; стоимость урока по
  умолчанию в форму не подставляется.
- **CHANGELOG.md**: строка в секцию `[Unreleased]` → «Изменено».
