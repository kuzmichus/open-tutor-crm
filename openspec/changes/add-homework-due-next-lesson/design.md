# Design

## Context

Домашнее задание урока живёт в модуле `homework`:

- `app/homework/models/homework.py` — запись 1:1 с уроком, `due_at` в UTC;
- `app/homework/services/homework_context.py` — контекст панели
  (`panel_values`, `homework_panel_context`), поле «Срок сдачи» показывает
  настенное время зоны педагога через `to_local`;
- `app/homework/services/homework_writer.py` — ленивое создание и
  обновление записи ДЗ;
- `app/homework/templates/homework/_panel.html` — форма панели.

Панель рендерится и в модалке редактирования урока
(`lesson_form_context`), и ответом на сохранение/удаление файла. Значения
полей собираются в одном месте — `homework_panel_context`.

«Ближайший урок ученика» в проекте уже считается: индивидуальные уроки
плюс групповые через `GroupMember`, статус `planned`, `starts_at >= now`
(`app/student/services/list_metrics.py::_next_lessons`,
`app/cabinet/services/lessons.py::upcoming_lessons`). Новый сервис повторяет
этот шаблон, но с дополнительным условием «позже текущего урока».

## Goals / Non-Goals

**Goals:**

- Один источник правила «следующее занятие» — сервис
  `next_lesson_start(db, lesson, *, now=None)`.
- Панель нового ДЗ показывает подставленный срок в зоне педагога.
- Сохранение нового ДЗ без срока тоже получает подстановку (работает без
  JS: форма отправляется обычным POST).
- Существующая запись ДЗ не меняется: подстановка — только при создании.

**Non-Goals:**

- Хранение признака «срок подставлен» и автоматический пересчёт при
  переносе следующего урока.
- Напоминания и автостатус по дедлайну.
- Подстановка в форме создания урока (вкладки «ДЗ» там нет).

## Decisions

**D1. Подстановка — сервис `next_lesson_start`, а не вычисление в вьюхе.**
Правило нужно двум местам (контекст панели и writer), поэтому живёт в
`app/homework/services/due_default.py` и не знает про FastAPI. Шаблон и
вьюхи получают готовое aware-UTC значение.

**D2. Цель поиска зависит от типа урока.**
У индивидуального/пробного/отработочного урока есть `student_id`: ищем
минимум по индивидуальным урокам ученика и по групповым через `GroupMember`
(как «ближайший урок» в списке учеников). У группового урока цели-ученика
нет — берём уроки той же группы.

**D3. Фильтры: `planned`, позже текущего урока, не раньше «сейчас».**
Проведённое занятие сроком сдачи быть не может, а занятие в прошлом —
бессмысленный дедлайн. Условие `starts_at > lesson.starts_at` отсекает сам
урок, к которому добавляют ДЗ, и всё, что раньше; `Lesson.id != lesson.id`
оставлен страховкой от строки с тем же временем.

**D4. Панель подставляет срок только при отсутствии записи ДЗ.**
`homework_panel_context` вычисляет значение лишь когда `get_homework(...)`
вернул `None`. Иначе сохранённый (в том числе вручную очищенный) срок
перекрывался бы подсказкой при каждом открытии модалки.

**D5. Writer дублирует подстановку для пути без значения в форме.**
Форма без JS отправляет пустое `due_at`; полагаться на предзаполнение поля
нельзя (пользователь мог очистить его, запрос мог прийти из API). При
создании записи с `due_at is None` writer подставляет `next_lesson_start`.
Существующую запись writer не трогает: `due_at` из формы применяется как
есть.

**D6. Подсказка — существующий класс `.form-hint`.**
Новых BEM-классов не вводим: рядом уже есть подсказки полей ДЗ. Текст
«По умолчанию — начало следующего занятия» показывается только когда
значение действительно подставлено (`hw_due_default`), а не при
перерисовке после ошибки с присланными полями.

**D7. Время нормализуется через `as_utc`.**
SQLite теряет tzinfo; сравнение и минимум считаются по aware-UTC, как в
остальных сервисах проекта.

## Risks / Trade-offs

- Два дополнительных SELECT при открытии вкладки «ДЗ» у урока без ДЗ. Оба
  идут по индексам `lessons.starts_at`/`student_id`/`group_id` и
  ограничены `LIMIT`-подобной выборкой минимума в Python; на объёмах CRM
  это незаметно.
- Срок не пересчитывается после переноса следующего занятия — это осознанно:
  ДЗ может быть сдано раньше, и молчаливая правка сохранённого поля
  удивила бы педагога.

## Migration Plan

Схема БД не меняется, миграций нет. Откат — удаление подстановки в панели и
writer (данные не затрагиваются).
