# Spec Delta

## ADDED Requirements

### Requirement: Бэкенд хранения выбирается конфигурацией

Система SHALL хранить байты загруженных файлов вне базы данных и SHALL выбирать
хранилище переменной окружения `FILES_BACKEND`: `local` (по умолчанию) —
локальный каталог `FILES_LOCAL_ROOT`, `s3` — S3-совместимый бакет.

#### Scenario: Локальное хранилище по умолчанию
- **WHEN** `FILES_BACKEND` не задан и файл загружен
- **THEN** объект записан в каталог `FILES_LOCAL_ROOT`, метаданные — в таблицу файлов с бэкендом `local`

#### Scenario: S3-хранилище
- **WHEN** `FILES_BACKEND=s3`, заданы `S3_BUCKET` и ключи доступа, файл загружен
- **THEN** объект записан в бакет с префиксом `S3_PREFIX`, метаданные — с бэкендом `s3`

#### Scenario: Неполная конфигурация S3
- **WHEN** `FILES_BACKEND=s3`, но не задан бакет или ключи доступа
- **THEN** приложение не стартует и сообщает, каких параметров не хватает

### Requirement: Параметры S3 в конфигурации

Для бэкенда `s3` система SHALL читать бакет `S3_BUCKET`, регион `S3_REGION`,
необязательный адрес S3-совместимого хранилища `S3_ENDPOINT_URL`, ключи
`S3_ACCESS_KEY_ID`/`S3_SECRET_ACCESS_KEY` и префикс ключей `S3_PREFIX`.

#### Scenario: MinIO через свой адрес
- **WHEN** задан `S3_ENDPOINT_URL` локального MinIO
- **THEN** клиент S3 обращается к этому адресу, а не к AWS по умолчанию

### Requirement: Метаданные файла помнят своё хранилище

В базе данных SHALL храниться только метаданные файла: владелец, бэкенд, ключ
объекта, исходное имя, тип содержимого, размер и время создания. Файл SHALL
читаться из того хранилища, которое записано в его метаданных, а не из текущего
значения `FILES_BACKEND`.

#### Scenario: Старый файл читается своим бэкендом
- **WHEN** файл был сохранён при `FILES_BACKEND=local`, а затем бэкенд переключён на `s3`
- **THEN** этот файл по-прежнему читается из локального хранилища, а новые файлы пишутся в S3

### Requirement: Валидация загружаемого файла

Загрузка SHALL принимать только файлы с расширением из списка
`FILES_ALLOWED_EXTENSIONS` и размером не больше `FILES_MAX_SIZE_MB`. Нарушение
любого условия MUST NOT сохранять ни объект в хранилище, ни метаданные: форма
SHALL показывать сообщение об ошибке.

#### Scenario: Запрещённое расширение
- **WHEN** загружается файл с расширением вне списка разрешённых
- **THEN** файл не сохранён, форма показывает сообщение об ошибке

#### Scenario: Превышение размера
- **WHEN** размер файла больше `FILES_MAX_SIZE_MB`
- **THEN** файл не сохранён, форма показывает сообщение об ошибке

#### Scenario: Пустое имя файла
- **WHEN** в форме выбрано поле файла без имени
- **THEN** файл не сохранён, форма показывает сообщение об ошибке

### Requirement: Ключ объекта формирует сервер

Имя объекта в хранилище SHALL формировать сервер; исходное имя файла SHALL
сохраняться только как метаданные и SHALL использоваться как имя при скачивании.

#### Scenario: Ключ объекта без пользовательских имён
- **WHEN** загружен файл «Домашняя работа Иванова.pdf»
- **THEN** объект в хранилище получает сгенерированный ключ, а исходное имя сохраняется в метаданных

### Requirement: Временные ссылки на скачивание в S3

Для бэкенда `s3` скачивание SHALL выполняться по временной ссылке (presigned
URL) со сроком жизни `FILES_PRESIGN_TTL_SECONDS`; бакет MUST быть приватным.

#### Scenario: Скачивание из S3
- **WHEN** пользователь с доступом открывает адрес файла, сохранённого в S3
- **THEN** ответ — перенаправление на временную ссылку, действующую `FILES_PRESIGN_TTL_SECONDS`

#### Scenario: Имя и тип при скачивании из S3
- **WHEN** пользователь скачивает файл из S3 по временной ссылке
- **THEN** файл приходит вложением под исходным именем и со своим типом содержимого

### Requirement: Отдача локального файла приложением

Для локального бэкенда файл SHALL отдавать само приложение с проверкой доступа и
заголовками `Content-Disposition: attachment` и
`X-Content-Type-Options: nosniff`.

#### Scenario: Скачивание из локального хранилища
- **WHEN** пользователь с доступом открывает адрес файла, сохранённого локально
- **THEN** файл отдаётся как вложение под исходным именем, без кэширования браузером

### Requirement: Доступ к файлам ограничен участниками ДЗ

Скачивание файла SHALL быть доступно репетитору-владельцу файла, ученику
домашнего задания, к которому привязан файл (индивидуальный урок или группа с
его участием), и родителю, привязанному к этому ученику.

#### Scenario: Ученик своего ДЗ
- **WHEN** ученик открывает файл, привязанный к ДЗ его урока
- **THEN** файл скачивается

#### Scenario: Родитель ребёнка
- **WHEN** родитель открывает файл, привязанный к ДЗ его ребёнка
- **THEN** файл скачивается

### Requirement: Чужой файл неотличим от несуществующего

Запрос файла без доступа MUST отвечать так же, как запрос несуществующего файла.

#### Scenario: Чужой репетитор
- **WHEN** репетитор B открывает файл ДЗ репетитора A
- **THEN** система отвечает как при отсутствии файла

#### Scenario: Без входа
- **WHEN** файл запрошен без действующей сессии
- **THEN** система отвечает как при отсутствии файла

#### Scenario: Посторонний ученик
- **WHEN** ученик открывает файл ДЗ чужого урока
- **THEN** система отвечает как при отсутствии файла

### Requirement: Удаление файла убирает и объект, и метаданные

Удаление файла SHALL удалять объект в хранилище и строку метаданных. Сбой
хранилища MUST NOT оставлять метаданные без объекта.

#### Scenario: Удаление файла из панели ДЗ
- **WHEN** репетитор удаляет прикреплённый файл
- **THEN** объект в хранилище и строка метаданных удалены, файл исчезает из списка панели

#### Scenario: Сбой хранилища при удалении
- **WHEN** хранилище не отвечает при удалении файла
- **THEN** метаданные файла не остаются в базе, ошибка записывается в журнал

### Requirement: Удаление урока уносит объекты файлов

Удаление урока или серии SHALL удалять объекты файлов ДЗ этих уроков, а
метаданные — каскадом вместе с записями ДЗ.

#### Scenario: Удаление урока
- **WHEN** урок с прикреплёнными файлами ДЗ удалён
- **THEN** объекты этих файлов и их метаданные удалены
