# Design

## Context

Модуль финансов уже разделён на сервисы: `summary.period_flow` считает суммы
по видам операций одним `GROUP BY`, `balance_sides` — долги и переплаты,
`expenses.period_expenses` — траты, `presentation` форматирует подписи.
Шаблон `finance/_summary.html` ничего не считает.

Время в проекте уже посчитано для «Статистики»: `stats/services/hours.py`
даёт `completed_minutes`/`planned_minutes` из `Lesson.duration_min` (с
правилом «групповой урок — время педагога»), `stats/services/availability.py`
— `available_minutes` из рабочего шаблона и отметок недоступности. Денежная
сторона урока — `Lesson.price` и `group_member.price_override ??
group.price_per_lesson`, а списания создаёт `finance/services/charges.py`,
проставляя `lesson_id` и `occurred_at = lesson.starts_at`.

## Goals / Non-Goals

**Goals:**

- Показать, за какое астрономическое время заработаны деньги (часы + RevPTH).
- Дать простому денежную цену и путь в календарь.
- Сравнить индивидуальные и групповые занятия по деньгам на час.
- Исправить «Доход = 0 при начисленных 1 200»: начисление и касса — разные
  числа, оба видны.

**Non-Goals:**

- Прогноз свободных часов на будущие месяцы и план загрузки.
- Учёт почасового шаблона недели (разные часы по дням) — его нет в модели.
- Пересчёт тарифов, скидок и цен: используются уже сохранённые суммы списаний.
- Изменения схемы БД и миграции.

## Decisions

**D1. Единица времени — астрономический час, источник — `Lesson.duration_min`.**
Второй копии перевода минут в часы не появляется: `time_metrics` вызывает
`stats.services.hours.completed_minutes`. 45 минут — 0,75 часа; групповой
урок считается один раз.

**D2. «Доход» = начисленный доход (`kind='lesson'`), касса — отдельно.**
`summary_context` возвращает `income = flow["earned"]`; касса — `received =
оплаченные платежи − возвраты`. «Чистая прибыль» и «Осталось репетитору»
считаются от кассы: расходы платятся живыми деньгами. Тем самым сценарий
бага читается согласованно: «Доход 1 200», «Долги 1 200», «Получено 0»,
«Чистая прибыль −15 000».

**D3. RevPTH = начисленный доход ÷ проведённые часы; часов нет — `None`.**
`None` печатается как «—», а не «0 ₽/ч»: ноль выглядел бы измеренным
значением. Округление до рубля: копейки в стоимости часа — ложная точность.

**D4. Простой — только предстоящее время текущего месяца.**
Окно: `[начало сегодняшних суток в зоне педагога, начало следующего
календарного месяца)`. Свободные минуты = `available_minutes −
completed_minutes − planned_minutes`, не ниже нуля. Прошедшие дни месяца не
считаются: потерять можно только будущее время. Запланированный урок занимает
окно — иначе «свободными» оказались бы занятые часы.

**D5. Упущенная выручка = свободные часы × RevPTH; без множителя суммы нет.**
Если свободных часов нет — блок говорит об этом; если нет RevPTH (не было
проведённых часов) — называет часы, но не выдумывает сумму: «~0 ₽» соврал бы
о размере потерь. Ссылка «Посмотреть свободные окна» есть во всех состояниях.

**D6. Типы занятий: групповые — по `Lesson.group_id`, остальное — индивидуальные.**
Выручка групповых считается одним запросом списаний с JOIN по уроку;
индивидуальная — остаток `earned − группа`. Поэтому сумма колонок всегда
равна карточке «Доход», включая списания без `lesson_id` (внесённые вручную).
Часы — по типам из `Lesson.duration_min`, групповой урок один раз.

**D7. Инсайт о группе — только при строгом преимуществе и ненулевых базах.**
Условия: у обоих типов есть часы и RevPTH, RevPTH группы строго выше. Текст:
«Групповые занятия приносят вам в N раза больше денег за час времени. Стоит
набрать ещё одну группу». Иначе блока нет — без деления на ноль и без
советов «в 0 раз».

**D8. Ряд аналитики переименован в «Получено».**
Ключ `income` и семантика сумм не меняются (оплаченные платежи), меняется
только подпись: на странице «Доход» теперь означает начисление, и два разных
числа под одним словом читались бы как ошибка.

**D9. `summary_context` принимает объект репетитора.**
Часы и простой считаются в зоне педагога (`today_local`, `local_day_bounds`),
а вьюхи уже загружают `Tutor` для проверки сессии — второй `SELECT` не нужен.

## Risks / Trade-offs

- Простой считается от начала сегодняшних суток: уже прошедшие «пустые» часы
  сегодняшнего дня в потери не попадают — осознанно, это уже история.
- `available_minutes` перебирает сутки в Python (как в «Статистике»): окно
  ограничено остатком месяца, поэтому дешёво.
- Списания без `lesson_id` отнесены к индивидуальным: точного типа у них нет,
  но сумма колонок обязана сходиться с «Доходом» — приоритет у согласованности.
- RevPTH зависит от начисления, а не от кассы: при большой дебиторке стоимость
  часа выше реально полученной — это отражено подписью «начислено».
- Откат: revert коммитов; миграций нет, данные не меняются.
