# Design

## Context

Страница `/tutor/profile` — одна страница с вкладками: ключ вкладки живёт в
query-параметре (`?tab=…`), набор вкладок задаётся кортежем `TABS` и словарём
`TAB_ACTIONS` в `app/tutor/services/profile_page.py`, значения полей собирает
`_form_defaults`, разметку вкладки подключает `app/tutor/templates/tutor/profile.html`.
У каждой вкладки свой POST-роут (образец — «Календарь»:
`app/tutor/views/profile_calendar.py` + `app/tutor/services/calendar_form.py`).

Настройки репетитора живут в `tutor_settings` (`app/tutor/models/tutor_settings.py`):
колонки + словарь `DEFAULTS`. Чтение — `get_settings` (до первого сохранения
отдаёт transient-объект с дефолтами), запись — `save_settings` (ленивый upsert).
Колонки с `nullable=False` обязаны иметь ORM-дефолт, иначе upsert упадёт на
NOT NULL.

## Goals / Non-Goals

**Goals:**

- Пятая вкладка «Финансы» с блоком «Налоги»: признак плательщика НПД, две
  ставки (4 % и 6 %) и годовой лимит дохода (2 400 000 ₽).
- Значения хранятся в настройках репетитора, изолированы по владельцу,
  переживают перезагрузку и повторно показываются.
- Валидация на сервере с сообщением на той же вкладке; пустое числовое поле
  возвращает значение по умолчанию.

**Non-Goals:**

- Расчёт налогов и отчёты по НПД, напоминания о приближении к лимиту.
- Автоматическое определение типа плательщика по ученикам (у ученика уже есть
  свой `payer_type`, но связывать его со ставками в этой задаче не нужно).
- Отдельная страница раздела финансов: вкладка живёт в профиле, как просит
  постановка.

## Decisions

**D1. Четыре отдельные колонки в `tutor_settings`.**
`npd_enabled` (`Boolean`, NOT NULL, дефолт `False`), `npd_tax_rate_individual` и
`npd_tax_rate_legal_entity` (`Numeric(5, 2)`, NOT NULL, дефолты 4.00 и 6.00),
`npd_annual_income_limit` (`Integer`, NOT NULL, дефолт 2 400 000). Параметры
скалярные, как `weekly_load_hours` и `preparation_coefficient`, поэтому живут
отдельными колонками, а не JSON-блоком: так их видно в схеме и можно
индексировать/агрегировать в будущих отчётах. `Numeric(5, 2)` покрывает
`100.00` и хранит ставки без двоичной погрешности float.

**D2. Вкладка добавляется в конец `TABS` — после «Календаря».**
Порядок вкладок — порядок кортежа; «Финансы» логично стоят последними, чтобы не
менять привычное расположение существующих вкладок.

**D3. Отдельный POST-роут `/tutor/profile/finances`.**
Каждая вкладка страницы сохраняется своим роутом (как «Календарь» и
«Уведомления»): одна форма — один обработчик, поля других вкладок не
присылаются и не затираются.

**D4. Пустое числовое поле = значение по умолчанию, а не ошибка.**
У каждой из настроек всегда есть осмысленное законодательное значение (4 %, 6 %,
2 400 000 ₽), поэтому очистка поля означает «вернуть значение по умолчанию» —
то же правило, что у «Коэффициента подготовки». Мусор, `NaN`, `Infinity` и
значения вне диапазона (ставки 0..100, лимит ≥ 0) отклоняются.

**D5. Переключатель НПД — только признак статуса.**
При выключении ставки и лимит не сбрасываются и не скрываются: репетитор может
временно потерять статус и вернуть его, не вводя значения заново.

**D6. Никаких новых CSS-классов.**
Разметка собрана из существующих: `card settings-card`, `settings-list`,
`switch-row`, `switch`, `form-grid`, `field`, `label`, `input`, `card__desc`,
`settings-actions`. Тест `tests/test_css_styles.py` требует, чтобы каждый
литеральный класс шаблона был описан в `styles.css`, поэтому переиспользование —
не только стилистическое, но и техническое требование.

## Risks / Trade-offs

- `nullable=False` + `server_default` безопасны для существующих строк: миграция
  заполнит их дефолтами (не плательщик, 4 %, 6 %, 2 400 000 ₽).
- `downgrade` удаляет введённые значения — откат только с бэкапом.
- Название вкладки «Финансы» совпадает с названием раздела `/tutor/finance`:
  это разные страницы (настройки профиля против операций и балансов), в спеке
  различие зафиксировано явно.
- Откат: revert коммитов плюс `alembic downgrade c3f1a9d7e2b4`.
