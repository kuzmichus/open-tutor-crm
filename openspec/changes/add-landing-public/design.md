# Design

## Context

Лендинг — одна страница на установку, которую владелец правит визуально в
GrapesJS. В базе хранить нечего: HTML и картинки — файлы. Публичная часть
должна быть максимально дешёвой: `GET /` не рендерит шаблон и не ходит в БД.

В проекте уже есть образец дискового хранилища — `app/files/services/
storage_local.py`: атомарная запись через временный файл и `os.replace`,
проверка «путь внутри корня» у последней границы, где строка становится
путём. Лендинг повторяет эти приёмы, но без абстракции бэкендов: S3 для
одной страницы не нужен, а `FILES_*` описывают пользовательские загрузки с
метаданными в БД.

Корень `/` принадлежит `app/common/views/index.py`; лендинг лишь
перехватывает ответ, когда страница опубликована. Сингл-режим уже есть
(`settings.single_mode`, `app/tutor/services/registration_mode.py`) —
фича включается тем же флагом.

## Goals / Non-Goals

**Goals:**

- Дисковый слой без веба: пути, наличие, чтение/запись черновика,
  публикация с бэкапом, отмена публикации, ассеты.
- `GET /` отдаёт опубликованный файл в сингл-режиме, иначе прежний 303.
- Картинки публично с `/landing-assets/<uuid>.<ext>` и долгим кэшем.
- Имя ассета генерирует сервер; пользовательский ввод в путь не попадает.
- Чтения на пустом корне не падают и не создают каталогов.

**Non-Goals:**

- Редактор, предпросмотр, загрузка картинок из UI — следующая задача.
- Серверная подстановка данных в страницу.
- Хранение в S3/БД, версионирование глубже одного бэкапа.
- Проверка содержимого картинок (антивирус, размеры, декодирование).

## Decisions

**D1. Отдельный модуль `app/landing/`, а не расширение `app/files/`.**
У загрузок файлов есть метаданные в БД, бэкенды и проверка доступа по
сессиям; у лендинга — один файл и публичная отдача. Общий код (атомарная
запись) крошечный, а смешение двух моделей в одном модуле усложнило бы оба.
Модуль следует конвенции `services`/`views`/`templates`; `models` нет.

**D2. Ленивое создание каталогов.**
`LandingStorage.__init__` только запоминает путь. Каталог создаётся при
первой записи (`mkdir(parents=True)` в `_write_atomic`). Свежая установка без
лендинга не получает пустой каталог, а чтения (`has_draft`, `has_published`,
`read_draft_html`, `list_assets`) отвечают «нет»/пустым списком без
исключений.

**D3. Публикация копирует черновик, а не переносит.**
`publish()`: если `index.html` есть — его байты пишутся в `index.prev.html`
(перезапись, хранится одна прошлая версия), затем байты `draft.html` — в
`index.html`. Черновик остаётся: редактор продолжает показывать предпросмотр
и править страницу после публикации. `unpublish()` удаляет только
`index.html` (`missing_ok`), бэкап и черновик не трогает.

**D4. Корень отдаёт `FileResponse` с `no-cache`.**
Файл читается с диска на каждый запрос, поэтому `Cache-Control: no-cache`
обязателен: браузер сверяет страницу с сервером (ETag/Last-Modified), и
обновление публикации видно сразу. `media_type="text/html"` фиксирован —
расширение `.html` и так дало бы его, но явный тип не зависит от `mimetypes`
системы.

**D5. Ассеты — публично и с `immutable`-кэшем.**
Имя — `uuid4` и расширение, поэтому содержимое под одним именем не меняется:
`public, max-age=31536000, immutable` корректен и снимает повторные запросы.
Тип содержимого берётся из явной таблицы (`image/svg+xml` для SVG), а не из
`mimetypes`: на части систем SVG определяется как `text/plain`.

**D6. Строгий regex имени — одновременно валидация и защита от traversal.**
`^[0-9a-f]{8}-…\.(png|jpe?g|gif|webp|svg)$` не пропускает `/`, `..`, `%2F`
и прочий ввод: не прошедшее имя — 404 до обращения к диску. Дополнительно
`LandingStorage.asset_path` отвергает разделители и нулевой байт — граница
«строка → путь» защищена и внутри сервиса (как в локальном хранилище файлов).

**D7. `settings` читается в момент вызова.**
`access.published_landing()` и `get_storage()` обращаются к глобальному
`settings` внутри функций: тесты подменяют `landing_root` и `single_mode`
через `monkeypatch`, владелец сервера меняет окружение и перезапускает
приложение. Кэш хранилища не нужен — объект дешёвый.

## Risks / Trade-offs

- **Одна прошлая версия.** Бэкап перезаписывается при каждой публикации;
  откат возможен ровно на один шаг. Для одной страницы этого достаточно, а
  история версий — отдельная задача.
- **`no-cache` на каждом запросе корня.** Ответ 304 дешёвый, но запрос всё
  равно доходит до приложения. Альтернатива (`max-age`) показывала бы старую
  страницу после публикации — это хуже.
- **Публичные картинки.** Ассет, ссылку на который убрали из страницы,
  остаётся доступным по прямому адресу. Имя — uuid, перебор нереалистичен;
  удаление ассета — забота редактора.
- **`<script>` в опубликованном HTML.** Осознанное решение: страницу правит
  владелец установки, это его домен и его код.

## Migration Plan

Схема БД не меняется, миграции не нужны. Новая настройка имеет безопасный
дефолт (`./landing`), каталог создаётся при первой записи. В образе каталог
`/data/landing` создаётся в Dockerfile на томе `/data` рядом с базой и
загрузками. Откат — вернуть прежний `app/common/views/index.py`; файлы
лендинга остаются на диске и не мешают.
