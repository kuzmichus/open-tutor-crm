# Design

## Context

Главная страница (`GET /tutor/`) рендерится одним шаблоном
`app/tutor/templates/tutor/home.html` из контекста
`app/tutor/services/dashboard.py::dashboard_context`. Два нижних блока —
`home-grid` из двух `home-panel`: «Расписание на сегодня» (`today_lessons`) и
«Недавние платежи» (`recent_payments`).

Пустое состояние обоих блоков было одной строкой:

```html
<p class="home-empty">На сегодня уроков нет</p>
```

В дизайн-системе уже есть `.empty-state` (ученики, группы, уроки, статистика):
центрированная колонка с иконкой 32×32, заголовком и подсказкой. Она задаёт
`grid-column: 1 / -1` и большие отступы — рассчитана на замену целой сетки
карточек, а не панели внутри главной.

## Goals / Non-Goals

**Goals:**

- Заглушка из трёх частей: декоративная иконка, заголовок, подсказка.
- Центрирование внутри панели и минимальная высота, чтобы блок не «схлопывался».
- Стили на токенах темы (светлая и тёмная темы).
- Тесты на разметку заглушек и на их отсутствие при наличии данных.

**Non-Goals:**

- Изменение сервисов и выборок дашборда — данные остаются прежними.
- Клиентский JS: всё рендерится сервером, иконки рисует существующий
  `app/static/icons.js`.
- Переиспользование `.empty-state` и правка её правил (её используют другие
  страницы, там своя геометрия).

## Decisions

**D1. Отдельный блок классов `.home-empty*`, а не `.empty-state`.**
`.empty-state` тянет `grid-column: 1 / -1` и padding `10×space` — внутри
`home-panel` это лишние отступы и бессмысленное свойство сетки. Локальные
классы держат стиль главной в её секции CSS, а общий `.empty-state` не меняется
— его проверяют тесты других модулей.

**D2. Минимальная высота вместо фиксированной.**
`min-height: calc(var(--space) * 45)` (180px) примерно равна высоте списка из
двух-трёх строк. Фиксированная высота сломалась бы при длинных подсказках и
крупном шрифте; `min-height` только не даёт блоку «схлопнуться», а при
нехватке места контент растит панель.

**D3. Иконки декоративные (`aria-hidden="true"`).**
Смысл несут заголовок и подсказка; скринридер не должен читать «calendar».
Атрибут есть — набор иконок не добавляет `aria-hidden` сам, если у элемента
задано `aria-*` (см. `app/static/icons.js`, `hasAccessibleName`), поэтому
указываем явно.

**D4. Иконки из уже собранного набора.**
`calendar` и `credit-card` в `app/static/icons.js` есть (календарь — в
сайдбаре и стат-карточке, карта — в пункте «Финансы»). Пересборка
`scripts/build_icons.py` не нужна, размер набора не растёт.

**D5. Приглушение иконки — `opacity` на токене `--muted-foreground`.**
Референс рисует иконку светлее текста. Отдельный токен под неё заводить не
нужно: `opacity: 0.55` поверх `--muted-foreground` даёт тот же эффект и в
тёмной теме, а литеральных цветов в CSS не появляется (это проверяет
`tests/test_css_styles.py`).

**D6. Подписи — по референсу, а не прежние строки.**
«Нет запланированных уроков» / «Добавьте урок в календаре» и «Нет платежей» /
«Платежи появятся здесь». Заголовок отвечает «что случилось», подсказка —
«что делать». Тесты ищут текст в пределах своей панели (`_panel`), чтобы
подпись одного блока не засчитывалась другому.

## Risks / Trade-offs

- **Смена текстов ломает старые проверки.** `tests/test_home.py` ищет прежние
  «На сегодня уроков нет» / «Платежей пока нет» — тест обновлён вместе с
  шаблоном, иначе он падал бы на изоляции.
- **Высота заглушки зависит от контента.** При очень узкой панели подсказка
  переносится и блок выше — это ожидаемо, `min-height` не мешает.
- **Дублирование стиля с `.empty-state`.** Два похожих блока CSS, но с разной
  геометрией и разными потребителями; объединение потребовало бы
  модификатора у общего класса и правки чужих шаблонов.
