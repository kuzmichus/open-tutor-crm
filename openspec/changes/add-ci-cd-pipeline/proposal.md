# Proposal

## Why

В проекте нет CI: 1864 теста, свежесть собранных иконок и правила из AGENTS.md
проверяются только руками, а образ для self-hosted развёртывания собирается
на машине разработчика без гарантии, что он соответствует коммиту. Из-за этого
регрессия обнаруживается уже после merge, а опубликованный образ может содержать
код, не проходивший тесты.

Автоматические проверки на push/pull_request ловят расхождение до merge, а
ручная публикация по кнопке даёт воспроизводимый образ в Docker Hub с тегом,
совпадающим с версией проекта.

## What Changes

- Новый workflow проверок на `push` и `pull_request`: прогон тестов, проверка
  lock-файла, проверка отсутствия дрейфа схемы миграций, линт узким набором
  правил, сборка Docker-образа со смоук-проверкой `/health`.
- Новый workflow публикации, запускаемый вручную (`workflow_dispatch` с полем
  `version`): тесты → сборка `linux/amd64` → push в Docker Hub → git-тег.
  Публикация не начинается, если тесты красные.
- Версия приложения читается из `pyproject.toml` вместо захардкоженной строки
  в `create_app()` — тег, образ и `app.version` перестают расходиться.
- README и AGENTS.md описывают, как запускаются проверки и как выпускается
  релиз.

**Вне области этого change:**

- Совместимость с PostgreSQL. README обещает смену `DATABASE_URL`, но
  `app/database.py` выполняет `PRAGMA foreign_keys=ON` без проверки диалекта —
  на PostgreSQL это упадёт. Сначала нужна правка кода, потом матрица БД в CI.
- Пиннинг `ruff` в dev-группу зависимостей. Версия линтера фиксируется
  в самом workflow, чтобы не менять `pyproject.toml` и `uv.lock`.
- Гейт по проценту покрытия и проверка `openspec validate` в CI.

## Capabilities

### New Capabilities

- `ci-cd-pipeline`: контракт автоматических проверок на push/pull_request и
  ручной публикации Docker-образа — какие проверки обязательны, при каких
  условиях публикация разрешена, какие теги получает образ и как версия
  приложения связана с тегом релиза.

### Modified Capabilities

Нет. Поведение CRM для пользователя не меняется: правка версии в `create_app()`
затрагивает только метаданные приложения и попадает в требования новой
capability как часть контракта релиза.

## Impact

- **Новые файлы**: `.github/workflows/ci.yml`, `.github/workflows/release.yml`.
- **Код**: `main.py` — версия приложения берётся из `pyproject.toml`.
- **Документация**: `README.md` (раздел про развёртывание и участие в проекте),
  `AGENTS.md` (раздел про проверки перед PR).
- **Внешние системы**: GitHub Actions (бесплатные минуты — репозиторий публичный),
  Docker Hub (`kuzmichus/open-tutor-crm`).
- **Секреты**: `DOCKERHUB_USERNAME`, `DOCKERHUB_TOKEN` — только в workflow
  публикации, недоступны в pull_request из форков.
- **Зависимости**: не меняются; `pyproject.toml` и `uv.lock` остаются как есть.
