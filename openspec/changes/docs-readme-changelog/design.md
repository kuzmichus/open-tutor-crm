# Design

## Context

Сейчас `README.md` — 633 строки: блок «Возможности» из ~20 абзацев дублирует детали
интерфейса (клик-сценарии, состояния окон, колонки таблиц), а руководство по развёртыванию
описывает только сборку из Dockerfile и systemd. При этом workflow `release.yml` (ветка
`ci_cd`) уже публикует образ `kuzmichus/open-tutor-crm` с тегами `X.Y.Z` / `X.Y` / `latest`
/ `sha-<7 знаков>` (платформа — только `linux/amd64`, решение владельца). Версия проекта —
`0.1.0` (`pyproject.toml`). История версий существует только в GitHub Releases и теряется
для тех, кто смотрит репозиторий.

Ограничения, унаследованные от Dockerfile и схемы БД (учитываются в примере compose):

- миграции запускаются одноразовым контейнером **до** первого старта приложения
  (иначе таблицы создаст `init_db()` без записи в `alembic_version`, и последующий
  `alembic upgrade head` упадёт);
- база живёт на томе `/data` (`DATABASE_URL=sqlite:////data/tutor.db` вшит в образ);
- процесс не под root, живость проверяет встроенный healthcheck `/health`;
- планировщик cron-задач (`cron.py`) вне контейнера — compose не умеет расписания.

## Goals / Non-Goals

**Goals:**

- README, по которому новый пользователь доходит до работающего приложения за
  одну-две минуты: первый путь запуска — Docker Compose с готовым образом.
- Целевой объём README — ориентировочно 150–200 строк (сейчас ~630).
- CHANGELOG.md как единственный в репозитории список версий, ведётся с 0.1.0.

**Non-Goals:**

- Перенос удалённых фичевых текстов в `docs/` или wiki: их роль уже выполняют
  openspec-спецификации (`openspec/specs/<capability>/spec.md`).
- Отдельный файл `docker-compose.yaml` в корне репозитория — в README кладётся пример.
- Изменения в Dockerfile, workflow, коде и шаблонах.
- Русскоязычная/англоязычная версия README — язык остаётся русским.

## Decisions

**1. Компрессия, а не перенос.** Подробные разделы (брони, кабинеты, счёт, статистика,
финансы, часовой пояс) сжимаются в короткие абзацы/списки и удаляются, а не переезжают
в отдельные файлы. Альтернатива — разнести по `docs/*.md`: отвергнуто, потому что
детальные сценарии уже зафиксированы в openspec-спецификациях, а второй источник
истины о поведении — источник расхождений.

**2. Новый порядок разделов README** (структура вместо старой):

1. Заголовок + один абзац-питч + бейджи (License, Python, FastAPI, **Docker Hub**).
2. «Возможности» — список по разделам интерфейса, одна строка на фичу.
3. «Быстрый старт» — Docker Compose (новый основной путь).
4. «Запуск на своём сервере»: Docker (образ с Docker Hub, ручной `docker run` без
   compose, cron-контейнер) → сборка образа локально (кратко) → без Docker
   (uv + systemd, сжатый unit-файл и crontab).
5. «Конфигурация» — таблица: `DATABASE_URL`, `APP_NAME`, `MESSENGER_TLS_VERIFY`
   (есть в `app/config.py`, сейчас в таблице отсутствует), `MIGRATION_SOURCE_TZ`
   (только для `alembic upgrade`).
6. «Обновление» — git-путь и docker-путь, бэкап базы одной строкой.
7. «Дорожная карта» — актуализированная (см. решение 4).
8. «Разработка», «Участие в проекте», «Лицензия» — по 3–6 строк, ссылка на
   [AGENTS.md](AGENTS.md) и CHANGELOG.md сохраняется.

Альтернатива — оставить старый порядок и просто укоротить абзацы: отвергнуто,
потому что docker-путь сейчас спрятан в «Вариант B» после длинного systemd-раздела,
а для нового пользователя это должен быть первый вариант.

**3. Пример docker-compose.yaml** — два сервиса на готовом образе:

```yaml
services:
  migrate:                      # одноразовая миграция до старта приложения
    image: kuzmichus/open-tutor-crm:latest
    command: alembic upgrade head
    volumes: [open_tutor_data:/data]
    restart: "no"

  app:
    image: kuzmichus/open-tutor-crm:latest
    depends_on:
      migrate:
        condition: service_completed_successfully
    ports: ["8000:8000"]
    volumes: [open_tutor_data:/data]
    restart: unless-stopped

volumes:
  open_tutor_data:
```

- Тег по умолчанию `:latest` с соседней строкой-советом «для стабильности зафиксируйте
  версию (теги вида `0.1.0`)» — так пример не устаревает с каждым релизом.
- Поле верхнего уровня `version:` не пишется: в Compose v2 оно устарело.
- Рядом с примером — одна строка про cron: `docker compose run --rm app python cron.py`
  из crontab хоста (раз в минуту; compose расписаний не умеет).
- В docker-разделе явно указывается `linux/amd64` — честное предупреждение владельцам
  ARM-хостов (сейчас этого факта в README нет).

**4. Дорожная карта актуализируется по коду.** Секции «Кабинет ученика», «Кабинет
родителя», «Рассылки», «Задачи», «Уведомления и мессенджеры» реализованы (изменения
`student-cabinet-*`, `parent-cabinet`, `mailing`, `task-*` в архиве и в спеках) —
переносятся в выполненные; остаются напоминания/повторные приглашения и PostgreSQL-ветка
как задумано. Уточнение списка сверяется с `openspec/specs/`, а не по памяти.

**5. CHANGELOG.md — формат Keep a Changelog, по-русски.** Шапка с ссылками на формат
и SemVer; запись `[0.1.0] - 2026-10-31` (дата публикации первого образа; если к моменту
имплементации публикация ещё не случилась — дата ставится по факту релиза) с разделами
«Добавлено» (перечень возможностей первого релиза одной строкой на фичу) и «Известные
ограничения» (пометка «(Оплачено)» в списке уроков, `linux/amd64`). Правило ведения —
новая запись при каждом bump'е версии в `pyproject.toml` одновременно с релизом;
`[Unreleased]` держится сверху. Альтернатива — автогенерация из GitHub Releases:
отвергнуто, релизы сейчас содержат только строку про образ.

**6. Тесты не добавляются.** Изменение документационное: ни `tests/test_css_styles.py`,
ни бандл иконок README не проверяют. Единственная проверка после правки — прогон
`uv run pytest -n auto` (зелёный по определению) и перечитывание README глазами
(все команды примеров копируются из проверяемых мест: Dockerfile, `release.yml`,
`AGENTS.md`).

## Risks / Trade-offs

- [Удалённые подробности кому-то понадобятся] → Они остаются в истории git
  (`git show` по старому README) и в openspec-спецификациях; в proposal записано
  осознанное решение не переносить их в `docs/`.
- [README ссылается на образ, публикация которого зависит от несмерженной ветки
  `ci_cd` и секретов `DOCKERHUB_*`] → В README ничего менять не надо (ссылка
  правильная), но merge `ci_cd` и публикация `0.1.0` должны случиться до анонса
  нового README; в tasks.md это отдельная задача-напоминание вне кода.
- [Компактный README теряет «Как это работает» для новых контрибьюторов] →
  Раздел «Разработка» сохраняет ссылку на AGENTS.md (полные правила) и openspec;
  контрибьюторский путь не страдает.
- [Дата в `[0.1.0]` CHANGELOG может разойтись с фактическим релизом] → Дата ставится
  в момент имплементации по факту публикации образа; правка одной строки.
