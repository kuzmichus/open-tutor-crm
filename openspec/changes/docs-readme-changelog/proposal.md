# Proposal

## Why

README разросся до ~630 строк: подробные пошаговые сценарии отдельных фич (брони,
кабинеты, счёт, статистика, финансы) тонут рядом с тем, что ищет новый пользователь —
как поставить проект. Появились факты, которых в README нет вообще: готовый образ на
Docker Hub (`kuzmichus/open-tutor-crm`, публикация из workflow `release.yml` ветки
`ci_cd`) и `docker-compose.yaml` как самый короткий путь запуска. История версий не
фиксируется нигде — релиз отмечается только в GitHub Releases.

## What Changes

- **README.md — переработка, целиком, без переноса в другие файлы.**
  - Раздел «Возможности» сокращается из ~20 абзацев по фичам до компактного
    списка на несколько строк на фичу (одна строка — суть, детали живут в
    интерфейсе и в openspec-спецификациях).
  - Пошаговые разделы руководства (окна записи, кабинеты ученика и родителя,
    счёт ученика/группы, статистика, финансы, время и пояс) сжимаются в
    короткие абзацы/списки без потери фактов по развёртыванию.
  - Раздел Docker переписывается вокруг готового образа
    `kuzmichus/open-tutor-crm` (теги `X.Y.Z` / `X.Y` / `latest` / `sha-*`
    из `release.yml`) + добавляется пример `docker-compose.yaml`
    (миграция одноразовым сервисом → приложение; том `/data`; порт 8000).
  - Локальная сборка из Dockerfile остаётся как запасной вариант.
  - Дорожная карта приводится к фактическому состоянию (кабинеты ученика и
    родителя, рассылки, задачи и т.д. уже реализованы; остаются напоминания).
  - Добавляется бейдж Docker Hub и ссылка на CHANGELOG.md.
- **CHANGELOG.md — новый файл** в формате [Keep a Changelog](https://keepachangelog.com/ru/1.1.0/):
  стартовая запись `[0.1.0]` (версия из `pyproject.toml`, дата — дата публикации
  образа) с кратким перечнем возможностей первого релиза; правило ведения —
  новые записи вносятся при каждом релизе вместе с bump'ом версии.

Assumption: пример docker-compose кладётся в README (отдельный файл
`docker-compose.yaml` в корне не создаётся — запрос называл «пример файла»);
подробные фичевые тексты удаляются, а не переезжают в `docs/` — их роль
уже выполняют openspec-спецификации.

## Impact

- Файлы: `README.md` (переработка), `CHANGELOG.md` (новый).
- Код, шаблоны, миграции, тесты — не затрагиваются; существующие тесты
  (`tests/`) зелёные по определению, прогон всё равно выполняется на всякий случай.
- Связанное, но вне скоупа этого change'а: merge ветки `ci_cd` (workflows
  `ci.yml`/`release.yml` ещё не в `main`) и создание секретов `DOCKERHUB_*` —
  README будет ссылаться на образ, публикация которого выполняется этим workflow.
