# Design

## Context

См. `proposal.md` — Why. Состояние кода, формирующее подход:

- **Вкладка «Оплаты» уже решила задачу «панель внутри формы»**. Модалка группы — одна `<form>` на пять вкладок; панель оплат приходит отдельным GET-маршрутом `/tutor/groups/{id}/payments`, слот грузит её с `hx-trigger="load"` и `hx-swap="outerHTML"`, `hx-target="this"` обязателен, потому что `hx-target` наследуется от формы (иначе ответ панели заменил бы собой всю модалку). Вкладка «Занятия» повторяет этот паттерн один в один.
- **Модалка урока открывается в `#modal` из трёх мест** (страница уроков, календарь, список занятий группы). Первые два — обычный слой; из вкладки «Занятия» она должна открыться **поверх** модалки группы, как диалоги счёта поверх карточки ученика (design D10 `student-finance`): второй слой — отдельный контейнер `#modal-lesson` рядом с `#modal` и класс `.modal-root--stack` (z-index 60), уже существующий в дизайн-системе.
- **Форма урока жёстко таргетировалась на `#modal`** — `hx-target` у POST сохранения и у двух кнопок удаления. Во втором слое повторная отрисовка с ошибкой валидации ушла бы в `#modal` и вытеснила бы модалку группы.
- **htmx шлёт цель заголовком `HX-Target`** (id элемента-цели) с каждым запросом: и у GET из строки списка, и у POST формы, чей `hx-target` — контейнер второго слоя. Это позволяет серверу понять, в каком слое открыто окно, без дополнительных параметров в URL и скрытых полей.
- **У ДЗ связь с уроком 1:1** (`homework.lesson_id` UNIQUE) — индикатор «ДЗ: есть/нет» берётся одним `LEFT JOIN`, без N+1.
- **Границы «время урока»** (`format_time_span`) и подписи статусов уже живут в `lesson/services/presentation.py`; не хватает только даты «17.05.2027» и короткой подписи ДЗ.

## Goals / Non-Goals

**Goals:**

- Из карточки группы увидеть занятия группы: когда, в каком статусе, с домашкой или без.
- Открыть занятие на правку, не теряя несохранённые поля других вкладок модалки группы.
- Тот же паттерн «панель — не форма», что у вкладки «Оплаты»: модалка группы не меняется как форма.
- Изоляция по репетитору на новом маршруте: чужая группа — 404.

**Non-Goals:**

- Создание занятия из модалки группы (создание живёт на странице уроков и в календаре).
- Пагинация: у группы десятки занятий, список скроллится телом модалки.
- Посещаемость и детализация по участникам.

## Decisions

### D1. Панель — отдельный GET-маршрут `lesson`, а не данные внутри `manage_context`

`GET /tutor/groups/{id}/lessons` в модуле `lesson` (`views/group_lessons.py`), ответ — партиал `lesson/_group_panel.html` с корнем `#group-lessons-content`. Слот в `_manage.html` грузит его с `hx-trigger="load"` и `hx-swap="outerHTML"`; чипы статуса перезапрашивают тот же маршрут, таргет — корень партиала. Дополнительно слот слушает `lesson-saved from:body` (урок сохранили или удалили во втором слое) и `homework-saved from:body` (индикатор ДЗ устарел).

Почему так:

- тот же аргумент, что у панели оплат: модалка — форма, встроенные данные уходили бы в POST и пересчитывались при каждой отрисовке с ошибкой;
- маршрутов `/tutor/groups/{id}/<раздел>` уже два, паттерн закреплён; маршрут в пространстве `/tutor/groups`, но по домену это уроки: сервис `lesson.services.group_lessons`, владелец — ри-экспорт `get_owned_group` в `lesson/services/access.py` (правило AGENTS.md о ри-экспортах).

### D2. Второй слой модалок: контейнер `#modal-lesson` + цель из `HX-Target`

На странице групп рядом с `#modal` появляется `<div id="modal-lesson">` — контейнер второго слоя (по образцу `#modal-payment` на страницах учеников). Строка занятия шлёт `hx-get="/tutor/lessons/{id}/edit"` c `hx-target="#modal-lesson"`.

Чтобы форма урока жила в обоих слоях, `lesson_form_context` принимает `modal_target` (по умолчанию `#modal`) и шаблон использует его в трёх местах: POST сохранения и две кнопки удаления (урок и серия). Сервер определяет слой по заголовку `HX-Target` (`views/update.py::_modal_target`): `modal-lesson` → второй слой, иначе обычный. Заголовок приходит и на GET из строки, и на POST формы — отдельная механика для POST не нужна; без заголовка (не htmx) — обычный слой.

Почему не query-параметр `?stack=1`: его пришлось бы протаскивать и в POST (скрытое поле или в action), а заголовок htmx ставит сам и он всегда соответствует фактическому контейнеру окна.

Escape и клик по оверлею закрывают только верхнее окно (Alpine `x-show` своего корня) — поведение совпадает с диалогами счёта второго слоя.

### D3. Фильтр статуса: три чипа, нормализация на сервере

Значения `""` («Все», по умолчанию), `completed` («Проведённые»), `planned` («Запланированные») — закрытый список `FILTER_STATUSES` строится из `LESSON_STATUSES`. Неизвестное значение query схлопывается в «Все» (`normalize_status`, как `normalize_period` в списке уроков). Чипы переиспользуют `.period-chips` из дизайн-системы; активное состояние рисует сервер, перерисовывая партиал.

### D4. Выборка: один запрос, свежие сверху, ДЗ — тем же запросом

`SELECT lessons LEFT JOIN homework WHERE group_id = :group ORDER BY starts_at DESC, id` — порядок «новые сверху» (референс вкладки), при равном времени — стабильный по `id`. Изоляция не нужна отдельным условием: маршрут уже проверил владельца группы, дальше выбираются только уроки этой группы. `LEFT JOIN` корректен, потому что связь ДЗ с уроком 1:1 — строки не размножаются.

### D5. Индикатор ДЗ: «есть/нет», а не статус

Статусы ДЗ («Задано», «Сдано», «Проверено», «Не выполнено») в списке не показываются: строка и так насыщена (дата, статус урока, предмет), а педагогу на этом уровне важно одно — задано ли что-то. Записи нет или статус «Не задано» (запись создаётся лениво) — «ДЗ: нет»; всё остальное — «ДЗ: есть». Подпись — чистая функция `homework_short_label` в `lesson/services/presentation.py`, рядом с остальными подписями модуля.

### D6. Вторая строка карточки — описание группы

В референсе вторая строка показывает предмет («Английский язык»). Сущности предмета в проекте нет (спека: «формы без предмета»), ближайший носитель контекста — описание группы: на карточке группы и в референсе это одно и то же («Группа · Английский язык · участников: 2»). Если описания нет, строка показывает только индикатор ДЗ.

### D7. Подписи статуса — общие с уроками

Чипы строк используют существующие `LESSON_STATUS_LABELS` («Запланирован» / «Проведён») через `lesson_status_label`, а не форму «Запланировано» из референса: подпись статуса одна на проект, в списке уроков и календаре она уже masculinity-формы.

## Risks / Trade-offs

- **Модалка урока во втором слое не перепроверяет владельца слоя**: если окно открыто, а список под ним устарел (урок удалён в другом окне), POST вернёт 404 в контейнер второго слоя — пустой фрагмент. Сценарий редкий (один педагог), восстановление — закрытием окна.
- **Панель устаревает, пока модалка группы открыта**, для изменений, сделанных вне этой страницы (страница уроков, календарь). Осознанный компромисс, как у панели оплат; внутри страницы список обновляется событиями `lesson-saved`/`homework-saved`.
- **Заголовок `HX-Target` — контракт с htmx**: если контейнер переименуют, слой тихо откатится к `#modal`. Приемлемо: имя контейнера локально для страницы групп и покрыто тестом `test_groups_page_has_stacked_modal_container`.
