# Proposal

## Why

Ученик — центральная сущность CRM, но сейчас в проекте от него есть только заготовка: `Student` с `id INTEGER`, именем и глобально уникальным email, без связи с репетитором. Страница `/students` открыта без входа и отдаёт `select(Student)` — то есть список всех учеников всем подряд. Завести настоящего ученика нельзя: нет ни фамилии, ни телефона, ни класса, ни плательщика, ни напоминаний.

## What Changes

- **BREAKING**: таблица `students` перестраивается — `id` меняется с INTEGER PK на uuid4 (`String(36)`), добавляется обязательный `tutor_id` (владелец), появляются поля карточки: фамилия, телефон, email, признак ребёнок/взрослый, класс (1–11), школа, уровень, заметки, статус, часовой пояс и три флага напоминаний. `email` перестаёт быть обязательным и уникальным.
- Добавляются таблицы `contacts` (переиспользуемые взрослые контакты репетитора) и `student_contacts` (связь ученик ↔ контакт с ролью, признаком плательщика и тремя флагами напоминаний).
- **BREAKING**: включается проверка внешних ключей в SQLite (`PRAGMA foreign_keys=ON`). Сейчас объявленные FK не проверяются, поэтому удаление родителя оставляет сирот. Это затрагивает и существующие таблицы сессий и ключей восстановления.
- **BREAKING**: `GET /tutor/students` (прежде — публичный `GET /students`) перестаёт быть публичным: без действующей сессии — редирект на вход, данные фильтруются по `tutor_id` вошедшего репетитора.
- Появляется управление учениками: список карточками, карточка ученика, создание и редактирование в модальном окне, архивирование вместо удаления, поиск и фильтры, переключатель вид-сетка/список.
- Ленивый поиск контакта при вводе: если телефон или email уже есть в базе репетитора, предлагается существующий контакт, но дубликаты не запрещаются.
- Добавляется Alpine.js как локальный вендорный файл (`app/static/alpine.min.js`) для клиентского состояния модалки, табов и фильтров — по правилу AGENTS.md без CDN.
- Блоки «задолженность», «проведено уроков», «дата урока», «Уроки», «Отчёт» отрисовываются как явные заглушки: модулей уроков и финансов ещё нет, рабочих обработчиков у этих кнопок не будет.

## Capabilities

### New Capabilities

- `student-records`: карточка ученика — состав полей, принадлежность репетитору, правила подтипа ребёнок/взрослый, статусы и их обратимость, миграция существующей таблицы.
- `student-contacts`: переиспользуемые контакты взрослых — связь с учеником, роль, плательщик, часовой пояс и настройки напоминаний у получателя, ленивый поиск дубликатов.
- `student-management`: страницы управления учениками — список, карточка, форма создания и редактирования, архив, поиск и фильтры, доступ только владельцу.

### Modified Capabilities

Нет: существующие спецификации (`tutor-auth`, `tutor-password-reset`, `tutor-records`) не описывают учеников, поэтому их требования не меняются. Требование «`/tutor/students` доступен только владельцу» вводится как новое в `student-management`.

## Impact

- `app/student/models/` — `student.py` переписывается; добавляются `contact.py` и `student_contact.py` (по одному классу на файл); `app/models.py` пополняется импортами-регистраторами.
- `alembic/versions/` — новая миграция после `f7c3a1d92b6e`: пересборка `students` начисто (в базе 0 строк, переносить нечего), создание `contacts` и `student_contacts`.
- `app/database.py` — включение `PRAGMA foreign_keys=ON` на каждом соединении.
- `app/student/views/` — `index.py` (публичный `/students`) заменяется набором вьюх: список, партиал сетки, форма, создание, редактирование, архив; добавляется зависимость проверки сессии и скоупа по `tutor_id`.
- `app/student/templates/student/` — `index.html` переписывается; добавляются партиалы карточки, сетки и формы.
- `app/student/services/` — новый каталог: нормализация контактов и поиск дубликатов, правила подтипа, валидация.
- `app/static/` — добавляется `alpine.min.js`; `app/static/styles.css` пополняется компонентами (карточка ученика, сетка, модалка, фильтры, бейджи) и утилитами.
- `app/templates/base.html` — подключение Alpine.
- `tests/` — `test_models.py` и `test_pages.py` требуют переписывания (обязательный `tutor_id`, закрытый `/tutor/students`); добавляются тесты изоляции между репетиторами, контактов, плательщика и напоминаний.
