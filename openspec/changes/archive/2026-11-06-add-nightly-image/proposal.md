# Proposal

## Why

Образ обновляется только вручную (workflow Release с явной версией). Между
релизами ветка `main` уезжает вперёд, и «а собирается ли и запускается ли то,
что в main прямо сейчас» проверяется только локальной сборкой руками. Ежедневная
ночная сборка даёт постоянно свежий снапшот `main` под тегом `night`: по нему
можно проверять свежий код и развёртывать его до релиза, не трогая релизные теги.

## What Changes

- Новый workflow с триггером по расписанию (`schedule`/cron, раз в сутки):
  прогон проверок (переиспользуемый `ci.yml`) → сборка `linux/amd64` → push в
  Docker Hub с единственным тегом `night`.
- Ночной образ — НЕ релиз: он не создаёт git-тегов и GitHub-релизов, не двигает
  `latest` и не зависит от версии в `pyproject.toml`.
- Публикация выполняется только при зелёных проверках: красный `main` ночью
  образ не обновляет.
- Требование спецификации `ci-cd-pipeline` «публикация только вручную»
  уточняется: запрет на расписание касается канала релизов; ночной канал —
  отдельное поведение со своим тегом (change `add-ci-cd-pipeline` ещё в работе,
  правка вносится в его дельту напрямую — см. design.md).

## Capabilities

### New Capabilities

- `nightly-image`: ежедневная автоматическая сборка и публикация снапшот-образа
  ветки `main` в Docker Hub под тегом `night`; чем отличается от релизного
  канала, при каких условиях публикация выполняется и не выполняется.

### Modified Capabilities

(пусто — требований из `openspec/specs/` это change не меняет)

Примечание: правило «публикация образа MUST NOT запускаться по расписанию»
существует пока только в дельте работающего change `add-ci-cd-pipeline`
(в `openspec/specs/` спецификации `ci-cd-pipeline` ещё нет, поэтому оформить
изменение как MODIFIED-дельту этого change нельзя). Согласование формулировок
делается задачей этого change и описано в design.md.

## Impact

- `.github/workflows/` — новый файл `nightly.yml`; существующие `ci.yml` и
  `release.yml` не меняются (переиспользование через `workflow_call`).
- Реестр Docker Hub `kuzmichus/open-tutor-crm`: ежедневно перезаписывается тег
  `night`; релизные теги (`<version>`, `<minor>`, `latest`, `sha-*`) не
  затрагиваются.
- Секреты `DOCKERHUB_USERNAME`/`DOCKERHUB_TOKEN` уже настроены для release.yml —
  новых секретов не требуется.
- Спецификация `ci-cd-pipeline` в дельте change `add-ci-cd-pipeline`: уточнение
  одной формулировки (см. What Changes).
