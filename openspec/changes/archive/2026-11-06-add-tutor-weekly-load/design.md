# Design

## Context

Вкладка «Календарь» (`/tutor/profile?tab=calendar`) — одна форма на несколько
карточек: часовой пояс, учебный год, рабочее время и основные настройки. POST
`/tutor/profile/calendar` разбирается `parse_calendar_form`
(`app/tutor/services/calendar_form.py`) и сохраняется `save_settings`
(`app/tutor/services/settings.py`) в `tutor_settings`. Значения полей для GET и
ре-рендера собирает `_form_defaults` (`app/tutor/services/profile_page.py`).

Настройки хранятся лениво: строки в БД нет до первого сохранения —
`get_settings` отдаёт transient-объект с дефолтами из `DEFAULTS`. Колонки с
`nullable=False` обязаны иметь ORM-дефолт, иначе upsert упадёт на NOT NULL;
необязательные поля (`default_lesson_price`) объявлены `nullable=True`.

## Goals / Non-Goals

**Goals:**

- Параметр «Желаемая нагрузка в неделю» хранится в настройках репетитора.
- Поле на вкладке «Календарь» с понятной подписью и пояснением.
- Валидация: целое число часов 1..168, пусто = не задано (NULL).

**Non-Goals:**

- Использование значения в расчётах, сравнение с фактическими часами, отчёты.
- Дробные/получасовые значения: ориентир комфортной нагрузки не требует
  точности до минуты.
- Отдельный флаг «параметр включён»: отсутствие значения уже означает «не задано».

## Decisions

**D1. Новая колонка `tutor_settings.weekly_load_hours`, `Integer`, nullable.**
Параметр скалярный, как `workday_*` и `default_lesson_*`, поэтому живёт отдельной
колонкой, а не в KV-таблице `tutor_params` (там токены и внешние идентификаторы).
NULL = «не задано»: до первого сохранения ориентира нет, отдельный флаг
«включено» не нужен.

**D2. Единица — целые астрономические часы (60 минут), диапазон 1..168.**
168 — число часов в неделе: больше репетитор физически не проведёт. Дробные
значения не поддерживаются — параметр задаёт ориентир, а не расчёт; при
необходимости дробей это отдельная задача.

**D3. UI — отдельная карточка между «Рабочим временем» и «Основными
настройками».**
Параметр не относится ни к сетке календаря, ни к дефолтам урока, поэтому
отдельная карточка `input type=number` (`min=1`, `max=168`, `step=1`) с
пояснением про рабочие астрономические часы в неделю. Новых CSS-классов не
вводим — используются существующие `.card`, `.settings-card`, `.field`,
`.label`, `.input`, `.card__desc`.

**D4. Валидация в `parse_calendar_form` — единая точка формы вкладки.**
Пустая строка → `None` (очистка), иначе `int_or_none` и проверка
`1 <= value <= WEEKLY_LOAD_MAX_HOURS`. При ошибке `values is None`, сохранения
нет, на вкладке показывается сообщение «Желаемая нагрузка — целое число часов в
неделю от 1 до 168.».

## Risks / Trade-offs

- Колонка nullable — существующие строки получают NULL, `server_default` не
  нужен; `save_settings` перезаписывает только присланные поля, поэтому
  отсутствующий ключ не сбрасывает остальные настройки.
- Строгий диапазон 1..168 не поддержит дробные часы — допущение D2.
- Значение пока нигде не используется — это осознанно, см. Non-Goals.
- SQLite `ADD COLUMN` nullable не пересобирает таблицу, данные не теряются;
  `downgrade` удаляет введённые значения — откат только с бэкапом.
- Откат: revert коммитов плюс `alembic downgrade` до ревизии `7ce02b7b728c`.
