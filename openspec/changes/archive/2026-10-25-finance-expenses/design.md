# Design

## Context

Страница финансов (change finance-page) показывает поток денег учеников, но траты
репетитора не учитывает: кнопка «Расход» неактивна, «Чистая прибыль» равна чистому
доходу. Референс требует: диалог добавления расхода с категориями, арифметику
«получено − расходы = осталось репетитору», табы операций и карточку балансов
учеников рядом с табами.

## Goals / Non-Goals

- Goals: учёт трат репетитора; сводка с реальными расходами; список операций
  за период с фильтрами; балансы учеников на одной странице.
- Non-Goals: правка/удаление расходов, произвольные категории, «Квитанции»,
  содержание «Аналитики» и «Прогноза на месяц», пагинация ленты.

## Decisions

### D1. Расход — отдельная таблица, не вид операции счёта

`AccountOperation` ограничена тройкой платёж/возврат/списание (спека
student-finance): новый вид сломал бы формулу баланса, а у расхода нет ученика.
`expenses.tutor_id` — владелец напрямую, изоляция `get_owned_expense` одним
SELECT по `id + tutor_id`.

### D2. Категории — закрытый список в модели

Кортеж `EXPENSE_CATEGORIES` + словарь подписей (AGENTS.md, п. 10): один источник
для CHECK-констрейнта, селекта диалога и ленты. «Прочее» — умолчание формы.
Произвольные категории (кнопка «Добавить категорию» референса) — вне объёма.

### D3. `spent_at` строится как `occurred_at` платежа

Дата из формы + текущее время зоны педагога → UTC (design D15 finance-page).
Сводка и лента фильтруют траты тем же окном `[start, end)`, что и операции:
«Расходы» сводки совпадают с суммой строк вкладки «Расходы».

### D4. Лента — деньги репетитора

«Все операции» = платежи (все статусы, включая «Отменено» — как список платежей
карточки) + возвраты + расходы. Списания за уроки — внутренние движения баланса
ученика: остаются в истории карточки. Строки-представления собирает сервис
(`operations_feed`): классы бейджей статусов и сумм — закрытые списки, шаблон
не конструирует имена классов и не форматирует деньги.

### D5. Табы — ссылки, период сохраняется

`/tutor/finance?period=…&tab=…` (паттерн `/tutor/stats`): страница работает без
JS, состояние в адресе. Форма периода несёт скрытый `tab` — смена периода не
сбрасывает раздел. Заглушки табов рендерят «Раздел в разработке», данных не
запрашивают.

### D6. Обновление после сохранения — событиями

`expense-saved` добавлен к `payment-saved` в `hx-trigger` сводки; секция операций
(`#finance-operations`, партиал `/tutor/finance/operations`) перезапрашивает себя
по обоим событиям — числа всегда с сервера, в браузере нет денежной арифметики.

### D7. Балансы — одна формула

Карточка «Балансы учеников» использует `signed_amount` (как сводка и карточка
ученика): должники и переплата не могут разойтись с числами в других местах.
Сортировка по модулю баланса — от «самых заметных» сумм.

## Risks / Trade-offs

- Лента без пагинации (лимит 50): пагинации нет нигде на странице, лимит
  достаточно велик для месяца операций.
- Отрицательное «Осталось репетитору» (расходы > получено) показывается как есть
  с типографским минусом: прятать долг некорректно.
- Живой dev-сервер с `--reload` пересоздаёт таблицы через `create_all` до
  миграции (ловушка из памяти проекта): при пустой autogenerate-миграции дропнуть
  таблицу и сгенерировать заново.

## Migration Plan

Autogenerate-миграция `49508a25c7c2_add_expenses` (только новая таблица),
`uv run alembic upgrade head`. Тесты на in-memory базе через `create_all`
миграцию не требуют.

## Open Questions

- Правка и удаление расходов — когда появится реальная потребность.
- Наполнение «Аналитики» и «Прогноза на месяц» — отдельные change'ы.
