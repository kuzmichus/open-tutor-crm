# Design

## Context

Вкладка «Мои уроки» (`/student`) рендерится вьюхой `cabinet/views/index.py`:
`upcoming_lessons` (`cabinet/services/lessons.py`, `UPCOMING_LIMIT = 5`) отдаёт
только запланированные уроки с `starts_at >= utcnow()`, шаблон
`cabinet/lessons.html` показывает карточку «Ближайшее занятие» и таблицу
«дата — время — тип».

Календарь репетитора уже решает задачу «показать неделю» и разделён по слоям:

- `calendar/services/week.py` — окно недели `[пн, пн+7)` в зоне педагога
  (`local_week_bounds`) и выборка уроков репетитора;
- `calendar/services/schedule_event.py` / `schedule_day.py` — событие и день;
- `calendar/services/presentation.py` — `build_calendar_context`,
  `layout_events`, `build_event_view`, `build_grid_rows`: чистые функции,
  возвращающие готовые для шаблона словари;
- `calendar/templates/calendar/_area.html` — разметка `.cal-*`;
- `app/static/calendar.js` — вся интерактивность (hover четвертей, drag,
  модалки, копирование ссылки).

Кабинету ученика нужен только слой данных и разметки. Вторая копия сетки
означала бы два места правки вёрстки и два расхождения при следующем изменении
календаря.

## Goals / Non-Goals

**Goals:**

- `/student` показывает неделю ученика (пн–вс) — индивидуальные и групповые
  уроки, где он участник; чужие уроки не видны.
- Сетка — тот же визуальный компонент `.cal-*`, что у репетитора, но без
  интерактивности.
- Карточка: интервал времени, подпись занятия («Урок» / название группы),
  значок ДЗ со статусным цветом; прошедшие уроки серые.
- Листание недель и «Сегодня» работают и с JS (htmx-подмена области), и без
  него (обычные ссылки).

**Non-Goals:**

- Перенос, открытие и редактирование занятий из кабинета ученика.
- Показ цены урока, имени ученика и отметок недоступности репетитора.
- Вкладка «Мои уроки» ребёнка в кабинете родителя (остаётся таблицей).
- Легенда цветов ДЗ под календарём.
- Кнопка «Цвет» и режим раскраски «по статусу»: ученику не нужен контрол.

## Decisions

**D1. Данные — свой сервис, вид — общий `build_calendar_context`.**
`cabinet/services/calendar.py::student_calendar_context` собирает `ScheduleDay`
по семи датам и передаёт их в `build_calendar_context`. Раскладка пересечений,
шапка дня, часовые строки и подписи считаются общим кодом календаря: правка
вида недели доезжает до обоих кабинетов сразу.

**D2. Своя выборка, а не `week_lessons` репетитора.**
`week_lessons` берёт все уроки репетитора и резолвит цель через JOIN ученика и
группы. Ученику нужны только его уроки: два SELECT по `student_id`
(индивидуальные и через `GroupMember`) в окне `week_bounds(monday, tutor)`.
Фильтра по статусу нет — прошедшие уроки нужны, чтобы показать их серым.

**D3. Подпись цели считается на сервере, а не в шаблоне.**
`ScheduleEvent.from_lesson` получает `target_name`: «Урок» для индивидуального,
пробного и отработки, название группы — для группового. Слово «Урок» — часть
бизнес-подписи, поэтому живёт константой `LESSON_LABEL` в сервисе, а не
литералом в разметке.

**D4. Прошедшее — серый акцент и класс `cal-event--past`.**
Прошедшим считается урок со статусом `completed` или с `starts_at < now`
(«сейчас» — в зоне педагога). Цвет карточки заменяется на
`var(--muted-foreground)` — ссылку на токен темы, а не литерал (правило
«цвета только в `@layer tokens`»); дополнительно выставляется `is_past`, из
которого шаблон берёт существующий класс `cal-event--past`. У такого урока
снимается `is_overdue`: красная рамка «просрочен» адресована репетитору и в
кабинете ученика выглядела бы тревогой без повода.

**D5. Цена не показывается: `price=0` при сборке события.**
`build_event_view` склеивает подпись карточки из имени цели и цены, а
`format_price` на нуле возвращает пустую строку. Обнуление цены в сервисе
кабинета — самое узкое место: общий код календаря не получает флаг «скрыть
цену» и не усложняется.

**D6. Read-only обеспечивается отсутствием, а не запретом.**
В разметке нет `hx-get` на формы урока, нет `data-start-min`/`data-duration-min`
(их читает drag в `calendar.js`), четверти часа — пассивные `div.cal-slot` без
`@click`, `data-start` и `data-end`. `calendar.js` на страницу не подключается.
Класс `cal-event--readonly` снимает `cursor: grab` и hover-эффект: карточка не
обещает действие, которого нет. Проверяется тестом по тексту страницы —
отсутствие обработчиков надёжнее, чем их отключение на клиенте.

**D7. Значок ДЗ: карта статусов одним запросом.**
`homework_by_lesson(db, lesson_ids)` — один SELECT по `Homework.lesson_id IN (…)`
с фильтром `status != 'not_assigned'` (тот же `HIDDEN_STATUSES`, что у вкладки
«Домашние задания»). Статус и подпись кладутся в представление карточки
(`homework_status`, `homework_label`), класс значка считает
`homework_badge_class` (`cal-hw-badge--assigned|submitted|checked|not_done`,
fallback — `assigned`). Без N+1: число запросов не зависит от числа уроков.

**D8. Отметки недоступности репетитора не передаются.**
`ScheduleDay.unavailable` остаётся `None`: отпуск и выходные педагога —
внутренняя информация, требование о них в задаче не заявлено. Дни без
штриховки, шапка без плашки причины.

**D9. Листание — ссылки, а не кнопки с JS.**
Кнопки «‹», «›» и «Сегодня» — `<a href="/student?start=…">` с `hx-get` на ту же
область: без JS работает обычная навигация, с JS — подмена `#student-calendar`
без перезагрузки. Кривой `?start=` не ошибка, а текущая неделя (тот же приём,
что у календаря репетитора).

**D10. Переопределения CSS скоупятся под кабинет.**
Новые правила — `.cabinet-calendar*`, `.cal-event--readonly`, `.cal-hw-badge*`.
Общие `.cal-*` не меняются: иначе правка кабинета ученика поехала бы в
календаре репетитора. Высота сетки ограничена
`max-height: calc(100dvh - 14rem)`, чтобы `.cal-scroll` остался
скролл-контейнером, а панель и шапка дней закреплялись.

**D11. Карточка «Ближайшее занятие» остаётся.**
Замечание администратора к плану: карточка отвечает на вопрос «когда следующий
урок», календарь — «как выглядит неделя». Вьюха по-прежнему зовёт
`upcoming_lessons` для полной страницы (не для htmx-фрагмента — листание недель
её не перерисовывает).

## Risks / Trade-offs

- **Общие `.cal-*` могли поехать** → все новые правила скоупятся под
  `.cabinet-calendar` и `.cal-event--readonly`, календарь репетитора не
  затрагивается; регресс проверяется его тестами.
- **`upcoming_lessons` нужен кабинету родителя** (`parent_student_lessons.py`) →
  сервис не удаляется и не меняется, «Мои уроки» ребёнка остаются таблицей.
- **Тесты кабинета завязаны на старую разметку** → переписаны в этом же change:
  проверяют время урока, название группы, серый класс прошедшего и пустую неделю.
- **Высота сетки в `.main__container`** (padding, `max-width: 80rem`) может
  ломать `.cal-scroll` → лечится `max-height` у `.cabinet-calendar`; проверено
  на реальном рендере страницы.
- **Ученик видит историю своей недели** → это его собственные данные, объём
  ограничен одной неделей, а не всей историей.

## Migration Plan

Миграций БД и изменений моделей нет. Старые стили `.cabinet-nearest` и
`.cabinet-table` остаются: ими пользуется кабинет родителя. Откат — revert
шаблона `lessons.html`, вьюхи `index.py`, нового сервиса/шаблона/CSS-блока и
тестов.
