# Design

## Context

Вкладка «ДЗ» в форме урока — неактивная заглушка (спека `lesson-management`). Модалка урока сейчас — одна форма с одним `hx-post` (`lesson/_form.html`), разбираемая `parse_lesson_form` → `lesson_writer`. Массовое редактирование серии — whitelist `MASS_UPDATE_FIELDS`. Фоновых задач, файлового хранилища и кабинета ученика в проекте нет. Мотивация — в proposal.md.

## Goals / Non-Goals

**Goals:**

- ДЗ урока: задание, срок, флаг дедлайна, статус, ссылка на запись, заметка и комментарий педагога — сохраняются независимо от полей урока.
- Изменение не ломает существующее поведение модалки (урок, серия, удаление) и существующие тесты, кроме явных проверок заглушки в редактировании.

**Non-Goals:**

- Файлы-вложения (кнопка «Прикрепить файл» — визуальная заглушка), напоминания, автостатус по дедлайну, кабинет ученика — следующие итерации (см. proposal.md, вне scope).
- Показ ДЗ в списке уроков и в календаре: ДЗ видно только в модалке редактирования.

## Decisions

**D1. Отдельная таблица `homework` (1:1 с `lessons`), ленивое создание.**
Альтернатива — семь колонок на `lessons`: проще (одна форма), но «Сохранить ДЗ» молча сохранял бы и поля урока, а будущие напоминания/автостатус писали бы в таблицу уроков рядом со статусом урока `status` (planned/completed) — два разных «статусов» в одной таблице. `homework` наследует паттерн моделей проекта (один класс — один файл, CHECK-ограничения через кортежи + лейблы, как `LESSON_STATUSES`). `lesson_id` FK → `lessons.id` ON DELETE CASCADE: каскад чистит ДЗ при удалении урока/серии бесплатно (дисковых файлов нет — см. Non-Goals).

**D2. Две формы в модалке, футер — наружу обеих.**
Вложенные `<form>` в HTML запрещены, поэтому панели «Урок» и «ДЗ» — две независимые формы со своими `hx-post`; кнопки «Удалить», «Серию», «Закрыть» и заголовок выносятся в общий футер модалки (кнопки удаления — `type="button"` с `hx-post`, они уже так и работают). «Сохранить» остаётся submit-ом формы урока, «Сохранить ДЗ» — submit-ом формы ДЗ.

**D3. Панель ДЗ — переиспользуемый фрагмент `homework/_panel.html`.**
Форма ДЗ вставляется в модалку через include, а POST-обработчик возвращает **только фрагмент панели ДЗ**: при ошибке — со списком ошибок, при успехе — переотрендеренный с сохранёнными значениями (hx-target — сама форма ДЗ, `hx-swap="outerHTML"`). Это сохраняет несохранённые поля вкладки «Урок»: ответ ДЗ не должен выбрасывать введённую репетитором заметку урока. Пустое тело при успехе невозможно: `outerHTML` по самому себя удалил бы панель из DOM (вкладка «ДЗ» осталась бы пустой до переоткрытия модалки). Триггер `lesson-saved` ДЗ не шлёт (список уроков ДЗ не отображает), список не нужен.

**D4. Валидация ДЗ — отдельный сервис `app/homework/services/homework_form.py`** в стиле `lesson_form.py`: разбор формы → очищенные значения + ошибки, без FastAPI-зависимостей. Пустое/состоящее из пробелов «Задание» → ошибка; статус вне `HOMEWORK_STATUSES` → ошибка; `due_at` — `datetime-local`, кривая строка → ошибка. Сервис создания/обновления (`homework_writer.py`) при любой ошибке ничего не коммитит.

**D5. Статусы — закрытый список `HOMEWORK_STATUSES`** («Не задано» по умолчанию) с CHECK-ограничением и лейблами — паттерн `LESSON_STATUSES`. Свободный ручной выбор, без ограничений переходов. `deadline_enabled` — Boolean NOT NULL, default `true` (в макете чекбокс отмечен); поведения от флага пока нет.

**D6. Заметка и комментарий педагога — на английские имена `teacher_note` / `teacher_comment`**; ссылка на запись — `recording_url` (String(500), как `meeting_url`). Подписи в UI — из макета, без изменений.

**D7. В форме создания вкладка «ДЗ» остаётся заглушкой** (видна, `disabled`): панель и POST-эндпоинт ДЗ в разметку создания не попадают. Это сохраняет спеку «заглушка в создании» и не даёт создать ДЗ урока, которого ещё нет.

**D8. Успех показывает сама кнопка «Сохранить ДЗ».**
Панель при успехе переотрендерена сервером (D3), поэтому сервер же возвращает кнопку в состоянии успеха: `disabled`, зелёная заливка (`.btn--success`, токены `--success` в обеих темах), надпись «Успешно сохранено». Таймер отката — клиентский: делегирование `htmx:afterSwap` в `lessons.js` через `setTimeout` (~2 с) возвращает кнопке обычный вид и надпись «Сохранить ДЗ». Так не нужен ни JS-фреймворк во фрагменте, ни второй запрос; откат срабатывает и при повторных сохранениях (каждый своп ставит свой таймер, старый действует на уже удалённый из DOM узел и безвреден).

## Risks / Trade-offs

- [Разрез футера модалки ломает существующие тесты разметки (кнопки «Сохранить»/«Закрыть» в одной форме)] → прогон `tests/test_lesson_*.py`, точечная правка проверок разметки; поведение (POST-ы) не меняется.
- [Существующие тесты `test_lesson_create.py` / `test_lesson_update.py` проверяют заглушку «ДЗ» в редактировании] → обновить эти проверки: заглушка остаётся только для создания.
- [«Сохранить ДЗ» без триггера `lesson-saved` — репетитор может не заметить, что сохранилось] → кнопка внутри панели, успех закрывает панельные ошибки; при необходимости поведение уточнится отдельно, спеку это не меняет.
- [Ленивая запись `homework` — при сохранении вкладки создаётся строка даже при пустых полях] → принятие решения «пустое = ДЗ нет»; ошибка валидации по заданию не даёт создать бессмысленную запись без текста.

## Migration Plan

Одна миграция Alembic `add homework` (autogenerate): таблица `homework` + FK. Катим вниз — `alembic downgrade -1`, данные ДЗ теряются, остальное не затронуто. Новые зависимости не нужны.

## Open Questions

- Формат даты «Срока сдачи»: `datetime-local` как «Начало» урока (в макете показано «ДД.ММ.ГГГГ, --:--» с пикером) — принять как «Начало»; если позже понадобится только дата, это правка шаблона без смены спеки.
