# Design

## D1. Метрики списка одним набором запросов

`build_cards` дополняется агрегатами без N+1: балансы (GROUP BY по
`student_id, kind, status` + формула `signed_amount` в Python), число проведённых
уроков (два запроса: индивидуальные и через `group_members`), ближайший
запланированный урок (`MIN(starts_at)` при `status='planned'` и `starts_at >= now`),
первая оплата (`MIN(occurred_at)` оплаченного платежа), последняя цена
(`price IS NOT NULL`, свежая — по `starts_at DESC`). Итог: ~6 запросов на список
вместо запроса на карточку. Правила денег не дублируются: знак —
`balance.signed_amount`, формат — `money()` из `finance.presentation`.

«Осталось: N занятий» = `баланс // последняя цена`, только при `баланс > 0` и
определимой цене. Цена ученика как сущности в модели нет — берём цену последнего
индивидуального урока с ценой; нет цены — строка не показывается (честно, а не «0»).

## D2. Сводка долга живёт в партиале списка

Панель долга рендерится внутри `_list.html` (полн width над сеткой) и обновляется
тем же запросом, что и сетка: переключатель «Показать только их» — обычный
htmx-запрос с `hx-vals='{"debtors":"1"}'` + `hx-include` формы фильтров. Отдельный
эндпоинт и `HX-Trigger`-цепочки не нужны: один контейнер `#students-content` — один
запрос. Долг считается по текущему отфильтрованному списку — числа панели и карточек
всегда согласованы.

## D3. Доступ ученика: хранение и показ

Таблица `student_access`: `student_id` (UNIQUE, CASCADE), `login` (UNIQUE по всей
базе — будущий кабинет логинится глобально), `password_hash` (PBKDF2 через общий
`PasswordHasher`), `created_at/updated_at`. Пароль открытым текстом не хранится и
после сохранения не показывается: модалка успеха показывает логин и пароль один раз
из ответа POST (передача ученику), дальше — только смена пароля.

Валидация: логин `^[A-Za-z0-9_]{3,}$`, пароль ≥ 8 символов. Ошибки — списком строк,
как в `student_form`; повтор `login` — «Такой логин уже занят.» (IntegrityError
перехватывается сервисом по `SELECT`-проверке + уникальный индекс как страховка).
Смена пароля: при существующем входе поле пароля пустое = оставить старый.

## D4. Модалки «Уроки» и «Отчёт» по образцу вкладки «Занятия» группы

Маршруты — GET-фрагменты с изоляцией `get_owned_student` (чужой ученик — 404).
**Один маршрут — два шаблона**: без `HX-Target` вьюха отдаёт модалку целиком
(открытие по кнопке карточки), с `HX-Target: student-lessons-content` /
`report-content` — только содержимое без оболочки окна. Без этого перезапрос
чипами/стрелками вкладывал бы модалку саму в себя: второй оверлей затемнял фон,
крестик закрывал вложенный слой (тот же приём определения слоя, что в
`lesson/views/update.py::_modal_target`). Имя radio чипов — `status`: htmx шлёт
значение под именем поля, и вьюха читает тот же параметр (чужое имя молча
роняло фильтр — запрос уходил без `status`).

«Уроки»: чипы статуса (`""`/`completed`/`planned`, значения — статусы модели
Lesson), строки newest-first; клик по строке — `hx-get /tutor/lessons/{id}/edit`
в `#modal-lesson` (второй слой уже используется группой и payments). Уроки
ученика = индивидуальные (`lesson.student_id`) + групповые, где он участник
(`group_members`).

«Отчёт»: месяц из `?month=YYYY-MM` (мусор/пусто — текущий месяц педагога), границы
месяца — через `local_day_bounds` первого дня и первого дня следующего (зона
педагога, как `_month_window` дашборда). «Списано за месяц» — операции
`kind='lesson'` в окне; «Оплачено» — `kind='payment' AND status='paid'`;
«Заработок педагога» — те же списания, но только по индивидуальным урокам
(`lesson.type != 'group'`, JOIN по `lesson_id`). «Отменено» из референса не
переносится: статуса «отменён» в модели уроков нет, карточка с вечным нулём была бы
выдуманной метрикой.

## D5. Вид и фильтры

Переключатель сетка/список и хранение вида не меняются (CSS-класс на контейнере).
Новые контролы: сортировка (`sort=lastname|firstname`, по умолчанию фамилия —
`COALESCE(last_name, first_name)`) и кнопка «Удалённые» — Alpine переключает селект
статуса на `archived`/`""` и триггерит `change` формы: сервер остаётся единственным
источником фильтра, новых параметров нет. Кнопка «Импорт» — `disabled` с
`title`: маршрута нет, активная кнопка без обработчика была бы сломанной ссылкой.

## D6. Шаблоны и CSS

Новые блоки — плоские BEM-классы в секции страницы учеников (`students-debt`,
`student-stats`, `student-lessons`, `report-*`, `access-*`), цвета только токенами
(`--destructive`, `--success`, `--warning-*`). Иконки — `data-lucide`. Модалки —
`modal-root/modal-content` с локальным Alpine-состоянием `open` (закрытие по
оверлею/Esc), события — htmx. Окно «Уроки» — модификатор `modal-content--list`:
фиксированная высота (`min(30rem, 85dvh)`), чтобы смена чипа фильтра не «прыгала»
размером окна; короткий список оставляет пустое место внизу, длинный скроллится
в теле, `scrollbar-gutter: stable` не даёт скроллбару сдвигать контент.
