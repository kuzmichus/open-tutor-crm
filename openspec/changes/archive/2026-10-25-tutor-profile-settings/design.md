# Design

## Context

Профиль — карточка «только чтение» (change `tutor-dashboard`). Модель `Tutor` уже хранит `name`, `email`, `phone`, `about`, `hourly_rate`, `experience`, `timezone`; вход — email + пароль (`PasswordHasher`). Уведомлений в проекте нет вовсе: вкладка задаёт их настройки заранее, без каналов доставки.

## Goals / Non-Goals

- Goals: страница настроек с четырьмя вкладками по референсу; все формы работают без JS; изоляция по репетитору; дефолты настроек до первого сохранения.
- Non-Goals: каналы Telegram/Max и «Настройки учеников» (нет интеграции), подтверждение email, «Очистить кеш», поля «Предметы», школьные уведомления.

## Decisions

### D1. Вкладки — серверные, через `?tab=`
Вкладка — ссылка `?tab=security` и т.п.; сервер рендерит только активную вкладку. POST при ошибке ре-рендерит ту же вкладку с сообщениями, при успехе — 303 на `?tab=…&saved=1` с плашкой «Изменения сохранены». Alpine/htmx для страницы не нужны: состояние вкладки живёт в URL, формы работают без JS, а разбор ошибок не требует частичных ответов.

### D2. Настройки — отдельная таблица `tutor_settings`, строка на репетитора
PK = FK `tutor_id` (`ON DELETE CASCADE`). Полтора десятка булевых/числовых колонок не раздували бы `tutors`; отдельная таблица расширяется миграцией независимо. Строка создаётся лениво при первом сохранении; чтение без строки возвращает дефолты (все уведомления включены, напоминание за 1 час, сводка в 09:00, порог 0, длительность 60, четверти «10-25/12-25/03-20/05-25»).

### D3. Переключатели — серверный рендер чекбоксов, а не Alpine
`<input type="checkbox">` со стилизованным треком: состояние приходит на сервер формой, `checked` ставит Jinja. Клиентское состояние только визуальное и не нужно вовсе — страница без JS остаётся рабочей.

### D4. «Напоминать за» — JSON-список минут из закрытого набора
Чекбоксы 15 минут / 1 час / 24 часа — мультивыбор (`REMINDER_OFFSETS = (15, 60, 1440)` — источник истины и для формы, и для валидации). Хранение — JSON-колонка: фиксированных «слотов» три, а булевых колонок на каждый оффсет — три лишних; значение вне набора валидация формы отбрасывает.

### D5. Пароль меняется без ввода текущего — по референсу
Страница доступна только из-под сессии; референс не содержит поля «текущий пароль». Новый пароль задаётся парой «пароль + повтор»; пустая пара — пароль не трогается. Email валидируется как в регистрации (`is_valid_email`) и проверяется на уникальность; собственный текущий email конфликтом не считается.

### D6. Учебный год — четыре строки ММ-ДД
Кварталы — `String(5)` с regex-валидацией `^(0[1-9]|1[0-2])-(0[1-9]|[12]\d|3[01])$`: формат референса («10-25»), без года — пресеты серии уроков заполняются ближайшей датой в будущем (потребуется потребителю пресетов, вне этого change'а).

### D7. Длительность по умолчанию — из `LESSON_DURATIONS` без CHECK
Закрытый список длительностей живёт в `app/lesson/models/lesson.py` (один источник истины); сервис валидации импортирует его оттуда. CHECK-ограничение не ставится: оно потребовало бы междоменного импорта константы в модель tutor, а настройка заполняется только через форму.

### D8. Часовой пояс — переиспользование combobox
Поле — тот же селект с поиском, что у ученика (`timezone_options_json` + `combobox.js`): список зон единый, значение валидируется по `available_timezones`.

## Risks / Trade-offs

- Вкладки без JS — полная перезагрузка страницы при переключении: страница лёгкая, а URL-состояние и работа без JS перевешивают.
- Смена email без подтверждения письма: в системе нет почтового транспорта; ограничение уникальности защищает от коллизий входа.
- Дефолты «всё включено» включают ещё не реализованные каналы: настройкаahead-of-time — при появлении доставок переключатели уже будут значимы.
