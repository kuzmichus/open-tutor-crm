# Proposal

## Why

Статус ученика («новый» / «активный» / «архивный») живёт только в руках репетитора: при создании ученик получает «новый», и дальше его надо переводить в «активные» вручную. На практике про это забывают — в локальной базе из 15 учеников «активный» только один, хотя у троих уже есть проведённые занятия. Из-за этого счётчик «Активные ученики» на главной и фильтр списка показывают заниженную картину, а смысл статуса размывается.

При этом в системе уже есть точный сигнал «ученик реально занимается»: за проведённый урок с определимой ценой автоматически создаётся списание (`charges.sync_lesson_charge`). Бесплатный урок (цена не задана) списания не создаёт — сигнал «состоялся первый платный урок» невозможно перепутать с пробным занятием «на шару».

## What Changes

- **Первое списание за проведённый урок переводит «нового» ученика в «активные»** автоматически:
  - индивидуальный урок проведён с ценой → ученик становится «активным»;
  - групповой урок проведён → все его участники с определимой ценой становятся «активными»;
  - бесплатный урок (цена не задана) статуса не меняет;
  - «Пересчитать баланс» (backfill старых списаний) активирует так же, как обычный путь.
- **Правило перехода — только «новый» → «активный»**: архивного ученика автоматика не возвращает (разархивирование — осознанное решение человека), «активного» не трогает.
- Реализация — `app/student/services/activation.py` (правило жизненного цикла ученика), вызывается из двух путей создания списания (`charges.sync_lesson_charge`, `recalculate`) до коммита: урок, списание и статус сохраняются одной транзакцией.

Вне объёма: обратный переход «активный» → «новый» (бесполезен), деактивация при отсутствии уроков, уведомления, затрагивание статуса платежами и возвратами (платёж — деньги, а не признак занятий).

## Capabilities

### Modified Capabilities

- `student-management`: добавлено требование «Автоматический перевод в „активные“» — ученик со статусом «новый» становится «активным» при первом списании за проведённый урок; бесплатный урок и статус «архивный» автоматикой не затрагиваются.

## Impact

- **Новое**: `app/student/services/activation.py` (`activate_on_first_charge`).
- **Изменённое**: `app/finance/services/charges.py` (хук в `sync_lesson_charge` при создании списания), `app/finance/services/recalculate.py` (тот же хук при backfill-строке).
- **Миграций нет**: меняется только поведение записи, схема не трогается.
- **Тесты**: `tests/test_student_auto_activation.py` — индивидуальный и групповой урок, бесплатный урок, пересчёт баланса, архив и «активный» не меняются; через HTTP-маршруты, как у пользователя.
- **Спеки**: delta для `student-management`; README — пункт про автоперевод статуса.
