# Design

## Context

Что проверено на этой итерации (числа — с машины разработки, не оценки):

- Новый исходник задачи — `deepseek_svg_20261017_fdaaca.png`, ровно 200×200
  RGBA. Знак занимает квадрат 5.7…194.3 px с непрерывными углами, за его
  пределами прозрачность.
- Геометрия снята с растра по переходу «цвет знака / прозрачность» по 50 %
  альфы; для углов подобрана кубическая кривая с параметрами `radius`/`control`
  (ошибка аппроксимации < 0.3 px), для градиента — линейная регрессия по фону
  (остаток ≤ 2 из 255 на канал).
- `favicon.svg` растеризован в headless Chrome и сравнён с исходником
  попиксельно: из 33741 непрозрачных пикселей расхождение — 30 (0.09 %), все на
  крайних углах сквиркла с альфой 12–63 (субпиксельное сглаживание). Лишних
  пикселей нет.
- `ImageMagick` на этой машине теряет `linearGradient` при рендере SVG, поэтому
  для сравнения использован браузер (как и в `add-favicons`, D7).

## Goals / Non-Goals

**Goals:**

- Новый знак во всех форм-факторах набора из одного исходника, повторяемая
  сборка прежней командой.
- Векторные `favicon.svg` и `safari-pinned-tab.svg` соответствуют растру.
- `theme-color` и цвет `mask-icon` совпадают с верхом знака и друг с другом.

**Non-Goals:**

- Замена логотипа интерфейса и токенов `--brand`.
- OG-картинки, `browserconfig.xml`, исходник ≥512 px.
- Пересборка набора в CI: файлы коммитятся, Pillow не зависимость проекта.

## Decisions

**D1. Новый исходник заменяет `scripts/vendor/favicon-source.png`.**
Приём прежний: вендорный PNG — источник сборки, а не ассет для браузера.
Заменил файл — запустил `uv run --with pillow python scripts/build_favicons.py`,
код сборки размеров не меняется.

**D2. Геометрия знака — константы в системе координат 200×200.**
- Фон: `BACKGROUND = (5.7, 5.7, 188.6, 188.6)`, `radius = 46`,
  `control = 26.2` (у круга было бы `radius * 0.5523`; большее `control` —
  «мягче» угол, как у сквиркла).
- Облако: `BUBBLE = (43.1, 43.1, 112.9, 88.0)`, `radius = 25.25`,
  `control = 16.8`; хвостик вниз-влево — треугольник
  `(74.2,131.1) (93.4,131.1) (68,156)`.
- Солнце: центр `(99.5, 87)`, кольцо по средней линии `r = 18.7` толщиной
  `9.4` (внешний `23.4`, внутренний `14.0`), точка `r = 6.2`, восемь лучей —
  капсулы от `r = 28.5` до `r = 33.6` с полукруглыми концами `4.7`.

**D3. Цвета: градиент `#F97316 → #EC4899`, облако `#FEF8F6`, акцент `#EC4899`.**
Крайние точки градиента — углы знака `(5.7,5.7)` и `(194.3,194.3)`. Облако не
чисто белое: с растра снимается `(254, 248, 246)`. Солнце окрашено в цвет конца
градиента — так оно читается частью знака, а не отдельной заливкой.

**D4. `favicon.svg` — векторная реконструкция, а не трассировка.**
Три `path` (фон, облако+хвостик, солнце), всё на `fill` с
`fill-rule: nonzero`. Кольцо солнца — внешний и внутренний контур с разным
направлением обхода: при `nonzero` внутренний вырезает середину. Лучи —
капсулы (отрезок с полукруглыми концами). Трассировка дала бы десятки
килобайт узлов и «дрожащие» края на 16 px.

**D5. `safari-pinned-tab.svg` — только силуэт солнца, без облака и фона.**
Safari берёт форму и красит её в `color`. Фон-сквиркл дал бы сплошную заливку, а
облако на 16 px не читается. Остаётся солнце — тот же `path`, что в `favicon.svg`.

**D6. `apple-touch-icon` сводится на продолжение градиента, а не на белый.**
iOS не поддерживает прозрачность и заливает её чёрным; белый фон тоже плох:
сквиркл скруглён, и в углах остались бы белые клинья. Поэтому прозрачное
заменяется тем же диагональным градиентом — иконка «в обрез», а скругление iOS
рисует сам (`_on_gradient`).

**D7. maskable — знак в safe zone 80% на градиенте без альфы.**
Android обрезает maskable по своей форме. Облако с хвостиком вырезается
геометрической маской `_mark_mask` (тот же контур, что в SVG; `ImageDraw` в
4× и `LANCZOS` — у него нет сглаживания) и кладётся на градиент до краёв: при
обрезке по любому контуру нет прозрачных углов.

**D8. `theme-color` и `mask-icon color` — `#F66838`.**
Это образец верхнего края знака: адресная строка мобильного браузера выглядит
продолжением иконки. Одно значение на светлую и тёмную тему — как раньше.

**D9. Тест сверяет `theme-color` в `<head>` с `theme_color` из манифеста.**
Раньше в тесте было захардкожено `#3290ED`; при смене знака это значение
разъехалось бы с манифестом. Теперь источник истины — манифест: браузер берёт
мету для темы вкладки, а установленный PWA — манифест, и рассогласование даёт
«мигание» цвета.

## Risks / Trade-offs

- **512 px — апскейл из 200.** На вкладке не видно, у PWA-иконки края мягче.
  Лечится заменой исходника без правки кода.
- **Вектор может отличаться от растра.** Проверка — сравнение в браузере
  (D4, Context): расхождение 0.09 % на углах. При заметном расхождении запасной
  вариант — SVG со встроенным `data:image/png;base64` (имя и подключение те же).
- **maskable рисуется маской, а не из SVG.** Край облака на 512 px сглажен
  суперсэмплингом 4×; при увеличении исходника код не меняется.
- **`no-cache` у иконок.** Лишний 304 на страницу — дёшево; иначе обновление
  знака не подхватится без сброса кэша браузера.
- **Иконка не совпадает с логотипом интерфейса.** Осознанно: знак из задачи —
  айдентика сайта; логотип и токены `--brand` вне объёма.
