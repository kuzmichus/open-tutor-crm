# Proposal

## Why

Календарь `/tutor/calendar` до сих пор живёт на демо-данных (`demo_schedule`), тогда как модель уроков уже существует и полностью работает на странице Уроков: расписание репетитора отображается выдуманным, реальные уроки в календаре не видны, а диалоги создания и редактирования урока на календаре — самописная демо-модалка, не имеющая отношения к настоящей форме урока.

## What Changes

- **Уроки недели календаря — из БД**: `GET /tutor/calendar` строит сетку из уроков вошедшего репетитора за запрошенную неделю (джойн цели, изоляция по репетитору), демо-генератор уроков перестаёт участвовать в рендере. Демо-события отпусков и демо-слоты остаются как есть (их перевод на БД — отдельные change'ы).
- **Клик по карточке урока открывает диалог редактирования** — тот же `lesson/_form.html`, что на странице Уроков (`GET /tutor/lessons/{id}/edit` в контейнер `#modal`).
- **Кнопка «Добавить» и клик по пустой четверти открывают форму создания урока** — `GET /tutor/lessons/new?starts_at=...` с предзаполненным «Началом»; демо-модалка «Новый урок» удаляется с календаря.
- **Сохранение урока обновляет неделю календаря**: событие `lesson-saved` перерисовывает `#calendar-swap` с сервера.
- **Два режима раскраски карточек**: «по цели» (ученик и группа — единый тип цели, цвет закреплён за объектом) и «по статусу» урока (запланирован / просрочен / проведён — просроченный вычисляется: время прошло, статус всё ещё «Запланирован»). Выбор режима — параметр `?color=`, запоминается в `localStorage`.
- **Цвет цели хранится в БД** (**BREAKING**: миграция `students.color`, `groups.color`): назначается случайно из расширенной палитры (~16 разнесённых цветов) при создании ученика/группы, избегая цветов, уже занятых объектами этого репетитора, и далее не меняется. Существующие ученики и группы получают цвета при миграции.
- **Перетаскивание урока сохраняет новое время на сервер** — вместо «только DOM»: при отпускании карточки отправляется запрос на изменение начала урока, неделя перерисовывается с сервера. Перетаскивать можно только непроведённые уроки.
- **Диалог создания урока принимает префилл начала** — `GET /tutor/lessons/new?starts_at=YYYY-MM-DDTHH:MM` предзаполняет поле «Начало».

Не входит в change (отложено отдельными change'ами): перевод слотов и отпуска на БД, конвертация времени в часовую пояс репетитора (сейчас время показывается наивно и в списке, и в календаре — расхождения между ними не появляется).

### Modified Capabilities

- `calendar`: демо-занятия уроков заменяются на уроки недели из БД; новый режим «клик по карточке → редактирование»; форма создания урока с префиллом четверти вместо демо-модалки; раскраска по цели/статусу; перетаскивание с серверным сохранением; отпуск и слоты остаются демо и не меняются.
- `lesson-management`: форма создания принимает префилл начала; новый способ открытия формы — с календаря.
- `student-management`: новый ученик получает цвет из палитры при создании (назначение и хранение).
- `group-management`: новая группа получает цвет из палитры при создании (назначение и хранение).

## Impact

- `app/calendar/views/index.py`, `app/calendar/services/*` — выборка недели из БД вместо `demo_schedule.build_week` для уроков; контекст карточки получает `lesson_id`, цель, статус.
- `app/calendar/templates/calendar/index.html`, `_area.html` — контейнер `#modal`, подписка `#calendar-swap` на `lesson-saved`, клик по карточке, меню раскраски, уход demo-модалки урока.
- `app/static/calendar.js` — открытие диалогов через HTMX, drag → серверный запрос, режим раскраски.
- `app/lesson/views/create.py` — параметр `starts_at` префилла; новый view переноса урока (PATCH-семантика) + `app/lesson/views/__init__.py`.
- `app/lesson/services/lesson_form.py` — префилл значения «Начало».
- `app/student/*`, `app/group/*` — назначение цвета при создании; миграция `students.color`, `groups.color` (autogenerate) с массовым заполнением существующих строк.
- `tests/test_calendar.py` — значительная переработка (демо-тесты уроков уступают тестам реальных данных); новые/правки тестов lesson, student, group.
