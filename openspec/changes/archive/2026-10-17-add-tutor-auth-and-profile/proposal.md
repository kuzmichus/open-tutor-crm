# Proposal

## Why

Сейчас у репетитора есть только минимальная запись (id, имя, email) и общедоступная страница-список `/tutors` — нет способа создать аккаунт, войти в систему и видеть свою карточку. CRM не может работать «под репетитором», пока нет ни учётных данных, ни личного кабинета.

## What Changes

- **BREAKING**: таблица `tutors` перестраивается — `id` меняется с INTEGER PK на uuid4 (строка), добавляются поля: захешированный пароль, телефон, «о себе», предмет, опыт, стоимость в час, часовой пояс. Существующие записи переносятся в новые типы/колонки миграцией.
- **BREAKING**: страница-список `/tutors` и её ручка удаляются полностью; репетиторов видит только сам владелец в `/tutor/`.
- Регистрация: форма запрашивает **только имя, email, пароль и подтверждение пароля**; `POST /tutor/register` принимает **только эти четыре поля** — лишние игнорируются, необязательные поля карточки при регистрации не заполняются. Пароль сохраняется в захешированном виде.
- Работающий вход: `POST /tutor/login` проверяет пароль и открывает сессию (cookie); `GET /tutor/` показывает карточку вошедшего репетитора, без сессии — редирект на `/tutor/login`. Добавляется выход из сессии (logout) — предположение: раз вход рабочий, завершение сессии должно быть доступно.
- Страница `/tutor/remember-password`: ввод email → на странице отображается ссылка с уникальным ключом; по переходу по ссылке открывается страница установки нового пароля. Старый пароль не раскрывается.
- Страница `/tutor/reset-password` (по уникальному ключу): установка нового пароля, ключ одноразовый и ограничен по времени.
- Страница `/tutors` (список) удаляется (см. **BREAKING** выше); карточку видно в `/tutor/`.
- Формы: `GET /tutor/login`, `GET /tutor/register`, `GET /tutor/remember-password`.

## Capabilities

### New Capabilities

- `tutor-records`: учётная карточка репетитора — состав полей (uuid4 id, имя, email, захешированный пароль, телефон, о себе, предмет, опыт, стоимость в час, часовой пояс) и правила их хранения.
- `tutor-auth`: регистрация, вход с проверкой пароля, серверная сессия (cookie), доступ к личному кабинету `/tutor/`, выход.
- `tutor-password-reset`: восстановление доступа — по email выдаётся одноразовая ссылка с уникальным ключом, по ней устанавливается новый пароль.

### Modified Capabilities

(нет — в проекте ещё нет спецификаций)

## Impact

- `app/tutor/models/tutor.py` — новая схема модели; новые модели `TutorSession`, `PasswordResetToken` (по одному классу на файл); `app/models.py` пополняется импортами-регистраторами новых моделей.
- `alembic/versions/` — новая миграция: пересоздание таблицы `tutors` (id → uuid4 + новые колонки), перенос существующих данных; SQLite не позволяет менять PK через обычный ALTER.
- `app/tutor/views/` — новые view-файлы: кабинет `/tutor/`, login, register, remember-password, reset-password, logout; удаляется `index.py` (`GET /tutors`).
- `app/tutor/templates/tutor/` — новые шаблоны страниц (наследуют `base.html`); удаляется `index.html`.
- Сессии и хеширование — только стандартная библиотека (`hashlib.pbkdf2_hmac`, `secrets`, `hmac`); добавляется только `python-multipart` (обязателен для `Form()` в FastAPI, подтверждено пользователем).
- `tests/` — существующие тесты `Tutor(name=..., email=...)` требуют обновления (пароль обязателен, id теперь uuid4); добавляются тесты регистрации, входа, кабинета, сброса пароля.
