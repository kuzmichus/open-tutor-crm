# Design

## Context

Календарь (`/tutor/calendar`) — SSR + Alpine, демо-режим без БД и серверных запросов (см. proposal.md — Why; требования — в `specs/vacation-creation/spec.md`). В панели уже живут: «Добавить»/FAB (диалог урока), прямая кнопка «Добавить слот» (change `add-slot-booking`), выпадающий список «Цвет: ученик» (`.cal-color`) и тост. Отпуск сейчас существует только как серверная демо-заглушка `.cal-vacation` (недели августа); её требование «клик не открывает форму урока» в спеке `calendar` фактически не выполняется — блок имеет `pointer-events: none`, и клик утекает в четверть часа под ним. Change чинит это и добавляет клиентское создание отпуска.

## Goals / Non-Goals

**Goals:**
- Меню ⋮ в панели (паттерн «Цвет: ученик») с пунктами «Добавить слот» и «Добавить отпуск»; прямая кнопка слота убирается.
- Диалог «Новый отпуск»: две даты, нативная валидация, ноль сетевых запросов.
- Блоки «Отпуск» на дни диапазона в видимой неделе: под карточками занятий, клик по ним не открывает форму урока (включая существующую демо-заглушку).
- SSR-разметка всех элементов и покрытие тестами `tests/test_calendar.py`, старые тесты зелёные.

**Non-Goals:**
- Модель отпуска в БД, серверные маршруты, персистентность между листаниями.
- Редактирование, перенос, удаление и изменение цвета отпуска; отпуск в мобильной FAB.
- Отпуск, переживающий листание недели, и отрисовка выходящих за неделю дней.

## Decisions

**D1. Меню ⋮ — статическая разметка и состояние `moreOpen` (паттерн `.cal-color`).**
Кнопка `#cal-more` и `<ul>` с двумя пунктами присутствуют в SSR (`x-show` + `x-cloak`), закрытие — `@click.outside`, повторный клик и `@keydown.escape.window`. Пункт «Добавить слот» сохраняет `id="cal-add-slot"` и `@click="openSlotDialog()"` — существующий SSR-тест change `add-slot-booking` (кнопка есть в разметке, открывает диалог) продолжает проходить без правок. Прямая кнопка `#cal-add-slot` из тулбара удаляется.
*Альтернативы:* нативный Popover API — непоследователен с существующим `.cal-color` и требует отдельных стилей; оставить прямую кнопку и добавить меню рядом — дублирование точек входа, отвергнуто пользователем (кнопка переезжает в меню).

**D2. Диалог «Новый отпуск» — отдельный блок разметки, состояние `vacationForm: { open, start, end }`.**
Уже три режима у модалки урока/слота; отпуск семантически иной (диапазон дат, нет времени и ученика) и, как диалог записи в прошлом change, не должен конкурировать с формой создания (там — решение D1). Открытие: `openVacationDialog()` переиспользует общий префилл `prefillMoment()` (сегодня/первая видимая дата недели), `end = start` — однодневный отпуск по умолчанию. Закрытие: «Отмена», Escape, backdrop. Отправка формы — `@submit="createVacation($event)"` с `preventDefault()`.
*Альтернатива:* четвёртый режим `mode: "vacation"` в общей модалке — ещё одна ветка в разметке и состояниях без выигрыша.

**D3. Нативная валидация диапазона: `:min` у поля конца.**
`<input type="date" id="vac-end" :min="vacationForm.start" required>` — браузер сам блокирует отправку при `end < start` (спека: «конец раньше начала → форма не отправляется»), без своего UI ошибок. Дополнительно `createVacation()` defensively не создаёт блоки при `end < start` (защита от ручного ввода/старых браузерей), не меняя наблюдаемого поведения.
*Альтернатива:* собственная проверка с тостом — дублирует нативную валидацию и добавляет код без требования спеки.

**D4. Создание: пересечение диапазона с `data-date` колонок, блок вставляется первым ребёнком дня.**
`createVacation()` перебирает `.cal-day[data-date]`, вставляет `<div class="cal-vacation">Отпуск</div>` в каждый день `start ≤ date ≤ end` (сравнение ISO-строк). Вставка **первым** ребёнком `.cal-day` критична: клиентский блок рисуется раньше (ниже) карточек `.cal-event`, поэтому «отпуск не скрывает занятия» выполняется структурно — карточки видны и кликабельны поверх блока. Блок создаётся без аллокации состояния в Alpine и исчезает вместе с подменой `#calendar-swap` при листании — та же модель DOM-only, что у слотов (решение D6 change `add-slot-booking`). Существующий `.cal-vacation` переиспользуется полностью — визуал и подпись «Отпуск» бесплатны из спеки `calendar`.
*Альтернативы:* отдельный класс `.cal-vacation--client` — дублирование стилей без выигрыша; массив отпусков в состоянии Alpine — усложнение и расхождение с «DOM-only жизненным циклом» (слоты специально не заводят массив).

**D5. Клик по отпуску: guard в `openSlot()` по наличию `.cal-vacation` в дне.**
Обработчик четвери проверяет: если в колонке дня есть блок «Отпуск», форма урока не открывается. Это чинит существующее требование спеки `calendar` для демо-заглушки (клик утекал в слот под `pointer-events: none`) и покрывает клиентские блоки одним механизмом; сложность слоёв (что именно перехватило клик) поведение не зависит. Клики по карточкам занятий в отпуск-дне не затрагиваются: карточки выше блока в стеке и обрабатываются как обычно.
*Альтернатива:* снять `pointer-events: none` у `.cal-vacation`, чтобы блок сам перехватывал клик — хрупко (поведение зависит от порядка/перекрытия слоёв) и не покрывает случай, когда клик пришёлся на неперекрытую четверть.

**D6. Тесты — SSR и статические, без запуска JS.**
SSR: кнопка `#cal-more`, пункты (`#cal-add-slot` в меню, `#cal-add-vacation`), диалог «Новый отпуск» (`type="date"`, `required`, `min`, кнопки, форма `createVacation`). Статические: `openVacationDialog`/`createVacation`/`prefillMoment` в `calendar.js`, отсутствие `fetch(` и `XMLHttpRequest`, guard `.cal-vacation` в `openSlot`. Ручной браузерный сценарий фиксируется комментарием в задаче 4.x — как в прошлом change.

## Risks / Trade-offs

- [Старый тест change `add-slot-booking` ищет `#cal-add-slot` на странице] → пункт меню сохраняет id и обработчик, тест проходит без правок; задачи нового change это фиксируют.
- [Диапазон шире одной недели] → блоки рисуются только на видимую неделю и исчезают при листании — это требование спеки, а не дефект; тест явно это проверяет.
- [Отпуск создаётся поверх дня с занятиями] → вставка первым ребёнком: карточки выше блока (D4); клик по карточке работает, клик по территории блока — нет (D5).
- [Меню и диалог одновременно] → не бывает: выбор пункта закрывает меню до открытия диалога, а при открытом диалоге панель перекрыта backdrop.
- [Пользователь ожидает persistence отпуска] → вне объёма (proposal), поведение совпадает со слотами и демо-уроками.

## Migration Plan

Не требуется: клиентский демо-режим, миграций и конфигурации нет, откат — revert коммитов.

## Open Questions

Нет: состав пунктов меню, поля диалога (два обязательных датовых поля), DOM-only жизненный цикл и правило клика по отпуску подтверждены пользователем и спекой.
