# Design

## Context

Черновик лендинга — полноценный HTML-документ на диске (`draft.html`):
фиксированная шапка, `<style>` с оформлением, тело и тег
`/static/landing-auth.js`. GrapesJS работает с фрагментом тела и CSS
отдельно, поэтому между ними нужен слой разбора и сборки. Фича доступна
только в сингл-режиме, статика — локальная, CDN запрещены.

## Goals / Non-Goals

**Goals:**

- Открыть текущий черновик в полноэкранном редакторе с русским UI.
- Сохранить правки в `draft.html`, не теряя `<title>` и тег
  `landing-auth.js`.
- Круглый трип «открыл → ничего не менял → сохранил» без потери вида.
- 404 в мульти-режиме на обоих роутах.

**Non-Goals:**

- Загрузка картинок из интерфейса и настройка asset manager upload.
- Хранение черновика в БД или `FILES_*`.
- Сохранение пользовательских `<script>` из тела.

## Decisions

### D1. Вендоринг, а не CDN

GrapesJS 0.23.9 скопирован из npm-пакета (`dist/grapes.min.js`,
`dist/css/grapes.min.css`, `LICENSE`) без пересборки. Файлы отдаются
существующим `RevalidatingStaticFiles` с `/static/dist/grapesjs/...`.
Глобальный `.gitignore` содержит шаблон `dist/`, поэтому добавлены
исключения `!app/static/dist/` и `!app/static/dist/**` — иначе вендорные
файлы молча не попали бы в коммит.

Фактическая лицензия пакета — BSD-3-Clause, а в постановке указана MIT.
Сохранён исходный файл лицензии без подмены текста; расхождение отмечено в
`README.md` рядом с файлами и в резюме задачи.

### D2. Русская локаль — собственный браузерный скрипт

`i18n-ru.js` определяет `window.grapesjsI18nRu` и повторяет структуру
`locale/en.js` дистрибутива. Официальный `locale/ru.js` — CommonJS-модуль
(`exports.default`), не подключаемый тегом `<script>`, поэтому он взят как
справочник перевода, а не подключён напрямую. В init передаются
`locale: 'ru'`, `localeFallback: 'en'` и `detectLocale: false`: без
последнего GrapesJS подменяет локаль языком браузера.

### D3. Разбор и сборка документа регулярками

Формат черновика контролирует только наш код (шаблон и редактор), поэтому
`draft_render.py` обходится без HTML-парсера: извлекает первое тело, первый
`<style>` и `<title>`, вырезает `<script>` из тела. Сборка — фиксированная
шапка (`charset`, `viewport`, `<title>`, `<style>`) и тело. `<title>`
берётся из текущего черновика; нет черновика или заголовка — «{имя} —
репетитор» с HTML-экранированием имени.

### D4. Тег `landing-auth.js` гарантируется идемпотентно

Скрипт не попадает в редактируемое тело (GrapesJS его вырезал бы), поэтому
при сохранении проверяется маркер `landing-auth.js`: есть — документ не
меняется, нет — тег вставляется перед последним `</body>`, а без него
дописывается в конец. Два сохранения подряд и HTML с уже вставленным тегом
оставляют ровно один тег.

### D5. Обёртка `<body>` от GrapesJS снимается

`editor.getHtml()` возвращает `<body>…</body>` (GrapesJS оборачивает
компоненты в body). Сервер снимает внешнюю обёртку перед сборкой документа,
иначе при повторном открытии получилось бы `<body>` внутри `<body>`.
Проверено на GrapesJS 0.23.9: без нормализации обёртка накапливается.

### D6. CSS без служебного слоя GrapesJS

`editor.getCss({ avoidProtected: true })` не включает служебный
`* { box-sizing: border-box; }` канваса. Без этой опции служебные и
сгенерированные правила накапливались при каждом сохранении; с ней вывод
стабилен после первого круга. Селектор `#wrapper` заменяется на `body` —
GrapesJS оборачивает тело в компонент с этим id.

### D6a. Сокращения с `var()` разворачиваются до загрузки в GrapesJS

GrapesJS разбирает CSS браузерным CSSOM, а CSSOM выбрасывает сокращённое
свойство, если хотя бы одна его часть задана через `var()`:
`background: var(--accent)`, `border: 1px solid var(--border)`,
`border-radius: var(--radius)`. При первом сохранении такие объявления
исчезали бы — страница теряла цвет CTA и рамки. Поэтому `css_for_editor()`
в `draft_render.py` заранее разворачивает сокращения с `var()` в
эквивалентные длинные свойства (`background-color`, `border-*-width/style/color`,
четыре угла `border-*-radius`, стороны `margin`/`padding`, `row-gap`/`column-gap`),
которые CSSOM сохраняет. Остальные сокращения не трогаются: GrapesJS
раскрывает их сам без потери значений. Проверено в Chromium: computed-стили
всех элементов до и после круга «открыл → сохранил» совпадают, повторные
сохранения байт-в-байт стабильны.

### D7. Автосоздание черновика в GET

Если `draft.html` нет, `GET /tutor/landing/editor` вызывает
`save_default_draft(tutor)` и открывает созданный шаблон. Это то же
действие, что кнопка «Создать черновик», но без лишнего клика: страница
управления может вести в редактор и в пустом состоянии. Ответ отдаётся с
`Cache-Control: no-store`, чтобы после сохранения не открывалась старая
версия.

### D8. Автономная страница вместо `base.html`

Редактору нужен весь вьюпорт без сайдбара и мобильной шапки, поэтому
шаблон `landing/editor.html` — самостоятельный документ, как публичные
страницы бронирования. Общий `app.css` не подключается: конфликт с
оформлением GrapesJS исключён. Данные черновика передаются JSON-ом через
`tojson` (экранирует `</script>`), а не вставкой HTML в JS-строку.

## Risks / Trade-offs

- **Версия GrapesJS.** 0.23.9 зафиксирована; обновление требует сверки
  en-набора, правки `i18n-ru.js` и ручной проверки редактора.
- **Лицензия.** BSD-3-Clause вместо MIT из постановки; текст лицензии не
  подменяется, расхождение задокументировано.
- **Скрипты в теле.** Пользовательские `<script>` не переживут сохранение —
  это осознанное ограничение задачи; сохраняется только
  `landing-auth.js`.
- **Загрузка картинок.** Менеджер ассетов переведён, но endpoint загрузки в
  эту задачу не входит; настраивать недокументированный upload URL нельзя.
- **Экспорт CSS.** GrapesJS переупорядочивает и раскрывает shorthand-свойства
  (например, `padding: 64px 0` → четыре свойства). Вид страницы сохраняется,
  но CSS после первого сохранения выглядит иначе; это поведение
  библиотеки, а не ошибка сборки. Сокращения с `var()` перед загрузкой в
  редактор разворачиваются вручную (D6a), иначе CSSOM терял бы их целиком.
