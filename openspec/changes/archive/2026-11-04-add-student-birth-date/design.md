# Design

## Context

Карточка ученика — модальная форма из трёх панелей (`app/student/templates/student/_form.html`),
где «Общее» и «Настройки» — две отдельные формы, отправляющие один и тот же POST:
каждая добирает поля соседней через `hx-include`. Серверная цепочка полей ученика:

- `parse_student_form` (`app/student/services/student_form.py`) — очистка и валидация;
- `_STUDENT_FIELDS` в `app/student/services/student_writer.py` — запись в модель;
- `student_to_form` / `form_from_data` / `empty_student_form`
  (`app/student/services/presentation.py`) — значения для повторной отрисовки.

Хранение дат в проекте: моменты времени — `DateTime(timezone=True)` в UTC и показ
через `to_local` (`app/common/services/tutor_time.py`); календарные даты
(например, период счёта) — `Date` без зоны.

## Goals / Non-Goals

**Goals:**

- Дата рождения хранится как календарная дата (`Date`, nullable).
- Поле вводится в карточке ученика, сохраняется, очищается и показывается на
  странице карточки.
- Некорректная дата даёт сообщение об ошибке, а не 500.

**Non-Goals:**

- Напоминания о дне рождения и использование флага `notify_birthday`.
- Ограничения на диапазон даты (не в будущем, не раньше 1900).
- Показ даты в списке учеников и в мини-формах создания (группа, бронь).
- Пересчёт даты в часовой пояс педагога.

## Decisions

**D1. Поле `birth_date: Mapped[date | None]` типа `Date`, nullable.**
Дата рождения — календарный день, а не момент времени: `DateTime` с зоной
потребовал бы фиктивного времени и часового пояса. Дополнительный CHECK не нужен —
поле необязательное и свободное по значению.

**D2. Разбор по образцу `_parse_due` из `app/task/services/task_form.py`.**
Пусто → `None`, иначе `date.fromisoformat(raw)`; `ValueError` → ошибка
«Дата рождения указана некорректно.» и `None`. Так формат совпадает с тем, что
отдаёт `input type="date"`, и повторяет уже принятый в проекте подход.

**D3. Ограничение «только для ребёнка» не применяется.**
Класс и школа сбрасываются для взрослого, дата рождения — нет: она есть у любого
человека. Поле в шаблоне не помечается `data-depends-on-kind`/`x-show`.

**D4. `form_from_data` приводит `date` к ISO-строке.**
Парсер возвращает объект `date`, а `input type="date"` ждёт строку. Без явного
приведения повторная отрисовка после ошибки валидации теряла бы выбранную дату
(в отличие от `grade`, который парсер уже отдаёт числом и представление
преобразует).

**D5. Отдельный хелпер `birth_date_label`, а не `short_date_label`.**
`short_date_label` прогоняет значение через `to_local` и применяет зону педагога;
для календарной даты это сдвигало бы день. `birth_date_label` форматирует
`%d.%m.%Y` напрямую и зарегистрирован в `register_template_helpers`.

**D6. Полная перезапись карточки сохраняется.**
POST карточки без поля `birth_date` очищает дату до NULL — это та же семантика,
что у `level`/`timezone`. Поэтому все payload'ы тестов и обе формы шлют поле;
форма «Настройки» добирает его через `hx-include="#student-form-general"`, так что
сохранение с другой вкладки дату не стирает.

## Risks / Trade-offs

- SQLite `ALTER TABLE ADD COLUMN` с nullable-колонкой безопасен и не пересобирает
  таблицу; данные не теряются.
- `downgrade` удаляет колонку вместе с введёнными датами — откат только с бэкапом.
- Мини-форма создания ученика в группе (`app/group/services/student_mini.py`) и
  создание из брони (`app/booking/services/confirmation.py`) поле не передают:
  ученик создаётся с NULL, что допустимо.
- Откат: revert коммитов плюс `alembic downgrade` до ревизии `10c3311d3321`.
