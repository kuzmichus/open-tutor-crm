# Design

## Context

Что проверено на этой итерации (числа — с машины разработки, не оценки):

- Исходник задачи — `deepseek_svg_20261027_f69104.png`, ровно 200×200 RGBA,
  круг знака занимает 6…194 px (r = 94), за пределами круга прозрачность.
- Статика проекта отдаётся mount'ом `/static` (`RevalidatingStaticFiles`,
  `Cache-Control: no-cache`) из `main.py`; отдельного маршрута для иконки нет,
  поэтому `/favicon.ico` сейчас попадает в обработчик 404.
- `mimetypes` на Python 3.14 даёт для набора: `image/vnd.microsoft.icon`,
  `image/svg+xml`, `image/png`, `application/manifest+json`.
- `.gitignore` содержит правило `*.manifest`, но `site.webmanifest` оно не
  съедает (`git check-ignore` → exit 1), переименование не нужно.
- `ImageMagick` в системе рендерит SVG своим MSVG-рендерером и теряет
  `linearGradient` (черновик выходил чёрным); `rsvg-convert` и `inkscape` не
  установлены. Значит растеризовать SVG для автопроверки нечем.
- В браузере (headless Chrome) SVG и растр сравнивались попиксельно: расхождение
  цвета градиента в контрольных точках — 1–2 из 255 на канал.

## Goals / Non-Goals

**Goals:**

- Один исходник → весь набор, повторяемая сборка одной командой.
- Набор отдаётся локально, подключён на всех страницах и по корневому адресу.
- Манифест валиден и ссылается только на существующие файлы.
- Тесты проверяют набор без Pillow: он не зависимость проекта.

**Non-Goals:**

- Замена логотипа в интерфейсе и токенов `--brand` — знак становится иконкой
  сайта, а не новым логотипом.
- OG-картинки для соцсетей, `browserconfig.xml` для IE/Edge Legacy.
- Исходник ≥512 px: 512 растягивается из 200, для вкладки это незаметно.
- Пересборка набора в CI: нет смысла гонять Pillow, файлы коммитятся.

## Decisions

**D1. Исходник коммитится в `scripts/vendor/favicon-source.png`.**
Тот же приём, что у `scripts/vendor/lucide.min.js`: вендорный файл — источник
сборки, а не ассет для браузера. Так пересборка не требует ни сети, ни
вложений задачи: заменил PNG — запустил скрипт.

**D2. Сборка — отдельный скрипт по образцу `build_icons.py`.**
Константы `ROOT`/`SOURCE`/`OUTPUT`, идемпотентность, docstring «почему так».
Pillow подключается через `uv run --with pillow`: добавлять его в
`pyproject.toml` нельзя — разойдутся `uv.lock` и образ (джоба lock в CI).

**D3. Все растры уменьшаются LANCZOS из исходника, а не из готового 512.**
Каскад «512 → 180 → 32» накапливает размытие: мелкие размеры считаются прямо
из 200×200, где детали знака ещё целы.

**D4. `apple-touch-icon` — RGB на белом.**
iOS не поддерживает прозрачность и заливает её чёрным: прозрачные углы дали бы
чёрный квадрат вместо иконки. Остальные PNG остаются RGBA — прозрачные углы там
нужны и поддерживаются.

**D5. Maskable-иконка — знак в safe zone 80% на градиенте без альфы.**
Android обрезает maskable по своей форме и оставляет видимой центральную
область. Поэтому маска белого знака вырезается из исходника и переносится на
градиент, залитый до краёв: при обрезке по любому контуру не остаётся
прозрачных углов. В манифесте иконка помечена `purpose: maskable` — обычные
иконки с прозрачными углами в этот слот ставить нельзя.

**D6. `favicon.svg` — векторная реконструкция, а не трассировка.**
Параметры: круг r = 94, градиент `#11A3E9 → #895EF6` по диагонали (крайние
точки экстраполированы по сэмплам вдоль круга), три белых эллипса
rx = 62.5, ry = 28, штрих 9.5 под 0/60/120°, белый центр r = 21.5. Числа
подобраны минимизацией расхождения маски с растром. Кольца описаны одним
`<path>` из внешнего и внутреннего контура с `fill-rule: nonzero`: так
обводка не зависит от поддержки `stroke` и даёт тот же результат при
масштабировании. Трассировка растра дала бы десятки килобайт узлов и «дрожащие»
края на 16 px.

**D7. Приёмка SVG — глазами в браузере, растеризации в тестах нет.**
Локальный ImageMagick теряет градиент (см. Context), поэтому автопроверка
«SVG похож на PNG» была бы ложной. Тест проверяет структуру (корневой `<svg>`,
`viewBox`, отсутствие внешних ссылок), совпадение с исходником — визуально.
Запасной вариант при заметном расхождении — SVG со встроенным
`data:image/png;base64`; имя файла и подключение при этом не меняются.

**D8. `safari-pinned-tab.svg` — только силуэт знака, без круга.**
Safari берёт из файла форму и красит её в `color` из разметки. Круг-фон
превратил бы иконку в сплошной залитый квадрат, поэтому в файле остаётся один
`path` со знаком.

**D9. Ссылки набора — в `base.html`, сразу после `<title>`.**
`base.html` наследуют все страницы (включая `auth.html`, `404.html`,
`cabinet/base.html`, публичную запись); ни один шаблон не подменяет `<head>`
целиком, только добавляет блок `head`. Значит правка одна, а покрытие —
все поверхности. Порядок ссылок — от лучшего варианта к запасному.

**D10. Отдельный маршрут `GET /favicon.ico`.**
Браузеры и внешние сервисы запрашивают корневой адрес, не читая разметку;
без маршрута они получают HTML 404. Ответ — `FileResponse` того же файла, что
лежит в наборе, с `Cache-Control: no-cache` (политика остальной статики,
`app/common/static_files.py`): иконка ревалидируется, 304 дёшев.

**D11. `site.webmanifest` публикуется по `/static/favicons/site.webmanifest`.**
Отдельный маршрут `/manifest.webmanifest` не нужен: манифест — статический
файл, а абсолютные `src` иконок не зависят от того, откуда его читают.

**D12. `theme-color` один — `#3290ED` (сэмпл верхней точки круга).**
Для светлой и тёмной темы одного цвета достаточно: он совпадает с фоном знака,
и адресная строка мобильного браузера выглядит продолжением иконки.

## Risks / Trade-offs

- **512 px — апскейл из 200.** На вкладке не видно, у PWA-иконки края мягче.
  Лечится заменой исходника без правки кода (описано в docstring скрипта).
- **Вектор может отличаться от растра.** Проверка визуальная; при расхождении
  есть запасной вариант со встроенным PNG (D7).
- **Правка `base.html` влияет на все страницы сразу.** Покрыто тестом на
  четырёх поверхностях: вход, 404, кабинет после входа, публичная запись.
- **`no-cache` у иконок.** Лишний 304 на страницу — дёшево; менять политику
  кэша ради иконок не стоит, иначе обновление знака не подхватится.
- **Иконка не совпадает с оранжевым логотипом интерфейса.** Это осознанно:
  знак из задачи — новая айдентика сайта; логотип и токены `--brand` вне объёма.
