# Design

## Context

Опубликованная страница лендинга отдаётся с `/` через `FileResponse` как
статический HTML — серверного рендера и подстановки данных нет. В шаблоне уже
стоят точки входа с `data-auth` (`student`, `parent`, `tutor`) и тег
`<script src="/static/landing-auth.js" defer>`. Не хватает эндпоинта статуса и
самого скрипта.

Ограничения проекта:

- сессии трёх ролей независимы и лежат в разных cookie (`tutor_session`,
  `student_session`, `parent_session`);
- статика локальная, CDN запрещены;
- публичная страница должна оставаться чистым файлом.

## Goals / Non-Goals

**Goals:**

- Публичный статус входа по трём сессиям без редиректов.
- Клиентская подмена текста и `href` только у `[data-auth]`.
- Отсутствие кэширования статуса браузером и прокси.
- Молчаливый откат к ссылкам входа при любой ошибке.

**Non-Goals:**

- Серверная подстановка кнопок в HTML.
- Восстановление тега скрипта после правок в редакторе (задача 4).
- Новые таблицы или миграции.

## Decisions

### D1. Статус — в общем модуле

`/auth/status` описывает все три роли сразу и не принадлежит одной доменной
области, поэтому живёт в `app/common/views/auth_status.py`, а не в
`app/landing/`. Роутер подключается первым в `main.py`, так что путь не
конфликтует с доменными роутами.

### D2. Эндпоинт публичный и не гейтится по `SINGLE_MODE`

Он отдаёт только булевы признаки собственных cookie текущего запроса и не
раскрывает чужих данных. Гейт по сингл-режиму сломал бы статус в
мульти-режиме без выгоды для безопасности.

### D3. `Cache-Control: no-store`

Вход и выход должны быть видны сразу: закэшированный `true` после выхода
показывал бы «В кабинет» анониму, а `false` после входа — ссылку на вход.
`no-store` запрещает хранение и браузеру, и промежуточным прокси.

### D4. Скрипт — ванильный IIFE без зависимостей

Опубликованная страница не подключает `app.js`, Alpine или htmx. Скрипт
самодостаточен, работает на `DOMContentLoaded` и обращается к DOM только
через `querySelectorAll("[data-auth]")`: остальная разметка владельца не
затрагивается. Текст меняется через `textContent`, ссылка — через
`setAttribute`, без `innerHTML`.

### D5. Ошибки — молчаливый no-op

Нет элемента, неизвестная роль, `false`, не-2xx ответ, сетевой сбой или
невалидный JSON — всё оставляет исходные ссылки на страницы входа. Это
безопасное состояние по умолчанию: страница не ломается и не показывает
ошибок посетителю.

## Risks / Trade-offs

- **Протухшая сессия между загрузкой и кликом.** Статус мог быть `true`, а
  сессия истечь до перехода — посетитель попадёт на страницу входа. Владелец
  принял это как нестрашное.
- **JS отключён.** Кнопки остаются обычными ссылками входа — рабочий сценарий.
- **Публичность статуса.** Раскрываются только собственные булевы признаки,
  без id и персональных данных.
