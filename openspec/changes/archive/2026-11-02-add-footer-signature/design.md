# Design

## Context

Подпись в подвале нужна на всех поверхностях сервиса, а их три вида:

- **с сайдбаром** — кабинет репетитора (`app/templates/sidebar.html`) и
  кабинеты ученика и родителя (`app/cabinet/templates/cabinet/_sidebar.html`,
  `.../parent/_sidebar.html`). У всех трёх уже есть `.sidebar__footer`
  с переключателем темы и строкой пользователя;
- **без сайдбара, по центру** — страницы входа/регистрации репетитора
  (`app/templates/auth.html`), вход и регистрация кабинетов
  (`app/cabinet/templates/cabinet/base.html`);
- **служебные** — 404 (`app/templates/404.html`).

Версия уже живёт в одном месте — `app/__init__.py` читает её из
`pyproject.toml` (`__version__`), и `tests/test_app_version.py` следит, чтобы
второго источника не появилось: `app.version` и `info.version` в OpenAPI
совпадают с манифестом. `pyproject.toml` копируется в рантайм-стадию
Dockerfile именно ради этого чтения.

Значок GitHub: в наборе Lucide (`app/static/icons.js`, собран
`scripts/build_icons.py` из `scripts/vendor/lucide.min.js`) брендовых иконок
нет — `grep Github` по бандлу не даёт ни одного экспорта.

## Goals / Non-Goals

**Goals:**

- Работающая версия видна без консоли и без открытия `pyproject.toml`.
- Ссылка на репозиторий проекта рядом с версией.
- Один источник версии и один экземпляр разметки подписи.
- Подпись не конкурирует с навигацией: мелкий приглушённый текст.

**Non-Goals:**

- Кнопка «Проверить обновления» и запрос к GitHub API за последним релизом.
- Показ git-хэша, даты сборки или канала (stable/dev).
- Правка `CHANGELOG.md`, bump версии, изменения маршрутов и данных.

## Decisions

**D1. Версия — глобальная переменная Jinja, а не контекст каждой вьюхи.**
`app/templating.py` регистрирует `app_version` и `app_repository_url` в
`templates.env.globals` — рядом с тем местом, где собирается окружение и
регистрируются остальные хелперы (`register_template_helpers`). Альтернатива —
передавать версию в `TemplateResponse` из каждой вьюхи — потребовала бы правки
нескольких десятков вызовов и легко забывалась бы в новых.

**D2. Адрес репозитория — константа в `app/__init__.py` рядом с версией.**
Обе подписи описывают сам проект, а не поверхность. Литерал в шаблоне пришлось
бы искать по всему дереву при переезде репозитория; тест
`test_templates_have_no_hardcoded_version` заодно запрещает литерал версии в
разметке.

**D3. Один партиал `_footer_signature.html` на все поверхности.**
Копия в каждом шаблоне разошлась бы: версию или адрес правили бы в одном месте.
Партиал называн с `_` по конвенции проекта (включаемые фрагменты, а не роуты).

**D4. Значок GitHub — inline SVG, а не `data-lucide`.**
В наборе Lucide брендовых иконок нет, добавлять сторонний бандл ради одного
значка — регрессия веса (`tests/test_icons_bundle.py` держит предел 96 КБ), а
CDN запрещён (AGENTS.md п. 8). Путь иконки — официальная octocat-марка,
`fill="currentColor"`, поэтому цвет следует теме; `aria-hidden="true"`, потому
что имя ссылки даёт `aria-label`.

**D5. Место в подвале — под строкой пользователя.**
В сайдбаре подпись идёт после профиля и кнопки выхода: это справка, а не
действие, и она не должна оттеснять элементы, за которыми заходят каждый день.
Тот же принцип, что у сервисных ссылок «Настройки»/«Обратная связь» ниже
основного меню (спека `app-navigation`).

**D6. На страницах входа подпись вынесена из карточки формы.**
`auth.html` получил обёртку `.auth__stack` (колонка 400px), а
`max-width: 400px` переехал с `.auth__card` на неё: внутри карточки подпись
читалась бы как часть формы. В кабинетах (`cabinet/base.html`) подпись —
отдельный блок `.cabinet__signature` под контентом.

**D7. Свёрнутый сайдбар (72px) кладёт подпись в столбик.**
Строка «версия + значок» шире полосы иконок, поэтому в
`html.sidebar-collapsed` у `.app-signature` меняется направление на `column` —
как уже сделано для переключателя темы (там прячутся подписи сегментов).

**D8. Внешняя ссылка — `target="_blank"` + `rel="noopener noreferrer"`.**
Как у пункта «Обратная связь» в сайдбаре: открытая вкладка не получает доступ
к `window.opener`, и переход не передаёт referrer.

## Risks / Trade-offs

- Риск: подпись занимает место в подвале сайдбара на низких экранах
  (`.sidebar__nav` скроллится, футер — нет). Подпись — одна строка 12px, около
  24px высоты; на экранах от 640px высоты меню остаётся доступным.
- Риск: версия на странице входа раскрывает, что сервис не обновлён. Это и есть
  цель задачи — владельцу сервера нужно видеть работающую версию.
- Откат: удалить партиал и шесть включений, две глобальные переменные в
  `templating.py`, правила `.app-signature*` в CSS.
