# Design

Контекст мотивации — в `proposal.md` (Why). Здесь — как устроен переключатель и почему именно так.

## Context

Опорные факты из кода:

- Тёмная тема — это **только переопределение токенов**: в `styles.css` блок `.dark` меняет значения `--background`, `--surface`, `--sidebar` и т.д., компонентные правила тему не дублируют. Значит, переключение темы = поставить/снять класс `.dark` на `<html>`, ничего больше не трогая.
- `app/static/app.js` уже содержит заготовку: `THEME_KEY = "opentutorcrm:theme"`, чтение `localStorage` и слушатель `[data-theme-toggle]`. Обработчик просто инвертировал класс и не знал, какой именно сегмент нажат, — для двухсегментного контрола этого мало.
- `base.html` уже имеет бутстрап-скрипт в `<head>`, который ставит `sidebar-collapsed` до отрисовки (чтобы сайдбар не «прыгал»). Тема страдает от той же проблемы: `app.js` подключён с `defer`, а значит выполняется после парсинга DOM.
- Футер сайдбара (`.sidebar__footer`) — `flex: none`, `margin-top: auto`; внутри лежит `.user-row-wrap`. Свёрнутый сайдбар (72px) прячет подписи через `html.sidebar-collapsed .sidebar { & .nav-item span, ... { display: none } }`.
- Иконки рисует Lucide (`<i data-lucide="sun">` → SVG) при загрузке и после каждого htmx-свопа; `sun` и `moon` есть в локальном `lucide.min.js` (v1.59).
- Сайдбар не описан ни одной спекой — его поведение закреплено только тестами `tests/test_sidebar.py`. Поэтому новая capability, а не правка существующей.

## Goals / Non-Goals

**Goals:**

- Переключатель — часть разметки сайдбара (SSR), а не клиентский виджет: работает до выполнения JS в смысле «виден и подсвечен верно».
- Активный сегмент определяется **CSS по классу на `<html>`**, а не JS-состоянием: нет рассинхрона между «какая тема» и «какой сегмент выделен».
- Обработчик идемпотентен: клик по активному сегменту не меняет тему и не пишет лишний раз в `localStorage`.

**Non-Goals:**

- Хранение темы на сервере (профиль репетитора) — тема не влияет на данные и живёт только в браузере.
- Режим «как в системе» (`prefers-color-scheme`): проект уже выбрал явную пару «светлая/тёмная», третий режим потребовал бы отдельного сегмента и состояния «не выбрано».
- Переключатель на публичных страницах (`/`, `/tutor/login`) — там нет сайдбара, а тема без переключателя восстанавливается из `localStorage` как обычно.
- Изменение набора токенов `.dark` — он уже готов и проверен тестом `tests/test_calendar.py` (слот-акцент задан и в `:root`, и в `.dark`).

## Decisions

### D1. Два сегмента с явным значением в `data-theme-toggle`

Каждая кнопка несёт `data-theme-toggle="light"` / `="dark"`, а не общий «переключатель». Обработчик берёт значение из атрибута и применяет **его**, а не инвертирует класс.

- Почему: инверсия класса ломается, как только состояние и разметка разошлись (например, второй клик по тому же сегменту, или тема изменена другим кодом). Явное значение делает операцию идемпотентной.
- Альтернатива — `<input type="checkbox">` со стилизованным свитчем: хуже для доступности с двумя подписями («Светлая»/«Тёмная» некуда повесить), и не совпадает с визуальным языком проекта (сегменты `.tabs`).

### D2. Подсветка активного сегмента — в CSS

Правило в `styles.css`:

```
html:not(.dark) .theme-switch__btn[data-theme-toggle="light"],
html.dark .theme-switch__btn[data-theme-toggle="dark"] { … }
```

- Почему: класс `.dark` — единственный источник истины о теме (от него уже зависят все токены). Подсветка, вычисленная из него, не может разойтись с фактическим оформлением и верна до выполнения `app.js` — нет «прыжка» выделения при загрузке.
- Альтернатива — `:checked`-стили или JS-класс `.theme-switch__btn--active`: требуют, чтобы JS успел отработать, иначе первый кадр показывает неверный сегмент.

### D3. Ранняя установка `.dark` в `<head>`

Тема добавляется в существующий бутстрап-скрипт `base.html` рядом с `sidebar-collapsed`.

- Почему: `app.js` — `defer`, а CSS применяется сразу; без раннего класса сохранённая тёмная тема даёт вспышку светлого фона (FOUC) на каждой навигации. Скрипт крошечный и уже обёрнут в `try/catch` (приватный режим, где `localStorage` бросает исключение).
- Альтернатива — инлайновый `<style>` с `@media (prefers-color-scheme)` не подходит: тема выбирается вручную, а не системная.

### D4. `aria-pressed` синхронизирует `app.js`, разметка даёт стартовое состояние

В шаблоне «Светлая» помечена `aria-pressed="true"`, «Тёмная» — `false`; `applyTheme()` обновляет оба атрибута после каждого переключения (и при инициализации).

- Почему: `aria-pressed` — состояние кнопки-переключателя, его нельзя выразить CSS. Стартовые значения в разметке совпадают с серверным состоянием «светлая по умолчанию»; для сохранённой тёмной темы атрибуты поправит `app.js` сразу при загрузке, а визуально всё уже верно из CSS.
- Альтернатива — `role="tab"`/`aria-selected`: это не табы, а переключатель режима; `role="switch"` на каждую кнопку вводил бы в заблуждение (у каждой кнопки своё фиксированное значение).

### D5. Свёрнутый сайдбар — только иконки

В медиа-блоке `html.sidebar-collapsed` у `.theme-switch__btn` убираются подписи (`span`) и боковые отступы.

- Почему: две подписи «Светлая»/«Тёмная» не влезают в 54px полезной ширины (72px минус отступы), и контрол начал бы переноситься или обрезаться. Иконки + `title` сохраняют смысл, а `aria-label`-эквивалент даёт текст внутри кнопки (он скрыт визуально, но доступен скринридеру).

### D6. Ключ `localStorage` — существующий `opentutorcrm:theme`

Не вводим новый ключ и не меняем формат (`"light"` / `"dark"`).

- Почему: заготовка в `app.js` уже писала этот ключ; смена имени осиротила бы выбор пользователей. Префикс `opentutorcrm:` совпадает с ключом сайдбара.

## Risks / Trade-offs

- **Тема не синхронизируется между устройствами** → осознанно: тема — локальная настройка браузера, сервер о ней не знает; при необходимости отдельный change с полем в профиле.
- **Класс `.dark` на `<html>` влияет на все страницы, включая публичные** → это желаемое поведение (единое оформление), но публичные страницы не дают выйти из тёмной темы: переключателя там нет. Mitigation: выход есть с любой страницы под сайдбаром; при жалобах — отдельная задача «переключатель на страницах авторизации».
- **`localStorage` недоступен (приватный режим, отключённое хранилище)** → и бутстрап, и `applyTheme` обёрнуты в `try/catch`: тема применяется в пределах текущей страницы, но не запоминается.
- **Lucide не успел отрисовать иконки** → кнопка временно пустая по центру; текст подписи остаётся, ширина не скачет (иконка фиксированного размера 16px, `[data-lucide]` задаёт `width/height`). Повторная отрисовка после htmx-свопа уже покрыта `renderIcons()`.
- **Расширение `.dark`-блока в будущем** → подсветка не зависит от конкретных токенов, поэтому новые токены подхватываются автоматически.

## Migration Plan

Изменение чисто клиентское и обратно совместимое:

1. Правки шаблонов, `app.js` и `styles.css` выкатываются одним коммитом.
2. У пользователей с уже сохранённым (заготовкой) значением `opentutorcrm:theme = "dark"` тема включится сама — ключ и значения не менялись.
3. Откат — revert коммита: возвращается прежняя разметка футера и обработчик-инверсия; сохранённый ключ остаётся, но перестаёт читаться бутстрапом (вредных следов нет).
4. Миграций БД и серверных маршрутов нет.
