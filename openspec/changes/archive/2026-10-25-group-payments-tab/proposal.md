# Proposal

## Why

Вкладка «Оплаты» в модалке управления группой — заглушка «Оплаты группы появятся позже», хотя счёт учеников уже живёт в модуле `finance`: списания за проведённые групповые занятия создаются автоматически (`charges.sync_lesson_charge`), платежи и возвраты вносятся в карточке ученика. Репетитор, который ведёт группу, не может увидеть по группе главное: сколько списано за занятия этой группы, сколько возвращено и сколько участники должны сейчас. Ответ разложен по карточкам учеников, хотя все данные уже есть в `account_operations` и связаны с группой через `lesson_id`.

Спека `group-management` прямо требует заглушку («суммы не отображаются») — этот change снимает требование и заменяет вкладку реальными данными, как это уже сделано для карточки ученика change'ом `student-finance`.

## What Changes

- **Вкладка «Оплаты» модалки группы показывает сводку счёта** вместо заглушки:
  - переключатель периода чипами: «За всё время» (по умолчанию), «Этот месяц», «Прошлый месяц»;
  - три сводки: «Списано за занятия группы» (списания текущих участников за уроки этой группы в периоде), «Возвращено» (возвраты участников в периоде), «Долг участников сейчас» (сумма долгов участников, от периода не зависит);
  - строка на каждого участника: имя-ссылка в карточку ученика (сразу на вкладку «Платежи»), «Баланс» и «Долг» — по всему счёту ученика, «Списано» — только за занятия этой группы в выбранном периоде, с числом занятий;
  - подпись-пояснение о разнице объёмов: баланс и долг — по всем занятиям ученика, списания — только за занятия этой группы, оплату вносят в карточке ученика.
- **Панель приходит отдельным GET-маршрутом** `/tutor/groups/{id}/payments` (партиал с корнем `#group-payments-content`): вкладка грузится лениво из слота с `hx-trigger="load"`, чипы периода перезапрашивают тот же маршрут — DOM обновляется с сервера, без JS-пересчётов (паттерн панели платежей ученика, design D11 `student-finance`).
- **Данные считает модуль `finance`** (новый сервис `group_panel`), владелец группы проверяется через ри-экспорт `get_owned_group` в `finance/services/access.py`. Модуль `group` остаётся без финансовых расчётов.
- **BREAKING для спек**: требование `group-management` «Заглушки вкладок «Расписание», «Занятия», «Оплаты»» сужается до вкладок «Расписание» и «Занятия»; добавляется требование «Вкладка «Оплаты»».

Вне объёма: внесение оплаты и возврат из модалки группы (оплата живёт в карточке ученика), списания за индивидуальные уроки участников (не относятся к группе), пагинация, экспорт, посещаемость.

## Capabilities

### Modified Capabilities

- `group-management`: вкладка «Оплаты» модалки управления группы показывает сводку счёта группы (периоды, списания за занятия группы, возвраты, долг участников, строки участников) вместо заглушки.

## Impact

- **Новое**: `app/finance/services/group_panel.py` (периоды, итоги, строки участников), `app/finance/views/group_panel.py` (GET-партиал), `app/finance/templates/finance/_group_panel.html`.
- **Изменённое**: `app/group/templates/group/_manage.html` (слот панели вместо заглушки), `app/finance/services/access.py` (ри-экспорт `get_owned_group`), `app/finance/services/presentation.py` (плюрализация «N занятий»), `app/finance/views/__init__.py`, `app/static/styles.css` (блок `group-payments`).
- **Миграций нет**: данные читаются из существующих `account_operations`, `lessons`, `group_members`.
- **Тесты**: `tests/test_group_payments.py` (сводка, периоды, изоляция, партиал); правка параметризации заглушек в `tests/test_group_manage.py`.
