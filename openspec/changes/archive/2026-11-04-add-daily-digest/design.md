# Design

## Context

Мотивация — в `proposal.md`. Здесь только то, что определяет технические решения.

Состояние проекта, проверенное перед планированием:

- cron: `cron.py` → `app/common/services/cron.py` (`TASKS`, `run_tasks`): своя
  сессия и транзакция на задание, коммит делает runner, падение одного задания
  изолировано. Сейчас зарегистрировано одно задание — `lesson.auto_complete`.
- Настройки: `app/tutor/models/tutor_settings.py` — `notify_daily_digest`,
  `digest_time` (`String(5)`, дефолт `09:00`), `notify_insufficient_funds`.
  Чтение с дефолтами — `app/tutor/services/settings.py:get_settings` (строки
  может не быть). Форма и страница вкладки «Уведомления» уже готовы.
- Мессенджеры: `send_message` (журнал `sent_messages`, ретрай, ошибки списком),
  `binding.chat_id_key`, `connections.is_messenger_connected` (только по токену).
  Привязанный чат — параметр `<мессенджер>_chat_id`.
- Данные дня: `app/tutor/services/dashboard.py:today_lessons` — образец выборки
  (окно `local_day_bounds`, JOIN `Student`/`Group`, изоляция по владельцу цели),
  но без цен.
- Деньги: `finance/services/balance.py:balance` (единственная формула),
  `finance/services/charges.py:group_targets` (цена участника =
  `price_override ?? group.price_per_lesson`), формат — `money`/`balance_label`.
- Время: `app/common/services/tutor_time.py` (`today_local`, `local_day_bounds`,
  `tutor_zone`) и `app/tutor/services/clock.py` (`as_utc`, `utcnow`).

## Goals / Non-Goals

**Goals:**

- Задание cron, которое отправляет сводку уроков дня в момент `digest_time`
  местного времени педагога во все привязанные каналы.
- Одна отправка на локальный день; пропущенный прогон догоняется в тот же день.
- Пометка «не хватает денег» по каждому ученику урока (в группе — по каждому
  участнику), с ценой участника по общему правилу модуля finance.
- Отсутствие миграций и изменений схемы.

**Non-Goals:**

- Превью сводки в профиле, ручная отправка «сейчас».
- Учёт отмены/переноса урока: отдельных статусов в модели нет.
- Сводная пометка для группы («не хватает у 2 участников»).
- Ограничение окна «не позже N часов после `digest_time`».
- Напоминания ученикам и родителям: сводка адресована репетитору.

## Decisions

**D1. Маркер дня — строка `tutor_params` с ключом `digest_sent_date`.**
Значение — локальная дата ISO (`YYYY-MM-DD`). Отдельная колонка в
`tutor_settings` потребовала бы миграции ради служебного состояния, а KV-таблица
для этого и существует. Маркер сравнивается с текущей локальной датой педагога,
поэтому прогон в 23:59 и в 00:01 — разные дни, а наложение двух прогонов в одну
минуту не даёт второй отправки.

**D2. Маркер ставится после попытки отправки, в том числе неудачной.**
Иначе сбойный канал ретраился бы каждую минуту до конца дня, а сводка — это
утреннее сообщение, а не гарантированная доставка. Факт сбоя остаётся в журнале
`sent_messages` (`status='error'`) — репетитор видит причину на вкладке журнала.

**D3. Отбор получателей — по наличию привязанного чата, а не токена.**
`connections.connected_messengers` отвечает на вопрос «настроен ли бот», а
отправлять некуда, пока чат не привязан. Поэтому задание берёт репетиторов, у
которых есть хотя бы один параметр `<мессенджер>_chat_id` (`bound_chats`), а
`send_message` сам проверит токен и вернёт ошибку, если его нет.

**D4. `bound_chats` живёт в `binding.py`, а не в `connections.py`.**
`connections` импортирует `messengers`; обратный импорт `connections → binding`
замкнул бы цикл (`binding → welcome → send → connections`). В `binding.py`
рядом уже лежат имена ключей `chat_id_key` — правило чтения привязки остаётся
в одном модуле.

**D5. Цели урока с ценами — `charges.lesson_targets_any_status`.**
Правило цены (индивидуальный — `lesson.price`, участник группы —
`price_override ?? group.price_per_lesson`) уже есть в `charges`; копия в сводке
разошлась бы со списаниями при первой правке. Существующая `lesson_targets`
фильтрует по статусу «Проведён» и отметкам отсутствия — для плана дня это
неверно, поэтому общая часть вынесена в публичную функцию без фильтра, а
`lesson_targets` стала её надстройкой.

**D6. Нехватка средств — `balance.shortfall(balance, price)`.**
Чистая функция рядом с единственной формулой баланса: ноль, если денег хватает
или цена не задана; иначе `price − balance`. Отрицательный баланс даёт нехватку
больше цены — долг тоже надо покрыть.

**D7. Пометка о нехватке включается флагом `notify_insufficient_funds`.**
Описание переключателя на вкладке («утром — у кого сегодня занятие, а на счету
меньше его стоимости») описывает ровно этот сценарий; флаг по умолчанию
включён, поэтому поведение из постановки работает из коробки.

**D8. В сводку — только «Запланированные» уроки.**
Сводка — план дня. Проведённый урок из плана уже не актуален, а пометка «не
хватает денег» относится к предстоящей оплате.

**D9. День без уроков — без сообщения, но с маркером.**
Пустая сводка противоречит правилу проекта «не показывать нули», а маркер нужен,
чтобы не пересчитывать день на каждом минутном прогоне.

**D10. Коммит после каждого репетитора внутри задания.**
Сетевые вызовы (до 10 с × 3 попытки × каналы) не должны держать открытую
транзакцию SQLite и блокировать запись веб-приложению. Повторный коммит runner'а
безопасен.

**D11. Обрезка текста до 4000 символов с «…».**
Лимит Telegram — 4096 символов; страховка для дня с десятками уроков. В журнале
`sent_messages` остаётся фактически отправленный текст.

**D12. Локальное время урока переводится в зону педагога в задании.**
`digest_lessons` возвращает aware UTC (как остальные сервисы), а текст сводки —
настенное время педагога; перевод делает оркестратор перед форматированием,
поэтому `build_digest_text` остаётся чистой функцией.

## Risks / Trade-offs

- **Сводка сразу после привязки канала.** У репетитора без строки настроек
  действуют дефолты (сводка включена, 09:00), поэтому привязка чата в 14:00
  даёт сводку в тот же день сразу. Это следствие `get_settings` и правила
  «догоняем в тот же день»; приемлемо — первое сообщение всё равно полезно.
- **Пропущенный день не догоняется.** Если cron не работал весь день, сводка за
  этот день не придёт: окно «не позже N часов» не вводится (см. Non-Goals).
- **Долгие сетевые вызовы.** Смягчение — коммит на репетитора, изоляция ошибок
  каналов, ограниченный круг получателей (только привязанные чаты).
- **Лимит длины сообщения.** Обрезка до 4000 символов; в журнале — фактический
  текст.

## Migration Plan

Миграции не нужны: схема не меняется, новый параметр — обычная строка
`tutor_params`. Откат — убрать запись из `TASKS` (задание перестаёт выполняться);
оставшиеся строки `digest_sent_date` безвредны.
