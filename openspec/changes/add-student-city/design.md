# Design

## Context

Серверная цепочка полей ученика (та же, что у даты рождения и часового пояса):

- `parse_student_form` (`app/student/services/student_form.py`) — очистка и валидация;
- `_STUDENT_FIELDS` / `_EMPTY_TO_NONE` в `app/student/services/student_writer.py` —
  запись в модель;
- `student_to_form` / `form_from_data` / `empty_student_form`
  (`app/student/services/presentation.py`) — значения для формы.

Виджет с поиском уже есть: `app/static/combobox.js` (Alpine.data `combobox`)
читает варианты из `data-options` (JSON `[{value, label}]`), фильтрует по
подстроке без учёта регистра и разрешает свободный ввод. Он же обслуживает поле
«Часовой пояс», контекст формы собирает `form_context`.

## Goals / Non-Goals

**Goals:**

- Город хранится как свободный текст (`String(100)`, nullable).
- Поле стоит перед «Школой» и доступно обоим подтипам ученика.
- Подсказки — из городов других учеников этого репетитора, без дублей.
- Город виден с иконкой в миникарточке списка и в большом профиле.

**Non-Goals:**

- Справочник городов, нормализация написаний, геокодирование.
- Отдельный htmx-эндпоинт подсказок: список собирается при открытии формы.
- Фильтр/колонка города в компактном виде «список» и поиск по городу в тулбаре.

## Decisions

**D1. Поле `city: Mapped[str | None]` типа `String(100)`, nullable.**
Город — свободный текст без CHECK-ограничения: закрытого списка значений нет.
Длина 100 символов — как у `level`, короче `school` (255): город короче названия
школы. Индекс не нужен: выборка подсказок идёт по индексированному `tutor_id`,
а карточек у одного репетитора немного.

**D2. Отдельной таблицы-справочника городов нет.**
Требование прямо говорит про «города других учеников», поэтому источник
подсказок — `DISTINCT` по `students.city` в пределах репетитора
(`app/student/services/cities.py`). Так репетитор видит свои привычные написания,
а не абстрактный справочник, и нет второй сущности для синхронизации.

**D3. Дедупликация и сортировка — в Python по `casefold()`.**
SQLite `lower()` не понимает кириллицу (тот же приём, что в
`students._matches_search`). При совпадении без учёта регистра остаётся первое
написание — «Москва» и «москва» в списке схлопываются в один вариант.

**D4. Свой город исключается из подсказок открытой карточки.**
`exclude_student_id` передаётся из `form_context` для сохранённого ученика:
подсказки — это «города других учеников», а свой уже стоит в поле.

**D5. Значение не нормализуется при сохранении.**
Город сохраняется как набран (общий `text_value` срезает пробелы по краям).
Отдельного справочника нет, поэтому «г. Москва» останется как есть — это цена
свободного поля; в подсказках такие варианты хотя бы не дублируются.

**D6. Поле доступно и ребёнку, и взрослому.**
Город есть у любого человека, поэтому, в отличие от класса и школы, поле не
помечено `data-depends-on-kind`/`x-show` и в сброс для взрослого не попадает.

**D7. Один виджет на два поля, отдельного JS не требуется.**
Разметка поля «Город» — копия поля «Часовой пояс»: `.combobox` +
`x-data="combobox()"` + `data-options`. У города `label` пустой — виджет просто
не рисует вторую колонку. Escape закрывает список, а не модалку.

**D8. Иконка `map-pin` из Lucide.**
Набор `app/static/icons.js` собирается tree-shaking'ом
(`scripts/build_icons.py`), поэтому после правки шаблонов набор пересобран —
иначе `tests/test_icons_bundle.py` краснеет.

## Risks / Trade-offs

- Карточка сохраняется целиком: POST без поля `city` обнулит город. Это та же
  семантика, что у `level`/`timezone`; форма «Настройки» добирает поле через
  `hx-include="#student-form-general"`, так что сохранение с другой вкладки город
  не стирает.
- Мини-формы создания ученика (группа, бронь) поле не передают — ученик
  создаётся с NULL, что допустимо.
- Список подсказок собирается на сервере в момент открытия формы: город,
  добавленный другим учеником в параллельной сессии, появится после переоткрытия
  формы. Для подсказки это приемлемо и не требует эндпоинта.
- В форме теперь два `data-options` (город и часовой пояс): тест-хелпер
  часового пояса привязан к своему блоку, иначе он читал бы список городов.
- SQLite `ALTER TABLE ADD COLUMN` с nullable-колонкой не пересобирает таблицу —
  данные не теряются. `downgrade` удаляет колонку вместе с введёнными городами:
  откат только с бэкапом.
- Откат: revert коммитов плюс `alembic downgrade` до ревизии `a7d3e1f42b90`.
