# landing-page Specification

## Purpose

Публичная страница репетитора: одна страница на установку, которая правится
визуально в редакторе, хранится на диске и отдаётся с корня сайта без
серверного рендера. Фича доступна только в сингл-режиме.

## Requirements

### Requirement: Хранилище лендинга на диске

Лендинг SHALL храниться на диске в каталоге `LANDING_ROOT` (по умолчанию
`./landing`) и MUST NOT храниться в базе данных или в хранилище `FILES_*`.
Каталог SHALL содержать черновик `draft.html`, опубликованную страницу
`index.html`, бэкап прошлой публикации `index.prev.html` и подкаталог
`assets/` для картинок редактора. Каталоги SHALL создаваться лениво, при
первой записи; чтения при отсутствующем каталоге MUST отвечать «нет» без
исключений.

#### Scenario: Пустой корень
- **WHEN** каталог `LANDING_ROOT` не существует
- **THEN** проверки наличия черновика и публикации возвращают «нет», чтение черновика — пусто, список ассетов пуст, и каталог не создаётся

#### Scenario: Сохранение черновика
- **WHEN** редактор сохраняет HTML черновика
- **THEN** файл `draft.html` записан в `LANDING_ROOT`, а каталог создан при необходимости

### Requirement: Публикация и отмена публикации

Публикация SHALL перезаписывать `index.prev.html` текущим `index.html` (если
тот существует) и затем записывать копию `draft.html` в `index.html`;
черновик MUST оставаться на месте. Без черновика публикация MUST NOT создавать
страницу. Отмена публикации SHALL удалять только `index.html` и MUST NOT
трогать `index.prev.html` и `draft.html`.

#### Scenario: Публикация черновика
- **WHEN** черновик сохранён и вызвана публикация
- **THEN** `index.html` содержит HTML черновика, а `draft.html` остаётся на месте

#### Scenario: Повторная публикация
- **WHEN** страница уже опубликована и публикуется новая версия черновика
- **THEN** `index.html` содержит новую версию, а `index.prev.html` — предыдущую

#### Scenario: Отмена публикации
- **WHEN** опубликованная страница снята с публикации
- **THEN** `index.html` удалён, а `index.prev.html` и `draft.html` сохранены

### Requirement: Отдача опубликованной страницы с корня

В сингл-режиме при наличии `index.html` запрос `GET /` SHALL отдавать
содержимое файла как есть (`text/html`) с заголовком `Cache-Control:
no-cache`, без серверного рендера и подстановки данных. Если фича выключена
(мульти-режим) или страница не опубликована, `GET /` SHALL отвечать прежним
редиректом 303 на `/tutor/`.

#### Scenario: Опубликованная страница в сингл-режиме
- **WHEN** включён `SINGLE_MODE` и в `LANDING_ROOT` есть `index.html`
- **THEN** `GET /` отвечает 200 с содержимым файла и `Cache-Control: no-cache`

#### Scenario: Публикации нет
- **WHEN** включён `SINGLE_MODE`, но `index.html` отсутствует
- **THEN** `GET /` отвечает 303 на `/tutor/`

#### Scenario: Мульти-режим
- **WHEN** `SINGLE_MODE` выключен, даже если `index.html` существует
- **THEN** `GET /` отвечает 303 на `/tutor/`

### Requirement: Публичная отдача картинок лендинга

Картинки редактора SHALL отдаваться по `GET /landing-assets/{filename}`
публично, с типом содержимого по расширению и заголовком `Cache-Control:
public, max-age=31536000, immutable`. Имя файла SHALL генерировать сервер
(`uuid4` и расширение из набора png, jpg/jpeg, gif, webp, svg); имя, не
соответствующее шаблону сгенерированного имени, MUST отвечать 404, как и
отсутствующий файл.

#### Scenario: Картинка опубликованной страницы
- **WHEN** запрошен адрес ассета, сохранённого редактором
- **THEN** ответ 200 с байтами картинки, типом по расширению и долгим неизменяемым кэшем

#### Scenario: Произвольное имя
- **WHEN** запрошен `/landing-assets/` с именем, не являющимся сгенерированным (`../secret.png`, `photo.png`, недопустимое расширение)
- **THEN** ответ 404

### Requirement: Загрузка картинок из редактора

`POST /tutor/landing/assets` SHALL требовать сессию репетитора и быть
доступным только в сингл-режиме; в мульти-режиме MUST отвечать 404, не
обращаясь к диску. Роут SHALL принимать multipart-загрузку Asset Manager
GrapesJS (поле `files` или `files[]`), валидировать весь набор до записи и
сохранять файлы под сгенерированным сервером именем (`uuid4` и расширение
исходного файла) через `save_asset()`.

Белый список расширений SHALL совпадать с публичной отдачей: `png`, `jpg`,
`jpeg`, `gif`, `webp`, `svg`. Лимит размера SHALL браться из существующей
настройки `FILES_MAX_SIZE_MB`. Для растров (png, jpg/jpeg, gif, webp)
содержимое SHALL проверяться по магическим байтам: расширению должен
соответствовать реальный формат. SVG MUST приниматься по расширению и
непустому телу. Пустой файл MUST отклоняться для любого формата.

Успешный ответ SHALL иметь вид `{"data": [{"src":
"/landing-assets/<uuid>.<ext>", "type": "image"}]}` с
`Cache-Control: no-store`. При отказе MUST возвращаться JSON
`{"error": "<понятное сообщение>"}`: 400 при недопустимом формате,
несовпадении сигнатуры, пустом файле или отсутствии файлов; 413 при
превышении лимита. Ссылки на вставленные картинки SHALL быть абсолютными
(`/landing-assets/…`).

#### Scenario: Успешная загрузка
- **WHEN** репетитор загружает `photo.png` с корректными байтами PNG из Asset Manager
- **THEN** ответ 200 содержит абсолютный `/landing-assets/<uuid>.png`, файл лежит в `landing/assets/`, а ссылка открывается публично

#### Scenario: Несколько файлов
- **WHEN** в одном запросе приходят два файла в поле `files[]`
- **THEN** ответ содержит два элемента `data`, на диске появляются два разных файла

#### Scenario: Не картинка
- **WHEN** загружен `virus.exe`, `page.html`, файл без расширения или `photo.png` с текстовыми байтами
- **THEN** ответ 400 с понятным сообщением, на диск не записывается ничего

#### Scenario: Пустой или слишком большой файл
- **WHEN** загружен пустой файл или файл больше `FILES_MAX_SIZE_MB`
- **THEN** ответ 400 или 413 соответственно, на диск не записывается ничего

#### Scenario: Атомарность набора
- **WHEN** в одном запросе валидный файл идёт рядом с невалидным
- **THEN** отклоняется весь набор и на диск не попадает ни один файл

#### Scenario: Мульти-режим
- **WHEN** `SINGLE_MODE` выключен
- **THEN** `POST /tutor/landing/assets` отвечает 404 и не создаёт файлов

### Requirement: Удаление картинки

`DELETE /tutor/landing/assets/{filename}` SHALL требовать сессию репетитора
и быть доступным только в сингл-режиме (404 в мульти-режиме). Имя файла
SHALL проверяться тем же строгим шаблоном, что и публичная отдача; не
прошедшее шаблон имя MUST отвечать 404. Валидное имя SHALL удалять файл с
диска; отсутствующий файл MUST NOT считаться ошибкой (ответ 204),
повторное удаление идемпотентно. Ответ SHALL отдаваться с
`Cache-Control: no-store`.

#### Scenario: Удаление ассета
- **WHEN** репетитор удаляет ассет в Asset Manager, и файл существует
- **THEN** файл исчезает с диска, ответ 204, а `GET /landing-assets/<имя>` отвечает 404

#### Scenario: Повторное удаление
- **WHEN** тот же ассет удалён повторно
- **THEN** ответ 204, а не ошибка

#### Scenario: Постороннее имя
- **WHEN** запрошено удаление `photo.png`, имени с другим расширением или обходом каталога
- **THEN** ответ 404, файлы на диске не меняются

#### Scenario: Мульти-режим
- **WHEN** `SINGLE_MODE` выключен
- **THEN** `DELETE /tutor/landing/assets/<имя>` отвечает 404 и не трогает диск

### Requirement: Инициализация Asset Manager

`GET /tutor/landing/editor` SHALL вшивать в страницу JSON текущих ассетов
(`list_assets()` → `[{"src": "/landing-assets/<uuid>.<ext>", "type":
"image"}]`) и инициализировать GrapesJS с
`assetManager: { upload: "/tutor/landing/assets", uploadName: "files",
uploadText: "<текст>", assets: <список> }`. В список MUST попадать только
файлы с именем, проходящим шаблон сгенерированного имени.

JS редактора SHALL по событию `asset:remove` отправлять `DELETE` на
`/tutor/landing/assets/<имя>` (имя восстанавливается из абсолютного
префикса `/landing-assets/`), а по `asset:remove:before` — показывать
текст подтверждения, предупреждающий, что файл будет удалён с диска и
ссылки на него перестанут работать. События `asset:upload:start`,
`asset:upload:end` и `asset:upload:error` SHALL показывать ход загрузки и
понятную причину отказа из JSON-ответа.

#### Scenario: Список существующих картинок
- **WHEN** в `landing/assets/` уже лежат картинки и репетитор открывает редактор
- **THEN** JSON `landing-assets` содержит их абсолютные ссылки, и они видны в Asset Manager

#### Scenario: Удаление в редакторе
- **WHEN** репетитор подтверждает удаление ассета в Asset Manager
- **THEN** редактор отправляет `DELETE`, файл исчезает с диска, а статус сообщает об удалении

#### Scenario: Отказ загрузки
- **WHEN** сервер отклонил загруженный файл и вернул `{"error": "…"}`
- **THEN** редактор показывает это сообщение в статусной строке

### Requirement: Загрузка ассетов только картинками

Сохранение ассета SHALL принимать только файлы с расширением из набора
картинок; расширение SHALL нормализоваться к нижнему регистру, а основа имени
MUST генерироваться сервером. Пользовательское имя файла MUST NOT попадать в
путь на диске.

#### Scenario: Одинаковые имена из редактора
- **WHEN** дважды загружена картинка с именем `photo.png`
- **THEN** на диске появляются два разных файла с именами на основе `uuid4`

#### Scenario: Не картинка
- **WHEN** сохранение ассета вызвано с файлом `page.html` или `virus.exe`
- **THEN** файл не сохраняется, операция завершается ошибкой

### Requirement: Шаблон лендинга по умолчанию

Система SHALL предоставлять самодостаточный шаблон страницы
(`app/landing/templates/default_page.html.j2`): стили внутри файла, шрифты —
локальный Geist из `/static/fonts/`, без CDN и без общего `app.css`.
Шаблон SHALL содержать шапку с именем, разделами-якорями (только десктоп),
кнопкой переключения темы (`data-theme-toggle`) и кнопками «Вход для
ученика» (`/student/login`, `data-auth="student"`) и «Вход для родителя»
(`/parent/login`, `data-auth="parent"`), вторичными по отношению к CTA
«Записаться на бесплатное пробное» → `/s/<tutor_id>`; секции в порядке:
hero (оффер, подзаголовок с предметом, CTA, строка доверия с опытом из
профиля, плейсхолдер фото), «Услуги и цены» (три карточки-пакета, ставка
профиля в первой; цены без «по запросу»), «Обо мне» (`about`,
`experience`), «Образование, курсы, сертификаты» (демо-список), «Результаты
и отзывы» (демо, snap-скролл на мобильном), «Как проходит обучение»
(шаги), «Частые вопросы» (нативные `<details>`), финальная CTA «Запись» →
`/s/<tutor_id>`; подвал с контактами (телефон из
профиля, ссылки-плейсхолдеры мессенджеров), плейсхолдером политики
конфиденциальности, копирайтом и мелкой приглушённой ссылкой «вход»
(`/tutor/login`, `data-auth="tutor"`). Шаблон SHALL быть мобильным
mobile-first с брейкпоинтами 768/1024/1440; тёмная тема SHALL включаться
автоматически (`prefers-color-scheme`) и кнопкой `data-theme-toggle` с
сохранением выбора в localStorage; анимации появления SHALL уважать
`prefers-reduced-motion` и включаться только скриптом эффектов.
`<title>` — вида «{имя} — репетитор по {предмету}». Перед `</body>` SHALL
стоять `<script src="/static/landing-effects.js"></script>` и
`<script src="/static/landing-auth.js" defer></script>`. Все поля профиля
MUST экранироваться. Пустые поля MUST NOT рендерить пустые заголовки и
строки. Демонстрационный контент (оффер, цены пакетов, отзывы, шаги,
ответы FAQ) помечен комментариями Jinja и не попадает в HTML.

#### Scenario: Генерация черновика из профиля
- **WHEN** репетитор с заполненным профилем создаёт черновик
- **THEN** `draft.html` содержит имя, предмет, «О себе», опыт, ставку и телефон, а все CTA ведут на `/s/<tutor_id>`

#### Scenario: Пустые поля
- **WHEN** в профиле не заполнены «О себе», опыт, ставка или телефон
- **THEN** соответствующие блоки не рендерятся (секция «Обо мне» скрыта целиком), а в разметке нет «None» и пустых заголовков

#### Scenario: Экранирование
- **WHEN** в поле профиля есть `<script>alert(1)</script>`
- **THEN** в черновике тег экранирован и не исполняется

#### Scenario: Точки входа и отсутствие CDN
- **WHEN** черновик создан
- **THEN** в нём есть ссылки входов ученика, родителя и репетитора, теги `/static/landing-effects.js` и `/static/landing-auth.js`, нет ссылок на CDN и `/static/styles.css`

### Requirement: Страница управления лендингом

`GET /tutor/landing` SHALL требовать сессию репетитора и быть доступной
только в сингл-режиме; в мульти-режиме MUST отвечать 404. Страница SHALL
показывать состояние: «опубликован» (есть `index.html`), «черновик» (есть
только `draft.html`) или «пусто». На странице SHALL быть кнопки
«Предпросмотр», «Опубликовать», «Снять с публикации», «Вернуть шаблон»
(с подтверждением) и «Редактировать» → `/tutor/landing/editor`; кнопка
«Редактировать» SHALL быть видна всегда. Обычный просмотр страницы
MUST NOT перезаписывать черновик.

#### Scenario: Пустое состояние
- **WHEN** черновика и публикации нет
- **THEN** страница показывает «пусто» и кнопку создания черновика

#### Scenario: Статус опубликованной страницы
- **WHEN** `index.html` существует
- **THEN** страница показывает «опубликован» и кнопку снятия с публикации

#### Scenario: Мульти-режим
- **WHEN** `SINGLE_MODE` выключен
- **THEN** `GET /tutor/landing` отвечает 404

#### Scenario: Правки черновика сохраняются
- **WHEN** `draft.html` отредактирован, а затем открыта страница управления
- **THEN** файл не меняется

### Requirement: Редактор лендинга

`GET /tutor/landing/editor` SHALL требовать сессию репетитора и быть
доступным только в сингл-режиме; в мульти-режиме MUST отвечать 404. При
отсутствии `draft.html` роут SHALL создавать черновик из шаблона профиля и
открывать его. Страница SHALL быть автономным документом (свой `<html>`,
без `base.html`, сайдбара и общего `app.css`) с верхней панелью
«Сохранить», «Предпросмотр», «Назад к управлению» и контейнером редактора
на весь вьюпорт. Ответ SHALL отдаваться с `Cache-Control: no-store`.

В редактор SHALL попадать содержимое `<body>` черновика без тегов
`<script>` и первый `<style>` черновика; подключение
`/static/landing-auth.js` на странице редактора MUST NOT выполняться.

#### Scenario: Открытие редактора
- **WHEN** включён `SINGLE_MODE`, репетитор вошёл и открывает `/tutor/landing/editor`
- **THEN** ответ 200 с автономной страницей GrapesJS, русскими подписями и телом черновика без скриптов

#### Scenario: Черновика нет
- **WHEN** репетитор открывает редактор, а `draft.html` отсутствует
- **THEN** черновик создаётся из шаблона профиля и открывается в редакторе

#### Scenario: Мульти-режим
- **WHEN** `SINGLE_MODE` выключен
- **THEN** `GET /tutor/landing/editor` и `POST /tutor/landing/draft` отвечают 404 и не создают файлов

### Requirement: Сохранение черновика из редактора

`POST /tutor/landing/draft` SHALL принимать JSON `{html, css}` от
`editor.getHtml()` / `editor.getCss()` и собирать полный документ:
`<!doctype html>`, `<html lang="ru">`, `<meta charset="utf-8">`,
`<meta name="viewport" content="width=device-width, initial-scale=1">`,
`<meta name="description">` и `<meta name="robots">` из текущего черновика
(robots без тега — «index, follow»; description без тега не пишется),
`<title>` из текущего черновика (или «{имя} — репетитор»),
`<style>{css}</style>` и тело. Внешняя обёртка `<body>…</body>`, которую
возвращает GrapesJS, SHALL сниматься. Документ MUST записываться в
`draft.html`. Ответ SHALL содержать `{"message": "Сохранено"}` с
`Cache-Control: no-store`.

Служебные теги скриптов `<script src="/static/landing-effects.js"></script>`
и `<script src="/static/landing-auth.js" defer></script>` SHALL
гарантироваться идемпотентно (по маркеру каждого): тег уже есть в
документе — второй не появляется; иначе тег вставляется перед последним
`</body>` (без `</body>` — в конец). Порядок — сначала эффекты, затем
входы. Повторные сохранения MUST оставлять ровно один тег каждого.

Оформление черновика SHALL переживать круглый трип: сокращённые CSS-свойства
с `var()` загружаются в GrapesJS развёрнутыми в длинные, чтобы CSSOM не
выбрасывал `background: var(--accent)`, `border: … var(--border)` и
`border-radius: var(--radius)`.

#### Scenario: Сохранение правок
- **WHEN** редактор отправляет новый HTML и CSS
- **THEN** `draft.html` содержит новый HTML, CSS в `<style>`, шапку документа с прежними `<title>` и `<meta>`, и ровно по одному тегу `landing-effects.js` и `landing-auth.js` (эффекты — раньше)

#### Scenario: Идемпотентность тегов
- **WHEN** сохранение выполнено дважды или в HTML уже есть теги скриптов
- **THEN** в `draft.html` остаётся ровно один тег каждого скрипта

#### Scenario: Круглый трип
- **WHEN** репетитор открыл редактор, ничего не менял и нажал «Сохранить»
- **THEN** страница остаётся валидной: `<title>`, `<meta>`, точки входа `data-auth`, секции, аккордеон FAQ (`<details>`), кнопка темы, оформление (цвет CTA, рамки), CSS-переменные, тёмная тема и брейкпоинты сохраняются

### Requirement: Набор блоков лендинга в редакторе

`GET /tutor/landing/editor` SHALL передавать в шаблон набор блоков
GrapesJS: готовые секции лендинга, базовые элементы и раскладку. Разметка
блоков SHALL храниться отдельными шаблонами в
`app/landing/templates/blocks/`, набор SHALL собираться сервисом
`app/landing/services/blocks.py` и вшиваться в страницу JSON-ом в
`<script type="application/json" id="landing-blocks">`. Редактор SHALL инициализировать GrapesJS с
`blockManager: { appendOnClick: true, blocks: <набор> }`, чтобы блок
добавлялся кликом, а не только перетаскиванием.

Набор SHALL содержать:

- категорию «Блоки лендинга» в порядке страницы: `header`, `hero`,
  `price`, `about`, `education`, `reviews`, `steps`, `faq`, `signup`,
  `contacts`, `footer` (id `price` сохранён за секцией «Услуги и цены»);
- категорию «Базовые»: `heading`, `text`, `image`, `button`, `divider`;
- категорию «Макет»: `column2`, `column3`.

Секции SHALL повторять разметку одноимённых секций шаблона по умолчанию
(с демо-текстами вместо данных профиля) и использовать классы и
CSS-переменные шаблона (`.header`, `.hero`, `.plan`, `.education`,
`.review`, `.step`, `.faq`, `.signup`, `.contact-link`, `.footer`), чтобы вставленный блок
выглядел как остальная страница без новых правил CSS. Ссылки CTA в
блоках `hero`, `price`, `signup` и `button` SHALL вести на публичную
страницу записи текущего репетитора (`/s/<tutor_id>`); адрес SHALL
подставлять сервер.

Подписи блоков и категорий SHALL задаваться в русской локали
(`app/static/dist/grapesjs/i18n-ru.js`) по id блока и категории; каждый
блок и каждая категория из набора MUST иметь подпись.

#### Scenario: Панель блоков
- **WHEN** репетитор открывает `/tutor/landing/editor`
- **THEN** страница содержит JSON набора блоков и инициализирует GrapesJS с `blockManager.appendOnClick: true`

#### Scenario: Вставка секции
- **WHEN** репетитор кликает блок «Обложка»
- **THEN** в канвас добавляется секция `.hero` с оффером, CTA, строкой доверия и плейсхолдером фото

#### Scenario: CTA ведёт на страницу записи
- **WHEN** вставлен блок «Обложка», «Услуги и цены», «Запись» или «Кнопка»
- **THEN** `href` ссылки равен `/s/<tutor_id>` этого репетитора

#### Scenario: Русские подписи
- **WHEN** открыта панель блоков
- **THEN** блоки и категории подписаны по-русски, английских подписей нет

### Requirement: Вставка изображения в редакторе

Блок «Изображение» SHALL добавлять компонент `<img>` без пустого
`src=""` и с маркером `data-landing-image`. После вставки редактор SHALL
снимать маркер и открывать Asset Manager с `types: ['image']`; выбранный
ассет SHALL записываться в `src` компонента, а загруженный через Asset
Manager файл — появляться в канвасе по абсолютной ссылке
`/landing-assets/<uuid>.<ext>`. Маркер `data-landing-image` MUST NOT
попадать в сохранённый HTML.

Двойной клик по любой картинке в канвасе SHALL открывать Asset Manager
штатным поведением GrapesJS.

Закрытие Asset Manager без выбора ассета SHALL убирать вставленный
компонент: `<img>` без `src` GrapesJS рисует служебной data-URI-заглушкой,
и без удаления она попала бы в сохранённый HTML.

#### Scenario: Вставка картинки
- **WHEN** репетитор кликает блок «Изображение»
- **THEN** открывается Asset Manager, после выбора ассета картинка появляется в канвасе

#### Scenario: Отмена выбора
- **WHEN** репетитор закрывает Asset Manager, не выбрав ассет
- **THEN** пустой `<img>` удаляется из канваса, а в сохранённый HTML не попадают ни заглушка, ни `data-landing-image`

#### Scenario: Загрузка новой картинки
- **WHEN** в открытом Asset Manager репетитор загружает файл
- **THEN** файл сохраняется через `POST /tutor/landing/assets` и становится доступен для выбора

#### Scenario: Сохранение страницы
- **WHEN** репетитор сохраняет черновик с вставленной картинкой
- **THEN** в `draft.html` попадает `<img>` с абсолютной ссылкой `/landing-assets/…` и без атрибута `data-landing-image`

#### Scenario: Замена картинки
- **WHEN** репетитор дважды кликает по картинке в канвасе
- **THEN** открывается Asset Manager и выбранный ассет заменяет `src`

### Requirement: Вендоринг GrapesJS и русская локаль

GrapesJS SHALL лежать локально в `app/static/dist/grapesjs/` вместе с CSS и
файлом лицензии; CDN MUST NOT использоваться. Версия SHALL быть
зафиксирована в README рядом с файлами. Русская локаль
`app/static/dist/grapesjs/i18n-ru.js` SHALL определять
`window.grapesjsI18nRu` со структурой ключей en-набора дистрибутива
(ассеты, блоки, устройства, панели, селекторы, стили, трейты, компоненты)
и подключаться с `locale: 'ru'`, `localeFallback: 'en'`; незаведённые
ключи MUST молча уходить в английский.

#### Scenario: Локальные файлы
- **WHEN** открыта страница редактора
- **THEN** GrapesJS CSS и JS загружаются с `/static/dist/grapesjs/`, запросов к CDN нет

#### Scenario: Русский интерфейс
- **WHEN** редактор инициализирован
- **THEN** панели, менеджеры стилей, трейтов, ассетов и устройств подписаны по-русски, а незаведённые ключи показываются по-английски

### Requirement: Кнопка «Редактировать»

На странице управления лендингом кнопка «Редактировать» SHALL быть видна
всегда и вести на `/tutor/landing/editor`; в пустом состоянии редактор сам
создаёт черновик.

#### Scenario: Переход в редактор
- **WHEN** открыта `/tutor/landing`
- **THEN** на странице есть ссылка `/tutor/landing/editor` с текстом «Редактировать»

### Requirement: Предпросмотр черновика

`GET /tutor/landing/preview` SHALL отдавать `draft.html` через `FileResponse`
как `text/html` с `Cache-Control: no-cache`; при отсутствии черновика MUST
отвечать 404, в мульти-режиме — 404.

#### Scenario: Черновик есть
- **WHEN** запрошен предпросмотр при существующем `draft.html`
- **THEN** ответ 200 с содержимым файла и `Cache-Control: no-cache`

#### Scenario: Черновика нет
- **WHEN** запрошен предпросмотр без `draft.html`
- **THEN** ответ 404

### Requirement: Действия со страницей лендинга

`POST /tutor/landing/publish` SHALL публиковать черновик; без черновика MUST
NOT создавать `index.html` и MUST перенаправлять на страницу управления с
подсказкой. `POST /tutor/landing/unpublish` SHALL удалять только
`index.html`, не трогая черновик и бэкап. `POST /tutor/landing/reset` SHALL
перезаписывать черновик шаблоном из профиля (в пустом состоянии — создавать
первый черновик). Все действия MUST отвечать 303 на `/tutor/landing` со
статусом в query-параметре и MUST отвечать 404 в мульти-режиме.

#### Scenario: Публикация
- **WHEN** есть черновик и вызвана публикация
- **THEN** 303 на `/tutor/landing?status=published`, а `GET /` отдаёт страницу

#### Scenario: Публикация без черновика
- **WHEN** черновика нет и вызвана публикация
- **THEN** 303 на `/tutor/landing?status=no-draft`, `index.html` не создан

#### Scenario: Снятие с публикации
- **WHEN** опубликованная страница снята с публикации
- **THEN** 303 на `/tutor/landing?status=unpublished`, `GET /` снова 303 на `/tutor/`

#### Scenario: Возврат шаблона
- **WHEN** вызван возврат шаблона
- **THEN** 303 на `/tutor/landing?status=reset`, а `draft.html` перезаписан данными профиля

#### Scenario: Мульти-режим
- **WHEN** `SINGLE_MODE` выключен и вызван любой из POST
- **THEN** ответ 404, файлы на диске не меняются

### Requirement: Пункт «Лендинг» в сайдбаре

В нижнем блоке сайдбара, перед пунктом «Настройки», SHALL выводиться пункт
«Лендинг» (`/tutor/landing`, иконка `globe`), если включён сингл-режим. В
мульти-режиме пункт MUST NOT рендериться вовсе. На странице управления пункт
SHALL быть подсвечен как активный.

#### Scenario: Сингл-режим
- **WHEN** включён `SINGLE_MODE`
- **THEN** в сайдбаре есть «Лендинг» выше «Настроек», а на `/tutor/landing` пункт активен

#### Scenario: Мульти-режим
- **WHEN** `SINGLE_MODE` выключен
- **THEN** пункта «Лендинг» в сайдбаре нет, а `/tutor/landing` отвечает 404

### Requirement: Статус входа и клиентская подмена кнопок

`GET /auth/status` SHALL быть публичным (без сессии и без редиректов) и
отвечать JSON `{"student": bool, "parent": bool, "tutor": bool}` по трём
независимым серверным сессиям (cookie `student_session`, `parent_session`,
`tutor_session`). Ответ MUST содержать `Cache-Control: no-store`. Отсутствующая,
поддельная или протухшая сессия SHALL давать `false` для своей роли, не
затрагивая остальные.

Скрипт `/static/landing-auth.js` SHALL на `DOMContentLoaded` запрашивать
`/auth/status` и для каждого элемента `[data-auth]` при `true` менять текст и
`href` по таблице: `student` → «В кабинет» → `/student`, `parent` → «В кабинет»
→ `/parent`, `tutor` → «кабинет» → `/tutor/`. Отсутствие элемента, неизвестная
роль, сбой запроса или `false` MUST оставлять исходную ссылку на страницу
входа; DOM вне `[data-auth]` MUST NOT изменяться.

#### Scenario: Аноним
- **WHEN** запрошен `/auth/status` без cookie сессий
- **THEN** ответ 200 с тремя `false` и `Cache-Control: no-store`, а кнопки лендинга остаются ссылками на вход

#### Scenario: Вошедший ученик
- **WHEN** у клиента живая сессия только ученика
- **THEN** статус даёт `student=true`, остальные `false`, а кнопка ученика становится «В кабинет» → `/student`

#### Scenario: Независимые сессии
- **WHEN** в браузере живут сессии ученика, родителя и репетитора одновременно
- **THEN** статус даёт три `true`, а каждая кнопка меняется по своей роли

#### Scenario: Протухшая сессия
- **WHEN** cookie содержит истёкший или поддельный токен
- **THEN** статус соответствующей роли `false`, а кнопка остаётся ссылкой на вход

#### Scenario: Сбой запроса
- **WHEN** `/auth/status` недоступен или ответ не JSON
- **THEN** скрипт молча ничего не меняет и страница остаётся со ссылками входа
