{# Контейнеры баннеров-напоминаний вверху страниц кабинета. Включается в шаблоны страниц кабинета сразу после открытия `main__container` (AGENTS.md: партиалы htmx начинаются с `_` — этот файл является включаемым, не роутом). Данные подгружают два независимых партиала: вьюхам страниц их контекст не нужен. 1. `/tutor/notices/balance` — «сегодня занятие, а на счёте не хватает денег» (красная плашка). Перезапрашивается по `payment-saved` (оплата меняет баланс) и `student-saved` (правка ученика), а также по `lesson-saved`: правка цены урока меняет сумму нехватки. 2. `/tutor/notices` — «N уроков не отмечены» (design D1 change'а unmarked-lessons). Перезагрузка по `lesson-saved` — урок отметили, плашка должна исчезнуть сразу. Пояснение про автозавершение — только у главной: перед включением поставьте `{% set notice_explain = true %}`. Плашка о деньгах идёт первой: неоплаченное занятие важнее отметки. Когда предупреждений два и больше, вместо них показывается одна сводная плашка «Требует внимания · N» с действием «Показать»/«Свернуть» (Alpine-фабрика `noticeGroup` из notices.js). Сервер о количестве плашек не знает: партиалы приходят htmx-свопами уже после отрисовки страницы, поэтому счётчик, скрытие и раскрытие — клиентские. Свёрнутая сводка прячет контейнер с плашками целиком (`.notice-stack__items`), а не сами плашки, — иначе собственное скрытие группы обнуляло бы счётчик. Состояние раскрытия лежит в localStorage, поэтому переживает перезагрузку и переходы между разделами кабинета. Показывать контейнер решает одно поле `expanded`: при одной видимой плашке оно истинно само собой, иначе сводка и плашки разъезжались бы после закрытия одной из двух плашек крестиком. Одиночная плашка и пустой случай обёртки не касаются: при одном предупреждении сводка скрыта и плашка видна как есть, при нуле — пустые контейнеры не занимают места. `x-cloak` есть только у сводки: контейнер с плашками им не помечен, чтобы при выключенном JS одиночная плашка не исчезла. #}
