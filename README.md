# Open Tutor CRM

**Открытая CRM для репетиторов: ученики, группы, уроки и расписание — на вашем собственном сервере.**

Проект для частных преподавателей, которым нужен порядок в записях, расписании и оплатах,
но не нужны подписки, чужие облака и десятки лишних полей в интерфейсе.
Один репетитор — один аккаунт — только его данные.

## Возможности

Open Tutor CRM — веб-приложение, которое закрывает ежедневную рутину репетитора:

- **Главная** — дашборд «сегодня»: запланированные уроки дня, активные ученики, доход и проведённые
  часы за месяц, расписание на сегодня с переходом через полночь и последние оплаченные платежи.
- **Настройки репетитора** (`/tutor/profile`, ссылка в строке пользователя в футере сайдбара) —
  четыре вкладки: профиль (имя, телефон, о себе, стоимость часа, опыт), безопасность (email и смена
  пароля), уведомления (переключатели с параметрами: напоминания за 15 минут/1 час/24 часа, дневная
  сводка, низкий баланс и другие) и календарь (часовой пояс, даты четвертей учебного года,
  рабочее время — границы сетки календаря целыми часами, длительность и стоимость урока
  по умолчанию). До первого сохранения действуют дефолты (рабочее время — 06:00–23:00),
  хранение — таблица `tutor_settings`.
- **Ученики** — карточки с контактами, классом, школой, уровнем и заметками; поиск, сортировка
  по фамилии/имени и фильтры по статусу, кнопка «Удалённые» показывает архив. Над списком —
  панель долга: общая задолженность, число должников и переключатель «Показать только их».
  Карточка показывает «Проведено», баланс (долг — красным), ближайший запланированный урок
  и остаток занятий; таблица добавляет колонки «Класс/Школа», «Уроки», «Баланс», «Появился»
  и «Первая оплата». Кнопки «Уроки» и «Отчёт» открывают модалки: список занятий ученика
  (клик открывает карточку урока) и итоги месяца (списано, оплачено, баланс, заработок).
  Кнопка «Доступ» заводит ученику логин и пароль: логин уникален и подсказывается
  транслитом имени («Иван Петров» → `ipetrov`), пароль хранится хешем и показывается
  один раз. Вкладка «Настройки» держит блок «Личный кабинет»: состояние входа
  и одноразовая ссылка-приглашение на регистрацию. Первый проведённый платный урок (списание
  за занятие — индивидуальное или групповое) автоматически переводит «нового» ученика
  в «активные»; архивный остаётся архивным.
- **Контакты** — родители, бабушки, водители: один взрослый переиспользуется в нескольких карточках,
  с ролью и отдельными настройками напоминаний; можно отметить, кто платит.
- **Группы** — до 10 участников, цена за урок с человека, постоянная ссылка на встречу и заметки;
  вкладка «Занятия» модалки группы показывает список занятий группы, вкладка «Оплаты» —
  списания за занятия группы, возвраты и долг участников.
- **Уроки** — индивидуальные, групповые, пробные и отработки; длительность, оплата ученика,
  оценка и комментарий для семьи; повторяющиеся серии с массовым изменением и удалением.
  Список листается по 50 строк, шапка остаётся на месте при прокрутке, а колонки
  «Ученик / Группа», «Дата и время» и «Статус» переключают сортировку кликом.
  Несколько уроков можно отметить проведёнными одним действием — чекбоксы в строках
  и кнопка «Отметить выбранные проведёнными»; списания пересчитываются в той же
  транзакции, уже проведённые уроки не трогаются.
  Прошедшие уроки, не отмеченные как проведённые, видны в списке через фильтр
  «Не отмеченные» и в баннере-напоминании вверху любой страницы кабинета; если урок
  не отмечен 24 часа после окончания, задание cron завершает его автоматически —
  с тем же списанием, что при ручной отметке.
- **Домашние задания** — отдельная вкладка урока: задание, срок сдачи, статус, ссылка на запись,
  заметка для себя и комментарий для семьи. Вкладки «Урок» и «ДЗ» полностью меняют окно,
  включая кнопки: кнопки сохранения и удаления живут в зафиксированном футере и не скроллятся.
  В панели расписания серии дата окончания подставляется чипами-пресетами из настроек
  календаря репетитора (окончания четвертей).
- **Статистика** (`/tutor/stats`) — обзорные показатели удержания и выручки: LTV, Retention Rate,
  активные и потерянные ученики, панель «Риск потери» с «тихо отвалившимися», прогноз выручки
  на месяц, таблица всех учеников с состояниями активности, фильтрами и выгрузкой CSV,
  конверсия из пробного занятия (подробнее — «Статистика» ниже).
- **Финансы** (`/tutor/finance`) — сводка по всем ученикам за период: доход, возвраты, чистый
  доход, расходы репетитора, заработанное уроками, долги и переплаты; кнопки «Доход» и «Расход»
  вносят платёж ученику и трату репетитора, ниже — список операций и балансы учеников
  (подробнее — «Финансы» ниже).
- **Задачи** (`/tutor/tasks`) — планирование дел двумя видами одной выборки:
  канбан по этапам «Новые», «В работе», «На проверке», «Готово» и список по срокам
  («Сегодня» вместе с просроченными, «Предстоящие», «Без срока», «Завершено»).
  У задачи есть приоритет, срок, описание и привязка к одному или нескольким ученикам;
  ответственного нет — задачи ставит себе сам педагог. Этап меняется из меню карточки
  или перетаскиванием карточки в другую колонку, фильтр по ученику действует в обоих видах.
- **Расписание** — недельный календарь с сеткой по четвертям часа, карточками занятий,
  окнами для записи и навигацией по неделям без перезагрузки страницы. Сетка ограничена
  рабочим временем из вкладки «Календарь» настроек: часы вне интервала не показываются,
  а занятия за его пределами прижимаются к границе и остаются кликабельными; перетаскивание
  зажимается рабочим временем.
- **Окна для записи и публичная страница** — репетитор открывает окна (одно или пачкой
  на месяц с перерывом), отправляет ученику ссылку `/s/<id>?start=<понедельник>`, ученик
  оставляет заявку без входа, репетитор подтверждает её в календаре — и в расписании
  появляется урок с созданным или найденным учеником. Количество необработанных заявок —
  красным счётчиком на пункте «Брони» в сайдбаре: обновляется само раз в 30 секунд
  и мгновенно после подтверждения, отклонения или отмены.
- **Отпуск и выходные** — отметки недоступности: отпуск, больничный, разовая недоступность
  и постоянный выходной. Отмеченные дни заштрихованы в календаре с причиной в шапке,
  срок можно продлить или сократить, а постановка урока в такой день спрашивает
  подтверждение (для серии — один раз с числом затронутых занятий).
- **Часовой пояс** — время уроков и сроков ДЗ хранится в UTC, а вводится и показывается
  в зоне репетитора из его карточки; при пустом поле действует зона сервера.
- **Счёт ученика** — баланс как сумма платежей, возвратов и списаний за проведённые уроки;
  история операций и отдельный список платежей с правкой. Проведённый урок списывает
  свою цену сам, а кнопка «Пересчитать баланс» догоняет историю по уже прошедшим занятиям.
- **Возвраты** — отдельной операцией по оплаченному платежу: полный или частичный,
  не больше остатка; статус платежа при этом не меняется.
- **Счёт за период** — список занятий периода (по умолчанию — следующего месяца) с ценами,
  стоимость занятий и сумма к оплате с учётом остатка на балансе; готовый текст
  для ученика копируется в буфер обмена.
- **Аккаунт** — регистрация, вход, серверные сессии, восстановление пароля по одноразовой ссылке.
- **Мессенджеры** — страница `/tutor/settings` (пункт меню «Настройки»): вкладка «Мессенджеры»
  с секциями Telegram и MAX — вставьте токен бота (от @BotFather или @masterbot), статус подключения
  и отправка сообщений через Bot API (Telegram — `sendMessage`, MAX — `platform-api2.max.ru`);
  отправка идёт через единый сервис с реестром мессенджеров и повтором при сбое, VK — на подходе.
  Токены и прочие параметры репетитора хранятся в таблице `tutor_params`.
- **Каналы уведомлений** — вкладка «Уведомления» на `/tutor/profile`: карточки Telegram и MAX с привязкой
  по диплинку бота. «Подключить» генерирует одноразовый код и ссылку (`t.me/<бот>?start=<код>` /
  `max.ru/<бот>?start=<код>`); после «Запустить» в чате бот сам сообщает chat_id через апдейты
  (`getUpdates` / `GET /updates`), и канал привязывается — вручную chat_id вводить не нужно.
  «Отвязать» удаляет привязку, токен остаётся на вкладке «Мессенджеры»;
  после привязки бот сам присылает в чат приветственное сообщение.
- **Приглашение ученика** — вкладка «Настройки» в карточке ученика: «Пригласить» генерирует
  диплинк на бота с одноразовым кодом, копирует его в буфер и показывает целиком — ссылку
  нужно отправить ученику. После «Запустить» в чате бот сам сообщает chat_id ученика
  (общая проверка апдейтов с привязкой канала), приглашение гасится, «Отвязать» удаляет
  подключение. Приглашения хранятся в таблице `student_messenger_invites`.
  Сертификат `platform-api2.max.ru` подписан корнем Минцифры, которого нет в системных хранилищах, —
  на таких машинах проверку сертификатов Bot API можно отключить переменной `MESSENGER_TLS_VERIFY=false`
  (шифрование сохраняется, не проверяется только подлинность сервера).
- **Рассылки** (`/tutor/mailings`, пункт меню «Рассылки») — страница «Коммуникации» с двумя вкладками.
  «Новое сообщение»: список учеников с поиском по имени/телефону и сегментами «Должники» (баланс < 0),
  «С уроками (будущие)», «Были недавно (7 дней)» и «Без уроков»; у каждого — баланс, следующий урок
  и метки подключённых каналов (Telegram/MAX), ученик без каналов не выбирается. Текст с подстановками
  `{имя}`, `{баланс}`, `{следующий_урок}` уходит во все подключённые каналы каждого выбранного ученика;
  шаблоны сообщений сохраняются («Сохранить» — текущий текст новым шаблоном, модалка «Шаблоны» —
  правка и удаление). «История» — журнал всех исходящих сообщений бота: рассылки, приветственные
  при привязке и уведомления, со статусом доставки и причиной ошибки.
- **Оформление** — переключатель светлой и тёмной темы в футере сайдбара; выбор запоминается в браузере
  и применяется до отрисовки страницы, поэтому тема не мигает при переходе между разделами.
- **Навигация** — в основном меню сайдбара десять ежедневных разделов (календарь, главная, брони,
  задачи, ученики, рассылки, группы, уроки, финансы, статистика); «Настройки» и «Обратная связь»
  стоят отдельным блоком ниже — за ними не заходят каждый день. Каждый пункт ведёт на работающую
  страницу (это проверяет тест), а на телефоне цель пункта — не меньше 44px, чтобы палец в
  выдвижном меню не открывал соседний раздел.

Данные каждого репетитора изолированы: запись другого аккаунта неотличима от несуществующей.

> **Статус проекта:** ранняя версия (`0.1.0`). Ученики, контакты, группы, уроки, ДЗ,
> недоступность репетитора, окна для записи, публичная страница записи и счёт ученика
> работают с базой данных; календарь наполняется реальными уроками и окнами недели.

## Почему стоит взять этот проект

- **Открытый код и MIT.** Никаких закрытых модулей и lock-in — код можно читать, менять и форкать.
- **Self-hosted.** База и данные лежат на вашем сервере. Ничего не уходит в чужое облако.
- **Развёртывание без DevOps.** Один процесс, один файл SQLite в качестве базы по умолчанию.
  Перенос на PostgreSQL — это смена `DATABASE_URL`.
- **Без сборки фронтенда.** Server-side rendering на Jinja2 + HTMX + Alpine.js: нет Node.js,
  npm-зависимостей и ночного CI, который перестаёт собираться.
- **Ассеты локально.** htmx, Alpine, иконки и стили отдаются из `app/static/` — без CDN
  и внешних запросов из браузера. Иконки — не полный Lucide (444 КБ), а набор
  используемых: `app/static/icons.js` собирается `scripts/build_icons.py` и весит ~23 КБ.
- **Понятная архитектура.** Доменные модули, один класс — один файл, строгие правила разработки
  в [AGENTS.md](AGENTS.md) и 600+ тестов.
- **Миграции и тесты из коробки.** Alembic для схемы, pytest для поведения.

## Технологии

Python 3.14 · FastAPI · Uvicorn · SQLAlchemy 2.0 · Alembic · SQLite · Jinja2 · HTMX · Alpine.js · pytest · [uv](https://docs.astral.sh/uv/)

## Быстрый старт

Нужен только [uv](https://docs.astral.sh/uv/) — Python 3.14 он подтянет сам.

```bash
git clone https://github.com/kuzmichus/open-tutor-crm.git
cd open-tutor-crm

uv sync                                  # окружение и зависимости
uv run alembic upgrade head              # схема БД (создаст tutor.db)
uv run uvicorn main:app --host 0.0.0.0 --port 8000
```

Откройте <http://localhost:8000> → регистрация → главная с дашбордом.
Проверка живости: `GET /health` → `{"status": "ok"}`.

## Запуск на своём сервере

### Вариант A. systemd + Uvicorn (рекомендуется)

```bash
sudo git clone https://github.com/kuzmichus/open-tutor-crm.git /opt/open-tutor-crm
cd /opt/open-tutor-crm
sudo uv sync --no-dev
sudo uv run alembic upgrade head
sudo chown -R www-data:www-data /opt/open-tutor-crm
```

Каталог должен быть доступен сервисному пользователю на запись: SQLite создаёт рядом
с базой журнальные файлы.

`/etc/systemd/system/open-tutor-crm.service`:

```ini
[Unit]
Description=Open Tutor CRM
After=network.target

[Service]
Type=exec
User=www-data
WorkingDirectory=/opt/open-tutor-crm
ExecStart=/opt/open-tutor-crm/.venv/bin/uvicorn main:app --host 127.0.0.1 --port 8000 --workers 4
Restart=on-failure
Environment=DATABASE_URL=sqlite:////opt/open-tutor-crm/tutor.db
Environment=APP_NAME=Open Tutor CRM

[Install]
WantedBy=multi-user.target
```

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now open-tutor-crm
sudo systemctl status open-tutor-crm
```

**Задания cron** — раз в минуту запускайте `cron.py`; сейчас он завершает уроки,
не отмеченные 24 часа после окончания (списание создаётся так же, как при ручной
отметке). Через crontab:

```bash
* * * * * cd /opt/open-tutor-crm && /opt/open-tutor-crm/.venv/bin/uv run python cron.py
```

или systemd-таймером (`open-tutor-crm-cron.timer` с `OnCalendar=*:*:00` и сервисом
с той же командой). Задания идемпотентны и живут в своей транзакции каждое: падение
одного не мешает остальным, код возврата 1 сигнализирует о падении.

Наружу отдавайте через nginx или Caddy: проксируйте на `127.0.0.1:8000`
и обязательно включите HTTPS — сессионная cookie ездит в браузере.

Для боевой установки используйте отдельный диск или том под `tutor.db`
(и его бэкапы) — файл базы переживёт перезапуски и обновления кода.

### Вариант B. Docker

В корне репозитория лежит `Dockerfile`: uv ставит зависимости из `uv.lock` на
этапе сборки, в рантайм-образ попадают только готовое виртуальное окружение,
исходники и миграции. Процесс работает не под root, живость проверяет
встроенный healthcheck (`GET /health`).

Сборка, миграции и запуск:

```bash
docker build -t open-tutor-crm .

docker run --rm -v open_tutor_data:/data open-tutor-crm alembic upgrade head

docker run -d --name open-tutor-crm \
  -p 8000:8000 \
  -v open_tutor_data:/data \
  open-tutor-crm
```

Том `/data` хранит базу между перезапусками и пересборками контейнера:
внутри образа `DATABASE_URL` по умолчанию указывает на `sqlite:////data/tutor.db`,
при необходимости переопределите через `-e` (переменные окружения — см.
раздел «Конфигурация», например `-e MESSENGER_TLS_VERIFY=false`).

Миграции запускаются отдельным одноразовым контейнером **до** первого старта
приложения: иначе таблицы создаст `init_db()` без записи в `alembic_version`,
и последующий `alembic upgrade head` упадёт на уже существующих таблицах.

**Задания cron** — вторым одноразовым контейнером из того же образа, раз
в минуту (планировщиком хоста):

```bash
* * * * * docker run --rm -v open_tutor_data:/data open-tutor-crm python cron.py
```

### Готовый образ и релизы

Собранный образ публикуется в Docker Hub как
[`kuzmichus/open-tutor-crm`](https://hub.docker.com/r/kuzmichus/open-tutor-crm)
(только `linux/amd64`). Если не хочется собирать локально — скачайте нужный тег:

```bash
docker pull kuzmichus/open-tutor-crm:0.1.0    # точная версия
docker pull kuzmichus/open-tutor-crm:0.1      # последняя в минорной ветке
docker pull kuzmichus/open-tutor-crm:latest   # последний выпуск
```

У каждого выпуска четыре тега: точная версия (`0.1.0`), минорная (`0.1`),
`latest` и `sha-<короткий SHA коммита>`. Дальше — те же шаги, что и при локальной
сборке: одноразовый контейнер с `alembic upgrade head`, затем запуск сервиса.

**Публикация только вручную.** Workflow `.github/workflows/release.yml` запускается
на странице Actions → **Release** → «Run workflow» и требует заполнить поле `version`.
(Кнопка появляется после того, как workflow попал в default-ветку `main`.) Версия
обязана совпадать с `version` в `pyproject.toml` — иначе публикация прерывается
до сборки, чтобы в реестре не появлялись мусорные теги. Порядок шагов: тот же
набор проверок, что и на push → сборка и push образа → релиз GitHub с
автоматически собранными release notes. Релиз создаётся последним и заодно
ставит тег `v<version>`: при ошибке реестра не появится ни релиза, ни тега.

Для публикации в настройках репозитория (Settings → Secrets and variables →
Actions) должны быть два секрета:

| Секрет | Значение |
|---|---|
| `DOCKERHUB_USERNAME` | логин Docker Hub |
| `DOCKERHUB_TOKEN` | access token с правами Read/Write на `kuzmichus/open-tutor-crm` |

Секреты доступны только workflow публикации: `ci.yml` запускается из форков
без них, а `pull_request_target` в проекте не используется.

Чтобы выпустить новую версию, поднимите `version` в `pyproject.toml`, закоммитьте,
дождитесь зелёных проверок на PR и запустите `release.yml` с той же версией.
Версия приложения (`app.version`, `info.version` в OpenAPI) читается из
`pyproject.toml`, поэтому больше нигде править её не нужно.

### Обновление

```bash
git pull
uv sync --no-dev
uv run alembic upgrade head
sudo systemctl restart open-tutor-crm
```

Перед обновлением сделайте резервную копию базы: `cp tutor.db tutor.db.bak`.

### Окна для записи и публичная ссылка

Ученик записывается сам — по ссылке, без входа в CRM. Сценарий целиком:

1. **Открыть окна.** В календаре меню «⋮» → «Добавить слот». Диалог умеет два режима:
   «Одно окно» (дата, начало, длительность, публичность) и «Несколько дней» — пачка
   на период: дни недели, рабочий интервал, длительность, перерыв. Предпросмотр
   считает сервер: «Будет создано окон: N», времена дня и список пропусков с причиной
   (занято уроком, занято окном, день недоступен, время прошло). Создание не атомарно —
   свободные окна создаются, конфликтные пропускаются, отчёт показывает и то, и другое.
   За одну пачку можно создать не больше 200 окон.
2. **Отправить ссылку.** Кнопка «Ссылка для записи» копирует публичный адрес недели
   (`/s/<id>?start=<понедельник>`) — она открывается без сессии и показывает неделю
   сеткой из семи дней: свободные окна зелёные («Свободно»), занятые уроком или
   заявкой — красные («Занято») без имён и контактов учеников. Если буфер обмена
   недоступен (http, запрет браузера), ссылка показывается в поле рядом — её можно
   скопировать вручную.
3. **Получить заявку.** Ученик кликает свободное окно, заполняет имя, телефон или
   мессенджер и необязательный комментарий, нажимает «Записаться». Заявка попадает
   в статус «Ожидает подтверждения», окно в календаре подсвечивается как занятое
   заявкой, а страница показывает экран «Заявка отправлена!» с выбранным временем.
   Комментарий виден педагогу в диалоге окна. Защита от спама: не больше 5 заявок
   на одно окно за 10 минут.
4. **Подтвердить.** Клик по окну в календаре открывает диалог с заявкой. Подтверждение
   ищет ученика по имени и телефону среди неархивных: одно совпадение — используется
   он, ни одного — создаётся новый (нужен подтип: ребёнок или взрослый), несколько —
   CRM попросит выбрать. Дальше проверяется, что время всё ещё свободно, и создаётся
   урок. Окно становится «Занято записью».
5. **Отменить или отклонить.** «Отклонить» освобождает окно и ничего не создаёт.
   «Отменить» оставляет урок и ученика: окно показывает «Занято уроком», пока урок
   не удалён, — после удаления урока окно снова «Свободно».

Состояние окна в календаре всегда вычисляется по данным: `booking > lesson > past > free`.
Занятые и прошедшие окна приглушены, свободные — с пунктирной рамкой в собственном
акценте. Время окон указано в зоне репетитора; на публичной странице об этом
предупреждает баннер «Внимание: время указано по <зона> (UTC+N)».

### Личный кабинет ученика

Ученик видит свои занятия сам — без входа в CRM и без ручной выдачи пароля:

1. **Пригласить.** В карточке ученика, вкладка «Настройки», блок «Личный кабинет» →
   «Создать приглашение». Блок показывает одноразовую ссылку `/invite/<токен>` —
   она действует 7 дней, и её можно скопировать одной кнопкой. Повторное
   создание гасит прежнюю ссылку, так работает и «сброс доступа»: ученик
   по новой ссылке задаёт пароль заново. Если вход уже привязан, блок показывает
   его идентификаторы (email и/или логин).
2. **Зарегистрироваться.** Страница по ссылке открыта без входа и спрашивает
   только Email и Пароль — имя ученика она не показывает. Регистрация привязывает
   вход к карточке; если вход уже был (заведён вручную), обновляются email
   и пароль, карточка остаётся той же. Недействительная ссылка — неизвестная,
   погашенная или просроченная — даёт одно и то же сообщение.
3. **Войти.** `/student/login` принимает логин или email с паролем. Сессия
   ученика — отдельная: вход и выход в кабинете не затрагивают сессию
   репетитора в том же браузере, обе работают одновременно.
4. **«Мои уроки».** Кабинет по адресу `/student` устроен как кабинет
   репетитора: слева сайдбар с меню и переключателем светлой/тёмной темы,
   справа — вкладка «Мои уроки»: ближайшее занятие и список ближайших
   запланированных уроков — индивидуальных и групповых. Прошедшие уроки
   не показываются; время — в зоне репетитора. Пункт «Профиль» пока
   показан неактивным — раздел появится следующим обновлением. Кнопка
   «Выход» в сайдбаре отзывает сессию.
5. **«Домашние задания».** Раздел `/student/homework`: карточки ДЗ уроков
   ученика (индивидуальных и групповых) со статусом не «Не задано»,
   свежее задание сверху. Карточка раскрывается по клику: задание, срок
   сдачи, ссылка на запись урока и комментарий репетитора. Ученик
   отправляет ответ — текст и ссылки на облачные хранилища (Яндекс Диск,
   Облако Mail): файлы не прикрепляются, только ссылки с открытым
   доступом. После отправки ДЗ помечается «Сдано»; ответ можно
   исправить и отправить снова, пока репетитор не отметил «Проверено» —
   после этого ответ виден только для чтения.

Наполнение кабинета (финансы, профиль) добавляется последующими
изменениями.

### Личный кабинет родителя

Родитель видит всех своих детей сразу — занятия, домашние задания и деньги —
по одному входу, без ручной выдачи логина и пароля:

1. **Пригласить.** В карточке ученика, блок «Контакты», на миникарточке
   сохранённого контакта — бейдж «Личный кабинет»: он показывает, привязан
   ли вход, и кнопку «Создать приглашение». Ответом выдаётся одноразовая
   ссылка `/parent/invite/<токен>` на 7 дней; повторное создание гасит
   прежнюю ссылку — это и есть штатный «сброс доступа». Действие обновляет
   только бейдж, не строку контакта: несохранённые правки раскрытой формы
   не теряются. У контакта, ещё не сохранённого в базе, бейджа нет.
2. **Зарегистрироваться.** Страница по ссылке открыта без входа и спрашивает
   только Email и Пароль — имя контакта и детей она не раскрывает. Если
   вход уже был, обновляются email и пароль, привязки к детям остаются.
   Недействительная ссылка — неизвестная, погашенная или просроченная —
   даёт одно и то же сообщение.
3. **Войти.** `/parent/login` принимает email и пароль. Сессия родителя —
   третья независимая: в одном браузере одновременно работают сессии
   репетитора, ученика и родителя, выход из одной не затрагивает другие.
4. **Кабинет `/parent`.** Устроен как кабинет репетитора: слева сайдбар
   с меню и переключателем темы, справа — страницы. В меню — секция на
   каждого привязанного ребёнка (имя, ссылки «Мои уроки» и «Домашние
   задания») и общие «Финансы» и «Профиль»; дети в архиве показываются
   наравне с активными. У контакта без детей общие разделы остаются
   доступны.
5. **Вкладки ребёнка.** «Мои уроки» — ближайшие запланированные занятия,
   индивидуальные и групповые; прошедшие не показываются, время — в зоне
   репетитора. «Домашние задания» — только просмотр: задание, срок,
   статус, комментарий педагога и запись урока; заметка педагога, скрытая
   от ученика, родителю не показывается, отправлять ответы нельзя.
6. **«Финансы».** По каждому ребёнку — баланс, сумма пополнений и история
   операций, плюс общий итог по всем детям. Видны все привязанные дети
   независимо от того, назначен ли контакт плательщиком.
7. **«Профиль» и «Выход».** Профиль показывает ФИО, телефон и email
   контакта и адрес входа — в режиме просмотра; изменение данных и смена
   пароля — через репетитора. «Выход» в сайдбаре отзывает сессию.

### Счёт ученика

Деньги репетитора и ученика сходятся в одном месте — вкладке «Платежи» карточки ученика.
Баланс не хранится отдельной колонкой: это сумма операций, и другого источника истины нет.

| Операция | Что делает с балансом |
|---|---|
| Платёж в статусе «Оплачено» | увеличивает |
| Платёж «Ожидает» и «Отменено» | не влияет (виден в списке платежей) |
| Возврат | уменьшает |
| Списание за проведённый урок | уменьшает |

Баланс может уйти в минус: если вернуть 2 400 при остатке 300, ученик окажется должен
2 100 — это не ошибка, а честный результат (деньги уже ушли на уроки).

Как это работает в интерфейсе:

1. **Внести оплату.** Вкладка «Платежи» → «Внести оплату»: сумма, способ (перевод,
   карта, онлайн), статус, дата и комментарий. Диалог открывается поверх карточки
   ученика, поэтому несохранённые правки в «Общем» не теряются.
2. **Списание появляется само.** Проведённый урок (статус «Проведён») списывает свою
   цену — за ученика индивидуального урока или за каждого участника группового
   (цена участника важнее общей цены группы). Возврат урока в «Запланирован» снимает
   списание; цена проведённого урока дальше не меняется — в форме она только для
   чтения; удаление урока убирает строку.
3. **Возврат.** По оплаченному платежу: полный или частичный, с причиной. Сумма
   не может превысить остаток по платежу, а статус платежа возврат не меняет.
4. **Пересчитать баланс.** Уроки, проведённые до появления счетов, списаний не имеют.
   Кнопка «Пересчитать баланс» (и баннер о том, что баланс не пересчитан) добавляет
   недостающие строки. Пересчёт идемпотентен: он не переписывает существующие суммы
   и не трогает платежи с возвратами, поэтому смена цены группы не переписывает прошлое.
5. **Счёт за период.** Показывает занятия периода (по умолчанию — следующий месяц)
   с ценами, стоимость занятий и сумму к оплате; тумблер «Учесть остатки на балансе»
   вычитает баланс. Готовый текст сообщения копируется в буфер обмена — отправка
   в мессенджеры пока не подключена, кнопка «Отправить ученику» неактивна.

> **Известное ограничение.** В списке уроков у проведённого занятия остаётся пометка
> «(Оплачено)»: она по-прежнему выводится из статуса урока, а не из счёта ученика.
> Источник истины по деньгам — вкладка «Платежи»: там видно, был ли платёж и что
> с ним стало. Пересмотр пометки — отдельная задача, в этот релиз не вошёл.

### Счёт группы

Вкладка «Оплаты» модалки управления группой отвечает на три вопроса по текущим
участникам: сколько списано за занятия группы, сколько возвращено и сколько они
должны сейчас. Чипы «За всё время» / «Этот месяц» / «Прошлый месяц» пересчитывают
списания и возвраты в зоне репетитора; «Долг участников сейчас» от периода не зависит.

Объёмы у сводки и у строк участников разные, и это подписано прямо на вкладке:

- «Баланс» и «Долг» участника — по всему счёту ученика, включая индивидуальные уроки;
- «Списано» — только за уроки этой группы в выбранном периоде, с числом занятий;
- выбывший участник исчезает из строк и итогов, но его прошлые списания остаются
  в его карточке.

Оплату и возвраты вносят в карточке ученика: имя в строке ведёт туда, сразу
на вкладку «Платежи».

### Занятия группы

Вкладка «Занятия» модалки управления группой показывает уроки группы — свежие
сверху, каждая строка: дата и интервал в зоне репетитора, статус, описание
группы и индикатор домашнего задания («ДЗ: есть/нет»). Чипы «Все» /
«Проведённые» / «Запланированные» фильтруют список по статусу урока.

Клик по занятию открывает стандартное окно урока **поверх** модалки группы
(второй слой): несохранённые поля вкладок группы не теряются. Сохранение,
удаление урока и правка ДЗ в этом окне закрывают его и обновляют список;
окно группы остаётся открытым на той же вкладке.

### Статистика

Страница `/tutor/stats` (пункт «Статистика» в меню) — три вкладки, всё только на чтение:
без htmx и JavaScript, фильтры и периоды работают обычными ссылками и GET-формами.

- **Обзор** — карточки «LTV (Сред. чек)» (оплаченные платежи минус возвраты на одного
  занимавшегося ученика), «Retention Rate» (статусно-активные из тех, кто хоть раз занимался),
  «Активных» (обычное занятие за 14 дней) и «Потерянных» (уход отмечен статусом «В архиве»),
  панель «Риск потери» — занимались, но больше 14 дней нет занятий, впереди ничего не
  запланировано, а статус не менялся. Кнопка «Прогноз на месяц» показывает ожидаемую выручку
  запланированных уроков на 30 дней: цена индивидуального урока плюс цена каждого участника
  группового.
- **Ученики** — таблица всех учеников с двумя метками статуса: статус карточки и состояние
  активности («Активен» / «Отвалился» / «Ушёл»). Пробные занятия активностью не считаются.
  Фильтры: поиск по ФИО, статус, состояние активности, «Без будущих занятий»; список
  отсортирован по дате последнего занятия; пагинация по 25 строк; кнопка «Скачать CSV»
  выгружает те же строки с теми же фильтрами (UTF-8 с BOM, разделитель «;» — открывается
  в Excel двойным кликом).
- **Новые и пробные** — фильтр периода (всё время / сегодня / 7 дней / 30 дней / произвольный
  в зоне репетитора). «Заведено» — карточки, созданные за период; «Стали активными» —
  ученики, у которых за период прошёл первый оплаченный платёж. Ниже — конверсия из
  проведённого пробного: «остался» — у ученика есть обычное занятие после пробного
  (проведённое или запланированное), а если занятий нет — оплата после пробного. Число
  в «Остались» раскрывается в список учеников с причиной по каждому; до пяти пробных
  вместо процента показывается «мало данных».

Вкладка «Преподаватели» из референса не переносится: в модели данных один педагог —
владелец аккаунта, поэтому разбивки по педагогам дают одну строку с его именем.

### Финансы

Страница `/tutor/finance` (пункт «Финансы» в меню) — сводка движения денег по всем ученикам:

- **Период** — «Этот месяц» (по умолчанию), «Прошлый месяц», «Последние 3 месяца», «Всё время»;
  границы считаются настенным временем репетитора, смена периода — обычная GET-форма.
- **Карточки за период** — «Доход» (оплаченные платежи; ожидающие и отменённые не считаются),
  «Возвраты», «Чистый доход», «Расходы» (траты репетитора), «Чистая прибыль» (чистый доход
  минус расходы), «Заработано (уроки)» (списания за проведённые занятия). Сводка разделена
  на два яруса: «Доход», «Чистая прибыль» и «Долги учеников» идут первыми крупным числом,
  остальные — компактной расшифровкой ниже. Показываются все восемь: ярус — это вес,
  а не фильтр, поэтому обновление сводки после сохранения платежа ничего не сворачивает.
- **Состояние на сейчас** — «Долги учеников» (сумма отрицательных балансов) и «Переплата»
  (сумма положительных): сколько должны репетитору и сколько он должен ученикам.
- **«Заработано и получено»** — арифметика по референсу: заработано уроками, получено от
  учеников, минус расходы и итог «Осталось репетитору», с подсказкой о разнице заработанного
  и полученного (платят вперёд или должны за прошедшие занятия).
- **Кнопка «Доход»** открывает привычный диалог платежа, где ученик выбирается из списка
  активных и новых (архивные — из их карточки). После сохранения диалог закрывается,
  а сводка обновляется с сервера.
- **Кнопка «Расход»** открывает диалог траты репетитора: сумма, дата, категория из списка
  (аренда, налоги, реклама, подписки и другие) и комментарий. Расход не трогает балансы
  учеников — он вычитается из «Чистой прибыли» и «Осталось репетитору».
- **Операции** — вкладки под сводкой: «Все операции» (платежи, возвраты, расходы
  и списания за проведённые уроки), «Расходы», «Доходы», «Аналитика» (графики) и
  «Прогноз на месяц». Таблица показывает операции выбранного периода колонками
  Дата, Тип, Описание и Сумма (статус платежа — бейдж рядом с типом). На «Все
  операциях» над таблицей — фильтр по виду операции (чипсы «Все», «Приходы»,
  «Возвраты», «Расходы», «Списания за уроки»; состояние в адресе `?kind=…`)
  и карточки итогов отфильтрованного набора: «Приходы», «Возвраты», «Расходы»,
  «Чистый» (списания за уроки в итогах не участвуют — это движение баланса
  ученика, а не деньги репетитора). Рядом с вкладками — кнопка «Добавить»
  (диалог расхода). Вкладки переключаются без перезагрузки страницы:
  подменяется только секция операций, а адрес в браузере соответствует
  открытому состоянию (перезагрузка и «назад» возвращают то же состояние).
  Без JavaScript вкладки и фильтр работают как обычные ссылки.
- **Аналитика** — два графика с переключателем горизонта «6 мес» / «12 мес»:
  столбчатая диаграмма «Доходы и расходы по месяцам» (доход, заработано уроками,
  расходы) и круговая «Расходы по категориям» с долями и суммами в легенде.
- **Прогноз на месяц** — ожидаемая выручка текущего или следующего месяца (селектор
  месяца): «Факт» (списания за проведённые уроки), «По календарю» (запланированные
  уроки и их цены; цена группового — сумма цен участников), «Не в расписании»
  (ученики, которые занимались последние четыре недели, но в календаре на остаток
  месяца их нет), «Итого за месяц» (диапазон: факт + календарь … плюс ожидание) и
  «Деньги к поступлению» (будущие списания минус предоплата на балансах).
  Кнопка «Зафиксировать прогноз» сохраняет снимок диапазона, после чего карточка
  «Прогноз vs факт» показывает отклонение факта от середины прогноза; ссылка
  «Скачать CSV» выгружает сводку и расшифровки. Прогноза по педагогам, ЗП и маржи
  нет: у репетитора один аккаунт, ставок педагогов в модели не бывает.
- **Балансы учеников** — карточка справа от вкладок: должники с суммой долга и переплаты
  с суммой переплаты, состояние на сейчас.

### Время и часовой пояс

Время уроков и сроков сдачи ДЗ хранится в базе в **UTC** — единая система координат
для всех записей. Вводится и показывается оно в **зоне репетитора**: она берётся
из его карточки (`tutors.timezone`, IANA-имя вроде `Europe/Berlin`), а пока поле
пустое — действует системная зона сервера. Поэтому расписание выглядит одинаково
и после переезда на другой сервер, и при смене сезонного времени.

Поле `timezone` заполняется системной зоной сервера при регистрации. Если сервер
переехал в другой пояс, зону в карточке репетитора стоит поправить — иначе
настенное время уроков продолжит считаться по прежней зоне.

Миграция, переводящая уже накопленные записи в UTC, берёт зону-источник из
`MIGRATION_SOURCE_TZ` (иначе — системная зона сервера) и печатает её в лог:
именно эта зона трактуется как «настенное время» старых значений.

```bash
MIGRATION_SOURCE_TZ=Europe/Berlin uv run alembic upgrade head
```

### Когда пора на PostgreSQL

SQLite спокойно держит личный кабинет одного-двух репетиторов. Если пользователей
больше или нужен внешний бэкап-кластер — смените `DATABASE_URL` на строку подключения
PostgreSQL, добавьте драйвер (`uv add "psycopg[binary]"`) и прогоните миграции.
Код моделей при этом не меняется.

## Разработка

```bash
uv sync                                                # dev-группа зависимостей
uv run uvicorn main:app --host 0.0.0.0 --port 8000 --reload
```

При старте в режиме разработки таблицы создаются автоматически (`init_db` в lifespan).
Для воспроизводимой схемы всё равно используйте Alembic.

| Команда | Назначение |
|---|---|
| `uv run pytest -n auto` | все тесты |
| `uv run pytest -q tests/test_lesson_create.py` | конкретный файл |
| `uv run alembic upgrade head` | применить миграции |
| `uv run alembic revision --autogenerate -m "..."` | новая миграция |
| `uv run alembic current` / `downgrade -1` | текущая ревизия / откат одной |
| `uv run uvicorn main:app --reload` | dev-сервер |

### Конфигурация

Параметры читаются из переменных окружения или файла `.env` в корне проекта:

```env
DATABASE_URL=sqlite:///./tutor.db
APP_NAME=Open Tutor CRM
```

| Переменная | По умолчанию | Описание |
|---|---|---|
| `DATABASE_URL` | `sqlite:///./tutor.db` | строка подключения SQLAlchemy |
| `APP_NAME` | `Open Tutor CRM` | название приложения |
| `MIGRATION_SOURCE_TZ` | системная зона сервера | зона-источник для миграции перевода времени в UTC; читается только `alembic upgrade` |

## Участие в проекте

Issues и pull request'ы приветствуются. Перед PR:

1. Прочитайте [AGENTS.md](AGENTS.md) — там архитектурные правила проекта.
2. Добавьте тесты на новое поведение.
3. Убедитесь, что `uv run pytest -n auto` зелёный, а миграции созданы через autogenerate.

**Автоматические проверки** запускаются на каждый push и pull request
(`.github/workflows/ci.yml`) и идут параллельно:

| Проверка | Что делает |
|---|---|
| Тесты | `uv sync --frozen` и `uv run pytest -n auto` |
| Lock-файл | `uv lock --check` — `pyproject.toml` и `uv.lock` не разъехались |
| Схема миграций | `alembic upgrade head` на пустой базе и `alembic check` — модель без миграции даёт красный PR |
| Линт | `ruff check --select E9,F63,F7,F82` — синтаксис и неопределённые имена |
| Сборка образа | `docker build` и запуск контейнера со смоук-проверкой `GET /health` |

Тот же набор вызывается перед публикацией образа, поэтому красные тесты не
могут уехать в релиз. Повторный push в ту же ветку отменяет предыдущий прогон.
